## 🎯 前置知识：什么是 FastAPI？

### 为什么选择 FastAPI？

FastAPI 是一个现代、高性能的 Python Web 框架，用于构建 API。

```
传统方式（Flask）：
手动写参数校验 → 手动生成文档 → 手动序列化数据 → 性能一般

FastAPI 方式：
自动参数校验 → 自动生成文档 → 自动序列化 → 性能极高（媲美 Node.js/Go）
```

### FastAPI 的核心优势

| 特性 | 说明 |
|------|------|
| **快** | 性能媲美 Node.js 和 Go，基于 Starlette 和 Pydantic |
| **自动文档** | 自动生成 Swagger UI 和 ReDoc 交互式文档 |
| **类型安全** | 基于 Python 类型提示，编辑器自动补全和错误提示 |
| **数据校验** | Pydantic 自动校验请求/响应数据 |
| **标准兼容** | 完全兼容 OpenAPI 和 JSON Schema |
| **现代 Python** | async/await 异步支持 |

### 什么是 API？什么是 RESTful？

**API（应用程序接口）**：
```
┌──────────┐    HTTP 请求     ┌──────────┐
│  浏览器   │ ──────────────→ │  服务器   │
│  (前端)   │ ←────────────── │  (后端)   │
└──────────┘    HTTP 响应     └──────────┘
```

**RESTful API** 是一种设计风格（一套写 API 的行业设计规范，约定「URL 写资源名（/books代表图书资源） + HTTP 方法（GET:查，POST：增，PUT：改，DELETE：删）做增删改查 + 标准状态码返回结果」，让接口简洁、规范、易懂。），将一切视为"资源"：
- GET `/books` → 获取图书列表（查）
- GET `/books/1` → 获取 ID=1 的图书（查）
- POST `/books` → 新增图书（增）
- PUT `/books/1` → 完整更新 ID=1 的图书（改）
- DELETE `/books/1` → 删除 ID=1 的图书（删）



### 什么是类型提示 Type Hints？

FastAPI 大量依赖 Python 的类型提示，理解它是学好 FastAPI 的前提：

```python
# Python 3.6+ 的类型提示语法
name: str = "张三"           # name 是字符串类型
age: int = 25                # age 是整数类型
price: float = 99.9          # price 是浮点数类型
is_active: bool = True       # is_active 是布尔类型

# 函数参数和返回值类型
def greet(name: str) -> str:  # 参数是 str，返回值是 str
    return f"你好, {name}"

def get_user(user_id: int) -> dict:
    return {"id": user_id, "name": "张三"}

# 可选类型（Optional）
from typing import Optional
def search(name: Optional[str] = None) -> list:
    # name 可以是 str 或 None，默认值是 None
    pass
```

**FastAPI 用类型提示做什么？**
1. 定义参数类型 → 自动校验数据
2. 解析请求参数 → 自动类型转换
3. 生成 API 文档 → 自动记录参数格式
4. 编辑器支持 → 代码补全和错误检查

### 1.4 uvicorn 是什么？

`uvicorn` 是一个 ASGI 服务器，负责运行你的 FastAPI 应用：

```
浏览器请求 → uvicorn（接收 HTTP 请求）→ FastAPI 应用（处理请求）→ uvicorn（返回响应）→ 浏览器
```

**ASGI vs WSGI**：
- WSGI（旧标准）：同步，一次只能处理一个请求
- ASGI（新标准）：支持异步，可以同时处理多个请求
ASGI = Asynchronous Server Gateway Interface（异步服务器网关接口）
是 Python 用来替代老旧 WSGI 的新一代 Web 服务标准协议，核心目的：支持异步 async/await，既能跑同步 Web 应用，也能跑异步、WebSocket、长连接、服务端推送。
WSGI 只支持同步；ASGI 向下兼容 WSGI，同步、异步代码都能跑。

## 2. 第一个 FastAPI 应用

### 2.1 最小应用

创建一个 `main.py` 文件：

```python
# main.py - 第一个 FastAPI 应用

from fastapi import FastAPI

# 创建 FastAPI 应用实例
# 这个 app 对象是整个应用的核心
app = FastAPI(
    title="我的第一个 API",
    description="这是一个学习 FastAPI 的示例应用",
    version="1.0.0"
)


# 路径操作装饰器：定义 HTTP 方法和路径
@app.get("/")                    # GET 请求，根路径
def read_root():
    """根路径，返回欢迎信息"""
    return {"message": "Hello, FastAPI!"}


@app.get("/hello/{name}")        # GET 请求，带路径参数
def say_hello(name: str):        # name: str 类型提示会自动校验
    """向指定用户打招呼"""
    return {"greeting": f"你好, {name}!"}


# ☝ 以上就是全部代码，只有 10 行！
```

> #### 📐 从"一个 app"到"一个工厂"——应用工厂模式
>
> 上面的例子中 `app = FastAPI()` 直接写在模块顶层，属于 **"全局 app"模式**。这在只有一个配置文件、不需要测试的小项目中完全够用。但当项目变大时会出现问题：
>
> ```python
> # ❌ 全局 app 模式的问题
> app = FastAPI(title="SyncHealth")
> app.add_middleware(CORSMiddleware, ...)    # 配置写死在全局
> app.include_router(api_router, prefix="/api/v1")
> # 问题1：测试时想用不同的配置（如测试数据库）→ 改不了，app 已经定型了
> # 问题2：多套环境（开发/测试/生产）→ 需要写三份 main.py 或者一堆 if/else
> ```
>
> **工厂模式**就是把创建 `app` 的过程封装到一个函数里，按需调用：
>
> ```python
> # ✅ 工厂模式：把 app 创建逻辑封装成函数
> def create_app() -> FastAPI:
>     app = FastAPI(title="SyncHealth", version="0.1.0")
>     app.add_middleware(...)
>     app.include_router(api_router, prefix="/api/v1")
>     return app
>
> app = create_app()  # 生产环境调用
> # 测试时可以：test_app = create_app(override_settings=...) 不同配置！
> ```
>
> 这和文档中 2.1 学的 `app = FastAPI()` 本质完全一样——`create_app()` 内部还是调用了 `FastAPI(...)`，只是多了一层函数包装，让"创建 app"这件事变成了一个**可重复、可定制的动作**。
>
> ---
>
> > ### 🏗️ 项目实例：SyncHealth 实际使用的工厂模式
> >
> > SyncHealth 的真实 `main.py` 完整展示了工厂模式 + `lifespan` 的组合：
> >
> > ```python
> > # backend/app/main.py - 工厂模式 + lifespan 启动钩子
> > from contextlib import asynccontextmanager
> > from fastapi import FastAPI
> > from fastapi.middleware.cors import CORSMiddleware
> > from starlette.responses import RedirectResponse
> >
> > @asynccontextmanager
> > async def lifespan(app: FastAPI):
> >     """应用启动时自动执行：初始化数据库"""
> >     await init_db()   # 建表 + 迁移
> >     yield             # 应用运行中...
> >     # yield 之后是关闭逻辑（此处不需要）
> >
> > def create_app() -> FastAPI:
> >     app = FastAPI(
> >         title="SyncHealth",
> >         version="0.1.0",
> >         lifespan=lifespan,    # 启动时自动调用 init_db()
> >     )
> >     app.add_middleware(
> >         CORSMiddleware,
> >         allow_origins=["http://localhost:5173", "http://localhost:3000"],
> >         allow_credentials=True,
> >         allow_methods=["*"],
> >         allow_headers=["*"],
> >     )
> >     from app.api.router import api_router
> >     app.include_router(api_router, prefix="/api/v1")
> >
> >     @app.get("/")
> >     async def root():
> >         return RedirectResponse(url="/docs")
> >
> >     return app
> >
> > app = create_app()  # 生产入口：uvicorn 加载的就是这个 app
> > ```
> >
> > **两个你暂时不需要深究、但知道它存在就行的概念**：
> > - `lifespan`：应用启动/关闭时自动执行的钩子，类似"开机自启动脚本"。这里用它来自动建表。
> > - `include_router`：把拆分的路由模块挂载到主应用上，在第3阶段的"大型项目结构"中会详解。
> >
> > 你现阶段只需要理解：`create_app()` 的内部就是 `app = FastAPI(...)` + 各种配置，最终 `return app`。和 2.1 学的一模一样。

#### 2.4.1 `@app.get("/")` — 装饰器详解

```python
@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}
```

**① `@` 装饰器的作用**

`@` 是 Python 的**装饰器语法**，它会把下面的函数"注册"成一个可被网络调用的 Web 接口：

```
没有 @app.get("/")：
  read_root() 只是一个普通 Python 函数，只能在本机代码中调用
  read_root()  →  返回 {"message": "Hello"}  →  仅此而已

有了 @app.get("/")：
  read_root() 变成了一个 Web 接口！
  浏览器访问 http://127.0.0.1:8000/  →  FastAPI 自动调用 read_root()
  →  返回 {"message": "Hello"}  →  自动转成 JSON  →  返回给浏览器
```

**通俗理解**：`@app.get("/")` 就像一个"挂牌"，把函数 `read_root` 挂到了 URL 路径 `/` 上。挂牌之后，任何通过 HTTP 访问这个路径的请求，都会由这个函数来处理。

---

**② `.get()` 的含义 — 限定 HTTP 方法**

`.get()` 表示这个接口**只接受 GET 请求**：

| 装饰器 | 对应 HTTP 方法 | 用途 | 举例 |
|--------|---------------|------|------|
| `@app.get()` | GET | 获取/查询数据 | 获取用户列表、查询商品详情 |
| `@app.post()` | POST | 新增/创建数据 | 注册用户、发布文章 |
| `@app.put()` | PUT | 全量更新数据 | 完整替换一条记录 |
| `@app.patch()` | PATCH | 局部更新数据 | 只修改用户名 |
| `@app.delete()` | DELETE | 删除数据 | 删除一条评论 |

**如果方法不对会怎样？**

```
# 用 POST 请求访问 GET 接口
curl -X POST http://127.0.0.1:8000/

# 返回 405 Method Not Allowed
# {"detail": "Method Not Allowed"}
```

> 每个接口只能响应它声明的 HTTP 方法，用错了方法会直接收到 `405` 错误。

#### 2.4.2 `@app.get("/hello/{name}")` — 路径参数详解

```python
@app.get("/hello/{name}")
def say_hello(name: str):
    return {"greeting": f"你好, {name}!"}
```

**① `"/hello/{name}"` 中的 `{name}` 是路径参数**

花括号 `{}` 表示"这是一个变量"，URL 中这个位置的内容会自动传给函数：

```
URL 路径                    提取的值
─────────────────────────────────────────
/hello/张三         →     name = "张三"
/hello/Lisa         →     name = "Lisa"
/hello/2024         →     name = "2024"  （也是字符串）
```

**② `name: str` 类型标注的作用**

你标注了 `name: str`，FastAPI 会做两件事：
- **自动类型转换**：路径中的值始终是字符串，但如果你标注 `name: int`，FastAPI 会尝试自动转成整数
- **Swagger 文档**：自动在交互式文档中标注参数类型为 `string`

> #### 🔍 深入原理：`name: str` 为什么能自动校验？
>
> 你没有写 Pydantic、没有写 BaseModel，但校验仍然生效。因为 **FastAPI 在底层自动调用了 Pydantic 的 `TypeAdapter`**——它是 Pydantic 校验**单个值**的工具，不需要 BaseModel 包装。
>
> FastAPI 内部做的事（简化版）：
>
> ```python
> from pydantic import TypeAdapter
>
> # 1. FastAPI 读取你的类型提示 str，创建一个校验器
> name_validator = TypeAdapter(str)
>
> # 2. 从 URL /hello/张三 中提取 "张三"
> raw_value = "张三"
>
> # 3. 用 Pydantic 校验并转换
> validated_name = name_validator.validate_python(raw_value)
> # → "张三"（str 类型，校验通过）
> ```
>
> `BaseModel` 和 `TypeAdapter` 的分工：
>
> | 场景 | 你写的代码 | Pydantic 用哪个 |
> |------|-----------|----------------|
> | 单个路径参数 | `name: str` | `TypeAdapter(str)` |
> | 单个查询参数 | `page: int = 1` | `TypeAdapter(int)` |
> | 整个 JSON 请求体 | `book: Book` | `Book`（BaseModel） |
>
> > **一句话**：`name: str` 虽然没有显式出现 BaseModel，但 FastAPI 内部用 `TypeAdapter(str)` 包装了它——Pydantic 的校验引擎对所有 Python 类型都生效，不只是 BaseModel。
>
> ---
>
> #### ⚠️ 校验失败会怎样？怎么处理？
>
> 当类型不匹配时，FastAPI **不会让请求进入你的函数**，而是直接返回 422 错误：
>
> ```python
> @app.get("/items/{item_id}")
> def read_item(item_id: int):    # 声明了 int
>     # 这个函数根本不会被执行！
>     return {"item_id": item_id}
>
> # 访问 /items/abc → 返回 422 + 详细错误信息：
> # {
> #   "detail": [{
> #     "loc":   ["path", "item_id"],          ← 哪个参数出错了
> #     "msg":   "value is not a valid integer", ← 为什么出错
> #     "type":  "type_error.integer"           ← 错误类型
> #   }]
> # }
> ```
>
> 这和我们手写校验的代码量形成强烈对比。不用 FastAPI 时的传统写法（30+ 行）：
>
> ```python
> # ❌ 传统方式：每个接口都要手写校验逻辑
> @app.get("/items/{item_id}")
> def read_item(item_id: str):          # 只能收字符串
>     if not item_id.isdigit():         # 手动判空
>         return JSONResponse(          # 手动构造错误响应
>             status_code=400,
>             content={"error": "item_id must be integer"}
>         )
>     item_id = int(item_id)            # 手动类型转换
>     if item_id <= 0:                  # 手动范围校验
>         return error...
>     # 然后才到业务逻辑 ↑ 光校验就占了 15 行
>     return {"item_id": item_id}
> ```
>
> 而 FastAPI 只需要一行类型提示 `item_id: int`，校验、转换、错误响应全部自动完成。
>
> **常见校验失败的场景与返回**：
>
> | 场景 | 你声明的类型 | 请求传的值 | 返回 | 解释 |
> |------|------------|-----------|------|------|
> | 传入非数字 | `item_id: int` | `/items/abc` | 422 `type_error.integer` | 无法转为 int |
> | 传入空值 | `name: str` | `?name=` | 422 `type_error.none` | 空字符串 ≠ None（必填没设默认值） |
> | 超过范围 | `page: int = Query(ge=1)` | `?page=0` | 422 `number.not.ge` | 违反 `ge=1` 约束 |
> | 传入非法布尔 | `is_active: bool` | `?is_active=abc` | 422 `type_error.bool` | 只有 true/false/1/0/yes/no 能被解析 |
>
> **如何处理校验错误？分两个层面**：
>
> **① 前端处理（推荐首选）**——校验错误应该在客户端就被拦截：
>
> ```javascript
> // 前端：发请求前先做基本校验，不给后端添乱
> const id = parseInt(input);
> if (isNaN(id) || id <= 0) {
>     alert("请输入有效的正整数");
>     return;  // 根本不到发送请求这一步
> }
> fetch(`/items/${id}`)...  // 保证通过后才发请求
> ```
>
> **② 422 兜底处理**——即使前端漏了，后端也会返回清晰的错误：
>
> ```javascript
> // 前端：捕获 422 错误，提取字段级别的错误信息
> const res = await fetch(`/items/${id}`);
> if (res.status === 422) {
>     const err = await res.json();
>     // err.detail[0].loc → ["path", "item_id"] → 哪个字段
>     // err.detail[0].msg → "value is not a valid integer" → 给用户看
>     showError(`参数 ${err.detail[0].loc[1]} 不合法：${err.detail[0].msg}`);
> }
> ```
>
> > **最佳实践**：前端做第一层校验（用户体验），FastAPI 的 422 做兜底（安全保障），两者配合，不需要在路由函数里写任何校验代码。

**③ 整个装饰器的三步作用总结**

```
                      ┌─────────────────────────┐
    @app.get(         │  1. 注册路由             │
        "/hello/      │     告诉框架，这个 URL   │
        {name}"       │     由这个函数处理        │
    )                 │                          │
                      │  2. 限定方法             │
                      │     只能 GET 请求访问     │
                      │     POST 会报 405         │
                      │                          │
                      │  3. 声明路径参数          │
                      │     {name} = URL 中取值   │
                      │     自动传给函数参数       │
                      └─────────────────────────┘
```

#### 2.4.3 完整执行流程（以 `/hello/李四` 为例）

以 `@app.get("/hello/{name}")` 为例，从客户端发起请求到收到响应的全过程：

```
┌──────────────────────────────────────────────────────────────┐

## 3. 路径操作装饰器详解

### 3.1 什么是"路径操作"？

| 术语 | 解释 |
|------|------|
| **路径 (Path)** | URL 中域名后面的部分，如 `/items/123` |
| **操作 (Operation)** | HTTP 方法，如 GET/POST/PUT/DELETE |
| **路径操作** | HTTP 方法 + URL 路径的组合 |

### 3.2 常用 HTTP 方法

```python
@app.get("/items")           # 获取资源列表
@app.get("/items/{id}")      # 获取单个资源
@app.post("/items")          # 创建新资源
@app.put("/items/{id}")      # 完整更新资源  
@app.patch("/items/{id}")    # 部分更新资源
@app.delete("/items/{id}")   # 删除资源
```

### 3.3 装饰器参数

```python
@app.get(
    "/items",                    # 路径
    response_model=Item,         # 响应数据模型
    status_code=200,              # 响应状态码
    tags=["商品"],               # API 文档分组标签
    summary="获取商品列表",       # 文档中的摘要
    description="返回所有商品的列表，支持分页",  # 详细描述
    deprecated=False             # 是否已废弃
)
def get_items():
    return []
```

### 3.4 理解装饰器原理

装饰器本质上是"把函数注册给框架"：

```python
# 你写的代码
@app.get("/items")
def get_items():
    return [{"name": "Item1"}]

# FastAPI 内部做的事（简化版）
# 1. 把 "/items" 路径和 get_items 函数关联起来
# 2. 分析 get_items 的参数和返回值类型
# 3. 生成 OpenAPI 文档
# 4. 当收到 GET /items 请求时，调用 get_items()
# 5. 把返回值转为 JSON 发送给客户端
```

## 4. 路径参数

### 4.0 什么是路径参数？

路径参数是 URL 路径中的变量部分，用于标识具体资源。

```
/items/123
       ↑
    路径参数 item_id = 123

/users/张三/articles/456
       ↑              ↑
   username=张三    article_id=456
```

### 4.1 基本用法

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    """
    item_id: int = 告诉 FastAPI 这个参数必须是整数
    如果传入 "abc" → 自动返回 422 校验错误
    """
    return {"item_id": item_id, "name": f"Item {item_id}"}
```

### 4.2 类型转换

FastAPI 自动将路径中的字符串转为指定类型：

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    # URL: /items/123
    # FastAPI 自动把 "123"（字符串）转为 123（整数）
    return {"item_id": item_id}  # item_id 是 int 类型
```

> #### 📐 `Query()` 显式声明是什么意思？为什么需要？
>
> 先看 FastAPI 怎么判断一个参数是"查询参数"——**规则很简单：不在路径 `{}` 里的参数，自动归类为查询参数**。
>
> ```python
> @app.get("/items/{item_id}")          # URL 路径
> def read_item(
>     item_id: int,                     # ← 在路径的 {} 里 → 路径参数
>     page: int = 1,                    # ← 不在路径里 → 自动当查询参数
>     keyword: str = None               # ← 不在路径里 → 自动当查询参数
> ):
>     ...
>
> # 访问：/items/123?page=2&keyword=hello
> #          ↑ 路径参数    ↑ 查询参数   ↑ 查询参数
> ```
>
> **那 `Query()` 是干什么的？** `Query()` 和 `page: int = 1` 一样，都声明了一个查询参数。唯一的区别是：**`Query()` 可以附加约束条件**。
>
> ```python
> # 方式1：普通写法 → 只是查询参数，没有校验规则
> page: int = 1
>
> # 方式2：Query() 写法 → 还是查询参数，但加了约束
> page: int = Query(1, ge=1)           # ge=1 → 页码必须 ≥ 1
> page_size: int = Query(100, ge=1, le=5000)  # le=5000 → 每页最多 5000 条
> ```
>
> **两者的等价关系**：
>
> | 普通写法 | Query() 等价写法 | 区别 |
> |---------|-----------------|------|
> | `page: int = 1` | `page: int = Query(1)` | **完全等价**，都是查询参数，默认值 1 |
> | `name: str` | `name: str = Query(...)` | 必填查询参数，`...` 表示必填 |
> | 无法表达 | `page: int = Query(1, ge=1, le=100)` | **Query() 独有**：可以加范围约束 |
> | 无法表达 | `q: str = Query(None, min_length=3, regex="^[a-z]+$")` | **Query() 独有**：可以加正则 |
>
> > **一句话**：你在参数里写 `page: int = 1`，它已经是查询参数了。加上 `Query(1, ge=1)` 只是告诉 FastAPI："它不但是查询参数，而且值必须 ≥ 1，否则自动拒绝请求"。
>
> 这在项目中非常常见——比如 SyncHealth 的心率数据查询：

> ### 🏗️ 项目实例：SyncHealth 路由参数混合使用
>
> SyncHealth 的健康数据查询接口展示了路径参数、查询参数、依赖注入的经典组合。`start`/`end` 是可选查询参数（时间过滤），`page`/`page_size` 用 `Query()` 约束范围，`current_user` 通过 `Depends` 注入认证用户：
>
> ```python
> # backend/app/api/health.py - 健康数据查询端点（路径参数 + 查询参数 + 依赖注入）
> from fastapi import APIRouter, Depends, Query
> from datetime import datetime
>
> router = APIRouter(prefix="/health", tags=["health"])
>
> @router.get("/heart-rate")
> async def get_heart_rates(
>     start: datetime | None = None,           # 可选查询参数：起始时间
>     end: datetime | None = None,             # 可选查询参数：结束时间
>     measurement_type: str | None = None,     # 可选过滤：测量类型
>     page: int = Query(1, ge=1),              # Query() 约束：页码 >= 1
>     page_size: int = Query(100, ge=1, le=5000),  # 每页 1-5000 条
>     current_user: User = Depends(get_current_user),  # 依赖注入：认证用户
>     db: AsyncSession = Depends(get_db),      # 依赖注入：数据库会话
> ):
>     items, total = await query_heart_rates(
>         db, current_user.id, start, end, measurement_type, page, page_size
>     )
>     return PaginatedResponse(
>         items=[HeartRateOut.model_validate(i) for i in items],
>         total=total, page=page, page_size=page_size,
>         total_pages=math.ceil(total / page_size),
>     )
> ```
>
> 这个接口同时展示了 FastAPI 自动识别参数来源的能力：`start`/`end` 不在路径中 → 查询参数，`page` 用 `Query()` 显式声明 → 查询参数，`current_user` / `db` 用了 `Depends()` → 依赖注入。

### 4.3 枚举约束路径参数

当路径参数只能取几个固定值时，使用 `Enum`：

```python
from enum import Enum

# 定义枚举类
class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"

@app.get("/models/{model_name}")
def get_model(model_name: ModelName):
    """
    model_name 只能是 alexnet、resnet、lenet 中的一个
    传其他值 → 自动返回 422 校验错误
    """
    if model_name == ModelName.alexnet:
        return {"model_name": model_name, "message": "Deep Learning FTW!（FTW = For The Win）"}
    return {"model_name": model_name, "message": "Have some residuals"}
```

### 4.4 路径参数注意事项

**路径顺序很重要**：固定路径(/items/me)要写在动态路径(/items/{item_id})前面

```python
# ✅ 正确：固定路径 /items/me 在前
@app.get("/items/me")
def read_my_items():
    return {"message": "我的物品"}

@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}

# ❌ 错误：/items/me 被 /items/{item_id} 拦截
# 访问 /items/me 时，FastAPI 会把 "me" 当作 item_id
# 然后转换 int("me") 失败，返回 422 错误
```

### 4.5 含文件扩展名/多级目录的路径参数

#### 🐛 一、不加 `:path` 会出什么 BUG？

普通路径参数写法 `{file_path}`，FastAPI 默认只能匹配**一层路径**，遇到 `.` 或 `/` 就会截断：

```python
# ❌ 普通写法 —— 只能匹配一层路径
@app.get("/files/{file_path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

**错误场景演示**：

| 访问的 URL | 你期望得到的 `file_path` | 实际结果 |
|---|---|---|
| `/files/photo.jpg` | `"photo.jpg"` | ✅ 勉强能匹配（单层无 `/`） |
| `/files/static/photo.jpg` | `"static/photo.jpg"` | ❌ **返回 404** — FastAPI 只把 `static` 当参数，`/photo.jpg` 无路由匹配 |
| `/files/archive/file.tar.gz` | `"archive/file.tar.gz"` | ❌ **返回 404** — `/` 截断，且 `.tar.gz` 多重点解析异常 |

**根本原因**：
- 默认路径参数**遇到 `/` 就认为参数结束**，后面的内容不再属于该参数，导致多级目录匹配失败
- 遇到文件后缀中的 `.` 也可能解析异常（尤其是 `file.tar.gz` 这种多个点的文件名）

---

#### ✅ 二、`{file_path:path}` 的作用

`:path` 是 FastAPI/Starlette 的**路径转换器**，作用：

1. **捕获斜杠 `/`** — 支持多级文件夹路径，不再被 `/` 截断
2. **完整捕获** — 从当前路由位置之后**所有内容**（包括 `.`、多个 `.`、`/`）全部作为参数值，不会被截断

```python
# ✅ 正确写法 —— 使用 :path 转换器
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

**正确匹配示例**：

```python
# GET /files/photo.jpg
# → file_path = "photo.jpg"

# GET /files/docs/readme.md
# → file_path = "docs/readme.md"

# GET /files/archive/file.tar.gz
# → file_path = "archive/file.tar.gz"

# GET /files/a/b/c/deep/nested/file.txt
# → file_path = "a/b/c/deep/nested/file.txt"
```

> 📌 **一句话总结**：需要路径参数支持**多级目录 + 文件扩展名**时，用 `:path` 声明，否则 FastAPI 默认只取一层。

## 5. 查询参数

### 5.0 什么是查询参数？

URL 中 `?` 后面的键值对就是查询参数，用于过滤、排序、分页等。

```
/items?page=1&size=10&sort=price_desc
       ↑________↑________↑
       查询参数：page=1, size=10, sort=price_desc
```

### 5.1 基本用法

**不在路径中的函数参数，自动被视为查询参数**：

```python
@app.get("/items/")
def read_items(skip: int = 0, limit: int = 10):
    """
    访问：GET /items/                 → skip=0, limit=10（使用默认值）
    访问：GET /items/?skip=20         → skip=20, limit=10
    访问：GET /items/?skip=20&limit=5 → skip=20, limit=5
    """
    return {"skip": skip, "limit": limit}
```

### 5.2 必填 vs 可选

```python
@app.get("/search/")
def search(
    keyword: str,                    # 没有默认值 → 必填
    page: int = 1,                   # 有默认值 → 可选
    size: int = 20                   # 有默认值 → 可选
):
    """
    访问：/search/?keyword=Python     → keyword="Python"
    访问：/search/                    → 返回 422 错误（缺少必填参数 keyword）
    """
    return {"keyword": keyword, "page": page, "size": size}
```

### 5.3 可选类型 Optional

```python
from typing import Optional

@app.get("/users/")
def get_users(
    name: Optional[str] = None,     # 可选，默认 None
    age: Optional[int] = None,      # 可选，默认 None
    is_active: Optional[bool] = None
):
    """
    Optional[str] = 可以是 str 或 None
    访问：/users/                      → name=None, age=None
    访问：/users/?name=张三&age=25      → name="张三", age=25
    """
    filters = {}
    if name:
        filters["name"] = name
    if age:
        filters["age"] = age
    return {"filters": filters}
```

### 5.4 布尔类型的查询参数

```python
@app.get("/items/")
def get_items(
    in_stock: bool = False,         # 默认 False
    on_sale: Optional[bool] = None  # 可以是 True/False/不传
):
    """
    布尔参数的传值方式：
    /items/?in_stock=true           → in_stock=True
    /items/?in_stock=false          → in_stock=False
    /items/?in_stock=1              → in_stock=True
    /items/?in_stock=yes            → in_stock=True
    /items/?in_stock=0              → in_stock=False
    /items/?in_stock=no             → in_stock=False
    """
    return {"in_stock": in_stock, "on_sale": on_sale}
```

### 5.5 Query() 高级校验

```python
from fastapi import Query

@app.get("/items/")
def read_items(
    q: str = Query(
        default=None,               # 默认值
        min_length=3,               # 最小长度
        max_length=50,              # 最大长度
        regex="^[a-zA-Z]+$",        # 正则校验（只能英文字母）
        alias="item-query",         # 别名（URL 参数名）
        title="搜索关键词",          # 文档标题
        description="用于模糊搜索的关键词",  # 文档描述
        deprecated=False            # 是否已废弃
    ),
    page: int = Query(default=1, ge=1, description="页码，最小为 1"),
    size: int = Query(default=10, ge=1, le=100, description="每页数量，1-100")
):
    """
    访问：/items/?item-query=hello&page=1&size=20
    参数 item-query（带连字符）对应 Python 函数参数 q
    """
    return {"q": q, "page": page, "size": size}
```

### 5.6 查询参数接收列表

```python
@app.get("/items/multi/")
def read_multiple_items(ids: list[int] = Query(default=[])):
    """
    接收多个同名查询参数
    访问：/items/multi/?ids=1&ids=2&ids=3
    → ids = [1, 2, 3]
    """
    return {"ids": ids}
```

## 6. 请求体与 Pydantic 基础

### 6.0 什么是请求体？

客户端发送给 API 的数据（如 JSON），放在 HTTP 请求的 body 中：

```
POST /books HTTP/1.1            ← 请求行
Content-Type: application/json  ← 请求头
                                 ← 空行
{                                ← 请求体（Body）
    "title": "三体",
    "author": "刘慈欣",
    "price": 39.90
}
```

### 6.1 Pydantic BaseModel 定义模型
没有默认值、也没有标注 Optional | None → 必填字段
给了默认值（包括 None） 或者 类型包含 None → 可选字段
```python
from pydantic import BaseModel
from typing import Optional

# 定义数据模型（Schema）
class Book(BaseModel):
    """图书数据模型"""
    title: str                              # 必填，字符串
    author: str                             # 必填，字符串
    price: float                            # 必填，浮点数
    description: Optional[str] = None       # 可选，默认 None
    is_published: bool = True               # 可选，默认 True
    tags: list[str] = []                    # 可选，默认空列表
```

### 6.2 POST 请求接收请求体

```python
@app.post("/books/")
def create_book(book: Book):
    """
    FastAPI 会自动：
    1. 读取请求体中的 JSON
    2. 用 Book 模型校验数据
    3. 校验失败 → 返回 422 错误（并说明哪个字段有问题）
    4. 校验通过 → book 是一个 Book 实例
    """
    # book.title、book.author 可以直接访问
    # IDE 有自动补全，因为类型是确定的！
    return {
        "message": f"图书《{book.title}》添加成功",
        "book": book
    }
```

> ### 🏗️ 项目实例：SyncHealth 的请求/响应模型分离
>
> SyncHealth 项目中严格区分**输入模型**和**输出模型**。输入模型收数据（如 `UserRegister` 含密码），输出模型过滤敏感字段（如 `UserResponse` 不含密码）：
>
> ```python
> # backend/app/schemas/auth.py - 认证相关的 Pydantic Schema
> from pydantic import BaseModel
>
> # 输入模型：注册时需要密码
> class UserRegister(BaseModel):
>     email: str
>     password: str
>     display_name: str
>
> # 输入模型：登录只需邮箱密码
> class UserLogin(BaseModel):
>     email: str
>     password: str
>
> # 输出模型：返回 token，不返回密码
> class TokenResponse(BaseModel):
>     access_token: str
>     refresh_token: str
>     token_type: str = "bearer"
>
> # 输出模型：用户信息不含密码哈希
> class UserResponse(BaseModel):
>     id: int
>     email: str
>     display_name: str
>     created_at: str
>     last_sync_at: str | None = None
>     model_config = {"from_attributes": True}  # 支持从 ORM 对象构建
> ```
>
> 健康数据 Schema 则采用继承模式：`HealthSampleBase` 定义公共字段（`sample_uuid`, `source_device`, `recorded_at`），各类型子类（如 `HeartRateIn`）添加自己的专有字段，输出子类（如 `HeartRateOut`）再增加 `id` 和 `synced_at`：
>
> ```python
> # backend/app/schemas/health.py - 健康数据 Schema（继承层级）
> class HealthSampleBase(BaseModel):
>     sample_uuid: str
>     source_device: str | None = None
>     recorded_at: datetime
>
> class HeartRateIn(HealthSampleBase):   # 输入：继承基础字段 + 心率专属
>     bpm: float
>     motion_context: str | None = None
>     measurement_type: str = "heart_rate"
>
> class HeartRateOut(HeartRateIn):       # 输出：继承输入字段 + 系统字段
>     id: int
>     synced_at: datetime
>     model_config = {"from_attributes": True}
> ```

> ### 🏗️ 项目实例：SyncHealth 的嵌套模型与模型继承实战
>
> SyncHealth 中，`SleepSession`（睡眠会话）内嵌 `SleepStage`（睡眠阶段）列表，演示了模型组合的实际用法：
>
> ```python
> # backend/app/schemas/health.py - 嵌套模型：SleepSession 包含 SleepStage 列表
> class SleepStageIn(BaseModel):
>     stage: str              # awake, rem, core, deep
>     start_time: datetime
>     end_time: datetime
>     duration_minutes: float
>
> class SleepSessionIn(HealthSampleBase):
>     start_time: datetime
>     end_time: datetime
>     total_duration_minutes: float
>     in_bed_duration_minutes: float | None = None
>     stages: list[SleepStageIn] = []   # 嵌套：一个睡眠会话包含多个阶段
> ```
>
> 来看两个实际的睡眠数据长什么样：
>
> **例子 1：典型的夜间睡眠（7 小时 42 分，包含 4 种阶段循环多次）**
>
> Apple Watch 记录了用户从入睡到醒来的完整过程，睡眠阶段会在 REM（快速眼动）、Core（核心睡眠）、Deep（深度睡眠）之间反复交替：
>
> ```json
> {
>     "sample_uuid": "sleep-20260704-001",
>     "recorded_at": "2026-07-04T07:30:00",
>     "start_time": "2026-07-03T23:15:00",
>     "end_time": "2026-07-04T06:57:00",
>     "total_duration_minutes": 462.0,
>     "in_bed_duration_minutes": 480.0,
>     "stages": [
>         { "stage": "core",    "start_time": "23:15", "end_time": "23:50", "duration_minutes": 35 },
>         { "stage": "deep",    "start_time": "23:50", "end_time": "00:45", "duration_minutes": 55 },
>         { "stage": "core",    "start_time": "00:45", "end_time": "02:10", "duration_minutes": 85 },
>         { "stage": "rem",     "start_time": "02:10", "end_time": "02:35", "duration_minutes": 25 },
>         { "stage": "core",    "start_time": "02:35", "end_time": "04:20", "duration_minutes": 105 },
>         { "stage": "deep",    "start_time": "04:20", "end_time": "05:00", "duration_minutes": 40 },
>         { "stage": "rem",     "start_time": "05:00", "end_time": "05:40", "duration_minutes": 40 },
>         { "stage": "core",    "start_time": "05:40", "end_time": "06:40", "duration_minutes": 60 },
>         { "stage": "awake",   "start_time": "06:40", "end_time": "06:57", "duration_minutes": 17 }
>     ]
> }
> ```
>
> **例子 2：午休小睡（45 分钟，只有浅层睡眠）**
>
> ```json
> {
>     "sample_uuid": "sleep-20260704-002",
>     "recorded_at": "2026-07-04T13:30:00",
>     "start_time": "2026-07-04T12:45:00",
>     "end_time": "2026-07-04T13:30:00",
>     "total_duration_minutes": 45.0,
>     "in_bed_duration_minutes": 50.0,
>     "stages": [
>         { "stage": "core",  "start_time": "12:45", "end_time": "13:30", "duration_minutes": 45 }
>     ]
> }
> ```
>
> **为什么不用一张大表存所有阶段？**
>
> 如果用传统方式，睡眠会话和阶段混在一张大表里，`stages` 的每个元素都是一行独立的数据库记录，通过 `session_id` 外键关联：
>
> ```
> ❌ 平铺到 API 响应中：
> [{ "session_id": 1, "stage": "core", "duration": 35 },
>  { "session_id": 1, "stage": "deep", "duration": 55 },
>  { "session_id": 1, "stage": "core", "duration": 85 }, ...]
> // 前端需要手动按 session_id 分组，才能组装出一个完整的"今晚睡眠图"
>
> ✅ 嵌套模型返回：
> { "start_time": "23:15", "total_duration_minutes": 462,
>   "stages": [{...}, {...}, ...] }
> // 前端拿到就是一个完整的对象，直接渲染 Apple Watch 风格的时间线图表
> ```
>
> 这就是嵌套模型的真正价值：**让 API 返回的数据结构和业务场景一致**——一次睡眠就是一个对象，阶段是这个对象的自然组成部分，前端不需要自己拼装。
>
> `WorkoutRecord` 同样内嵌 `WorkoutHRZone`（心率区间），进一步展示了多级嵌套：
>
> ```python
> class WorkoutHRZoneIn(BaseModel):
>     zone_index: int
>     lower_bound_bpm: float
>     upper_bound_bpm: float
>     duration_seconds: float
>
> class WorkoutRecordIn(HealthSampleBase):
>     workout_type: str
>     start_time: datetime
>     end_time: datetime
>     duration_seconds: float
>     avg_heart_rate: float | None = None
>     max_heart_rate: float | None = None
>     hr_zones: list[WorkoutHRZoneIn] = []  # 嵌套：锻炼记录包含多个心率区间
> ```
>
> 来看两次不同强度的锻炼，心率区间的分布完全不同：
>
> **例子 1：30 分钟户外跑步（高强度，心率集中在 4-5 区）**
>
> ```json
> {
>     "sample_uuid": "workout-20260704-001",
>     "recorded_at": "2026-07-04T07:00:00",
>     "workout_type": "running",
>     "start_time": "2026-07-04T06:30:00",
>     "end_time": "2026-07-04T07:00:00",
>     "duration_seconds": 1800,
>     "avg_heart_rate": 158.0,
>     "max_heart_rate": 182.0,
>     "hr_zones": [
>         { "zone_index": 1, "lower_bound_bpm": 0,   "upper_bound_bpm": 120, "duration_seconds": 60 },
>         { "zone_index": 2, "lower_bound_bpm": 120, "upper_bound_bpm": 140, "duration_seconds": 180 },
>         { "zone_index": 3, "lower_bound_bpm": 140, "upper_bound_bpm": 160, "duration_seconds": 420 },
>         { "zone_index": 4, "lower_bound_bpm": 160, "upper_bound_bpm": 175, "duration_seconds": 720 },
>         { "zone_index": 5, "lower_bound_bpm": 175, "upper_bound_bpm": 200, "duration_seconds": 420 }
>     ]
> }
> ```
>
> 跑步时一半以上时间在 4-5 区（高强度有氧/无氧），只有 1 分钟在 1 区热身。
>
> **例子 2：45 分钟瑜伽（低强度，心率全程在 1-2 区）**
>
> ```json
> {
>     "sample_uuid": "workout-20260704-002",
>     "recorded_at": "2026-07-04T19:00:00",
>     "workout_type": "yoga",
>     "start_time": "2026-07-04T18:15:00",
>     "end_time": "2026-07-04T19:00:00",
>     "duration_seconds": 2700,
>     "avg_heart_rate": 95.0,
>     "max_heart_rate": 115.0,
>     "hr_zones": [
>         { "zone_index": 1, "lower_bound_bpm": 0,   "upper_bound_bpm": 120, "duration_seconds": 2400 },
>         { "zone_index": 2, "lower_bound_bpm": 120, "upper_bound_bpm": 140, "duration_seconds": 300 }
>     ]
> }
> ```
>
> 瑜伽几乎没有进入 3-5 区——这完全符合运动类型的预期。前端的健康图表可以据此画出不同颜色的心率区间堆叠图，每种颜色代表一个运动强度级别。
>
> **对比：睡眠和锻炼都用了嵌套模型，但表达的意义不同**：
>
> | | 睡眠（SleepSession → SleepStage） | 锻炼（WorkoutRecord → WorkoutHRZone） |
> |------|------|------|
> | 嵌套的是什么 | 按**时间顺序**的阶段（23:15 core → 23:50 deep → ...） | 按**强度分级**的区间（1区多久、2区多久...） |
> | 数组含义 | 时间线片段（必须按顺序排列） | 分类统计（顺序无关，但 zone_index 递增） |
> | 核心用途 | 画睡眠阶段时间轴 | 画心率强度饼图 / 堆叠柱状图 |
>
> 同样的 `list[子对象]` 结构，表达的是完全不同的业务语义——这就是 Pydantic 嵌套模型的灵活之处。

## 8. 参数混合使用

### 8.1 路径参数 + 查询参数 + 请求体

FastAPI 能自动识别参数来源：

```python
@app.put("/items/{item_id}")
def update_item(
    item_id: int,                              # ← 路径参数
    q: Optional[str] = None,                   # ← 查询参数
    item: Book = None                          # ← 请求体
):
    results = {"item_id": item_id}
    if q:
        results["q"] = q
    if item:
        results["item"] = item
    return results
```

### 8.2 FastAPI 如何区分参数来源？

| 参数特征 | 来源 |
|----------|------|
| 在路径中出现 `{param}` | 路径参数 |
| 是 Pydantic 模型类型 | 请求体 |
| 是简单类型（str/int/float/bool）且不在路径中 | 查询参数 |
| 使用了 `Body()` | 请求体 |
| 使用了 `Query()` | 查询参数 |
| 使用了 `Path()` | 路径参数（可添加额外校验） |

### 8.3 多个请求体

```python
from fastapi import Body

@app.put("/items/{item_id}")
def update_item(
    item_id: int,
    item: Book = Body(...),                    # ... 表示必填
    user: dict = Body(...),
    importance: int = Body(gt=0)               # 单个值也可以放在 Body
):
    return {
        "item_id": item_id,
        "item": item,
        "user": user,
        "importance": importance
    }
```

对应的 JSON 请求体：
```json

    "item": {

        "author": "刘慈欣",
        "price": 39.9
    },
    "user": {
        "name": "admin"

    "importance": 5
}
```

## 📝 第1阶段总结

### 核心知识点

| 概念 | 说明 | 关键代码 |
|------|------|----------|
| FastAPI 应用 | 框架核心实例 | `app = FastAPI()` |
| 路径操作装饰器 | 定义路由 | `@app.get("/path")` |
| 路径参数 | URL 中的变量 | `{item_id}` → `item_id: int` |
| 查询参数 | `?` 后面的参数 | `skip: int = 0` |
| Pydantic BaseModel | 数据校验模型 | `class Book(BaseModel)` |
| 请求体 Body | POST/PUT 的 JSON 数据 | 参数类型是 BaseModel |
| 类型提示 | 自动校验和文档 | `name: str`, `age: int` |
| Swagger UI | 交互式文档 | `http://...:8000/docs` |

### HTTP 方法和用途速查

| 方法 | 用途 | 幂等性 | 是否有 Body |
|------|------|--------|-------------|
| GET | 获取资源 | ✅ 是 | ❌ 无 |
| POST | 创建资源 | ❌ 否 | ✅ 有 |
| PUT | 完整更新 | ✅ 是 | ✅ 有 |
| PATCH | 部分更新 | ❌ 否 | ✅ 有 |
| DELETE | 删除资源 | ✅ 是 | ❌ 无 |

### 常见错误速查

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| 404 Not Found | 路径不匹配 | 检查 URL 路径和装饰器路径是否一致 |
| 422 Unprocessable Entity | 参数校验失败 | 查看响应中的 `detail` 字段，修改参数 |
| 500 Internal Server Error | 代码报错 | 查看 uvicorn 终端输出的错误信息 |
| `TypeError: 'NoneType' object...` | 忘记 await | async 函数中使用 `await` |

### 最佳实践

1. **总是使用类型提示** - 这是 FastAPI 的核心价值
2. **用 Pydantic 模型定义数据** - 不要用原始字典
3. **善用 `/docs`** - 开发阶段最好的调试工具
4. **开启 `--reload`** - 代码改动自动重启
5. **路径命名用复数** - `/books` 而非 `/book`（RESTful 惯例）
