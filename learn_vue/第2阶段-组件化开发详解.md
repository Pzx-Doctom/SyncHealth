## 1. 组件基础

### 1.1 为什么需要组件？

```
传统开发：
┌────────────────────────────────┐
│         一个巨大的 HTML        │
│   所有代码混在一起，难以维护   │
└────────────────────────────────┘

组件化开发：
┌──────────┐  ┌──────────┐  ┌──────────┐
│  Header  │  │  Sidebar │  │  Content │
│   组件   │  │   组件   │  │   组件   │
└──────────┘  └──────────┘  └──────────┘
     │             │             │
     └─────────────┼─────────────┘
                   ▼
            ┌──────────┐
            │   App    │
            │  根组件  │
            └──────────┘
```

**组件的优势**：
- 代码复用
- 便于维护
- 职责分离
- 团队协作

### 1.2 全局组件注册

> **前置知识说明**：在学习全局组件注册前，需要先了解 Vue应用实例的创建过程。`createApp()` 是 Vue 3 创建应用实例的入口方法，返回的应用实例包含了注册组件、挂载应用等方法。
>
> **Vue应用的启动流程**：
> 1.调 `createApp()` 创建一个 Vue应用实例
> 2. 通过 `app.component()` 注册组件（全局可用）
> 3. 通过 `app.mount('#app')`将应用挂载到指定的 DOM元上
> 4. Vue 开始解析模板并渲染组件
>
> **组件注册的本质**：
> - 组件注册就是把组件配置对象（包含 template、data、methods等）存储到 Vue 的内部注册表中
> - 当模板中使用 `<my-button>`标签时，Vue 会查找注册表，找到对应的配置对象并创建组件实例
> -组件实例都有自己独立的数据和状态
>
> **代码逐行解读**：
>
> **第1步：创建应用实例**
> ```javascript
> const { createApp } = Vue;  // 从 Vue 中解构出 createApp 方法
> const app = createApp({      // 创建 Vue应用实例
>   data() {                   //根的数据
>     return { title: '我的应用' }
>   }
> });
> ```
>
> **第2步：注册全局组件**
> ```javascript
> app.component('my-button', {  // 注册名为 my-button 的组件
>   template: `<button>...</button>`,  //组件的 HTML模板
>   data() { return { count: 0 } },    //组件自己的数据
>   methods: { handleClick() { ... } }  // 组件的方法
> });
> ```
>
> **第3步：挂载应用**
> ```javascript
> app.mount('#app');  //将整个应用渲染到 id 为 app 的元素中
> ```
>
> **模板中的使用**：
> ```html
> <div id="app">
>   <my-button>点击我</my-button>  <!-- 使用已注册的全局组件 -->
> </div>
> ```
>
> **执行过程**：
> 1. Vue 解析到 `<my-button>`标签
> 2. 查找全局注册表中名为 `my-button` 的组件
> 3.根据配置对象创建组件实例
> 4.渲组件的 template内容
> 5.组件实例拥有独立的 data 和 methods

```html
<script>
// 从 Vue 中解构出 createApp 方法
const { createApp } = Vue;

// 创建 Vue 应用实例
// createApp() 接收一个根组件配置对象
const app = createApp({
    // data()函数返回组件的响应式数据
    //组件实例都有自己独立的数据
    data() {
        return {
            title: '我的应用'  //这是根组件的数据
        }
    }
});

// 注册全局组件
// app.component() 方法注册的组件可以在应用的任何地方使用
app.component('my-button', {
    // 组件模板：定义组件的 HTML 结构
    // 使用模板字符串可以方便地编写多行 HTML
    template: `
        <button class="my-btn">
            <!-- slot 插槽：允许父组件向子组件传递内容 -->
            <!-- 如果父组件没有提供内容，则显示默认文本 -->
            <slot>默认按钮</slot>
        </button>
    `,
    // 组件数据：每个组件实例都有独立的数据
    data() {
        return {
            count: 0  // 组件内部的计数器
        }
    },
    // 组件方法：定义组件的行为
    methods: {
        handleClick() {
            // this指向当前组件实例
            this.count++;
            console.log('按钮被点击，当前计数：', this.count);
        }
    }
});

// 注册另一个全局组件
app.component('my-card', {
    //模板中使用插槽和插值表达式
    template: `
        <div class="card">
            <!-- 使用 props接收父组件传递的数据 -->
            <h3>{{ title }}</h3>
            <!-- 默认插槽 -->
            <slot></slot>
        </div>
    `,
    // props:声组件接收的外部数据
    //通过属性向子组件传递数据
    props: ['title']
});

//挂应用应用到 DOM元
// mount() 方法将 Vue 应用渲染到指定的 HTML元素中
app.mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <!-- 使用全局组件 -->
    <!--组件名使用 kebab-case格 -->
    <my-button>点击我</my-button>
    
    <!--向传递 props 数据 -->
    <my-card title="卡片标题">
        <!-- 通过插槽向组件传递内容 -->
        <p>卡片内容</p>
    </my-card>
</div>
```

> **补充说明**：
> 
> **全局组件的特点**：
> - 在整个应用中都可以使用
> - 适合通用性组件（如按钮、卡片、表单控件等）
> -过使用可能导致命名冲突和性能问题
> 
> **组件注册的本质**：
>组件注册实际上是将组件配置对象存储在 Vue应用的组件注册表中。当模板中使用组件标签时，Vue 会查找注册表并创建对应的组件实例。
>
> **全局组件 vs局组件对比**：
>
> |特 |全局组件 |局组件组件 |
> |------|----------|----------|
> | 注册方式 | `app.component()` | `components` 选项 |
> | 使用范围 |整应用 | 仅在注册它的组件内 |
> | 适用场景 | 通用基础组件 | 业务特定组件 |
> |性能影响 | 注册过多影响性能 |性能更好，按需加载 |
> |命名冲突 |容冲突 | 作用域隔离 |
>
> **实际开发建议**：
> - 项目中 80% 的组件应该使用局部注册
> -只有基础 UI组件（如按钮、输入框）才考虑全局注册
> -大型项目中可以使用自动化工具批量注册常用组件

### 1.3 局部组件注册

> **前置知识说明**：局部组件注册需要先理解组件对象的结构。每个组件都是一个包含 template、data、methods等选项的配置对象，通过 components 选项在父组件中注册。

```html
<script>
const { createApp } = Vue;

// 定义组件对象（只是创建配置对象，还未注册）
// TodoItem 组件：表示单个待办事项
const TodoItem = {
    // 组件模板：定义单个待办项的结构
    template: `
        <li class="todo-item">
            <!--显示待办事项文本 -->
            {{ text }}
            <!-- 删除按钮：点击时触发 remove 事件 -->
            <!-- $emit() 是触发自定义事件的方法 -->
            <button @click="$emit('remove')">删除</button>
        </li>
    `,
    // props声：接收父组件传递的文本数据
    props: ['text']
};

// TodoList 组件：待办事项列表容器
const TodoList = {
    //组件模板：定义列表的整体结构
    template: `
        <div class="todo-list">
            <h2>待办事项</h2>
            <ul>
                <!-- 使用 v-for指渲染列表 -->
                <!-- todo-item组件对应一个待办事项 -->
                <todo-item 
                    v-for="(todo, index) in todos" 
                    :key="todo.id"           <!-- 为每个元素提供唯一标识 -->
                    :text="todo.text"        <!-- 通过 props 传递文本 -->
                    @remove="removeTodo(index)" <!--监听子组件的 remove 事件 -->
                />
            </ul>
        </div>
    `,
    //局注册：只能在这个组件内部使用

    // 组件数据：存储待办事项列表
    data() {
        return {
            todos: [
                { id: 1, text: '学习 Vue' },
                { id: 2, text: '写代码' }
            ]
        }
    },
    //组件方法：处理业务逻辑
    methods: {
        // 删除指定索引的待办事项
        removeTodo(index) {
            // 使用数组的 splice 方法删除元素
            this.todos.splice(index, 1);
            console.log('删除了第', index, '个待办事项');
        }
    }
};

// 创建应用并注册根组件
createApp({
    // 在根组件中注册 TodoList 组件
    components: {
        'todo-list': TodoList
    }
}).mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <!-- 使用已注册的 todo-list 组件 -->
    <todo-list></todo-list>
</div>
```

> **补充说明**：
> 
> **局部组件 vs全局组件**：
> - **局部组件**：只在注册它的组件内部可用，作用域更小，更利于模块化
> - **全局组件**：在整个应用中都可用，适合基础通用组件
> 
> **组件注册的层级关系**：
> ```
> App（根组件）
> └── TodoList（局部注册）
>     └── TodoItem（在 TodoList 中局部注册）
> ```
> 
> **组件通信流程**：
> 1. TodoList 通过 props向Item 传递数据（text）
> 2. TodoItem 通过 $emit向List 发送事件（remove）
> 3. TodoList 在事件处理函数中修改自己的数据

### 1.4 组件命名规范

```javascript
// 推荐使用 PascalCase 或 kebab-case
app.component('MyComponent', { ... });  // PascalCase
app.component('my-component', { ... }); // kebab-case

// 在模板中使用
<my-component></my-component>  // kebab-case
<MyComponent></MyComponent>    // PascalCase（需要构建工具）
```

> 📌 **项目实战：SyncHealth 中的 SFC 组件命名与使用**
>
> 在我们的工程化 Vue 项目中，所有组件都使用 `.vue` 单文件组件（SFC）形式存放。命名遵循 **PascalCase** 规范，例如 `AppLayout.vue`、`LoginView.vue`、`DashboardView.vue`、`AIChatView.vue`。
>
> 在模板中引用组件时，Vue 的构建工具（Vite + `@vitejs/plugin-vue`）会自动将 PascalCase 的组件名转换为 kebab-case 标签。例如，在 `router/index.ts` 中通过 `component: () => import('../views/LoginView.vue')` 导入的 `LoginView.vue`，模板中可以直接使用。路由组件不需要手动注册——Vue Router 会根据路由配置自动渲染对应的组件到 `<router-view />` 中。
>
> 在 `AppLayout.vue` 中，`<router-link>` 和 `<router-view />` 的使用展示了工程化项目中组件的典型协作方式：`<router-link>` 负责生成导航链接（与知识点 6.1 的 `v-on` 事件处理不同，它走的是声明式导航），`<router-view />` 作为子路由的渲染出口。这两个组件来自 `vue-router` 包，通过在 `main.ts` 中 `app.use(router)` 注册后才全局可用。整个侧边栏布局（固定在左侧 240px 宽度，包含导航列表和用户信息）+ 右侧动态内容区，形成了一个典型的后台管理布局模式。

## 2. Props 父传子

### 2.1基本用法

> **前置知识说明**：Props 是父组件向子组件传递数据的机制。在使用 props前，需要理解组件间的数据流向是单向的：父组件 →子组件。

```html
<script>
//子组件：UserCard（用户卡片）
const UserCard = {
    // props 选项：声明组件接收的外部数据
    //这些数据由父组件通过 HTML 属性传递
    props: ['name', 'age', 'email'],
    
    // 局部注册：只能在这个组件内部使用
    // components 选项定义该组件可以使用的子组件
    components: {
        // 键：组件在模板中的使用名称
        // 值：组件配置对象
        'todo-item': TodoItem  // 或简写：TodoItem（ES6 对象属性简写）
    },
    
    // 组件模板：使用接收到的 props 数据
    template: `
        <div class="user-card">
            <!-- 使用插值表达式显示 props 数据 -->
            <h3>{{ name }}</h3>      <!--显示用户名 -->
            <p>年龄：{{ age }}</p>   <!-- 显示年龄 -->
            <p>邮箱：{{ email }}</p> <!--显示邮箱 -->
        </div>
    `
    // 注意：props 中的数据是只读的，不应该在子组件中直接修改
};

//父组件
createApp({
    // 注册子组件 UserCard
    components: { UserCard },
    
    //父组件的数据
    data() {
        return {
            // 用户对象：包含要传递给子组件的数据
            user: {
                name: '张三',
                age: 25,
                email: 'zhangsan@example.com'
            }
        }
    }
}).mount('#app');
</script>
                 
<!-- HTML 模板 -->
<div id="app">
    <!-- 方式1：传递动态数据（使用 v-bind 或 :） -->
    <user-card 
        :name="user.name"     <!-- :name 是 v-bind:name 的简写 -->
        :age="user.age"       <!-- 绑定响应式数据 -->
        :email="user.email"   <!-- 数据变化时组件会自动更新 -->
    />
    
    <!-- 方式2：传递静态值（直接写字符串） -->
    <user-card 
        name="李四"           <!-- 字符串值 -->
        age="30"              <!-- 注意：这是字符串 "30"，不是数字 30 -->
        email="lisi@example.com" 
    />
</div>
```

> **补充说明**：
> 
> **Props 的工作原理**：
> 1.父在模板中通过属性向子组件传递数据
> 2.子组件通过 props 选项声明接收哪些数据
> 3. Vue 自动将父组件的数据传递给子组件的 props
> 4.子组件可以通过 `this.propName`访这些数据
> 
> **动态绑定 vs静值**：
> - `:prop="value"` - 动态绑定：传递 JavaScript表达式的值
> - `prop="value"` -静绑定：传递字符串字面量
> 
> **Props 的特点**：
> - **单向数据流**：数据只能从父组件流向子组件
> - **只读性**：子组件不应该直接修改 props 数据
> - **响应式**：父组件数据变化时，子组件会自动更新

### 2.2 Props 类型验证

> **前置知识说明**：类型验证是确保组件接收正确数据的重要机制。通过类型验证可以在开发阶段发现数据类型错误，提高代码的健壮性。

```javascript
const UserCard = {
    // props 选项的完整形式：对象形式
    //每 prop 可以配置类型、是否必需、默认值等
    props: {
        //基类型检查
        //写法：只指定类型
        name: String,      //要 name 是字符串类型
        age: Number,       //要求 age 是数字类型
        isActive: Boolean, //要求 isActive 是布尔类型
        
        //多种类型：允许传入多种类型的数据
        id: [String, Number], // id可以是字符串或数字
        
        //必填项：必须由父组件传递
        title: {
            type: String,     // 类型检查
            required: true    //必属性，不传会警告
        },
        
        //带值：父组件未传递时使用默认值
        count: {
            type: Number,    // 类型检查
            default: 0        // 默认值为 0
            // 当父组件没有传递 count 时，组件内部 this.count = 0
        },
        
        // 对象/数组默认值必须用工厂函数
        //原因：避免多个组件实例共享同一个对象引用
        list: {
            type: Array,
            // 使用函数返回新数组，确保每个实例都有独立的数据
            default() {
                return [];    //调用返回新的空数组
            }
        },
        
        // 自定义验证：实现复杂的验证逻辑
        score: {
            type: Number,
            // validator函数接收传入的值，返回 true/false
            validator(value) {
                // 验证分数必须在 0-100 之间
                return value >= 0 && value <= 100;
                // 返回 false 时会在控制台显示警告
            }
        },
        
        // 对象类型的完整示例
        user: {
            type: Object,
            default() {
                return {
                    name: '匿名用户',
                    age: 0
                };
            },
            validator(obj) {
                // 验证对象必须包含 name 和 age属性
                return obj.name && typeof obj.age === 'number';
            }
        }
    },
    template: `<div>...</div>`
};
```

> **补充说明**：
> 
> **类型验证的好处**：
> 1. **开发时检查**：在开发阶段就能发现类型错误
> 2. **文档作用**：清楚地表明组件需要什么类型的数据
> 3. **团队协作**：让其他开发者知道如何正确使用组件
> 
> **验证失败的处理**：
> - 开发模式：控制台会显示警告信息
> - 生产模式：验证会被跳过以提高性能
> 
> **常用类型**：
> -基本类型：`String`, `Number`, `Boolean`, `Array`, `Object`
> -特类型：`Date`, `Function`, `Symbol`, `Promise`
> - 自定义构造函数：`MyClass`（自定义类）
> 
> **最佳实践**：
> - 对外暴露的组件应该使用完整的 props 验证
> -内部私有组件可以使用简单形式
> -合设置默认值，提高组件的易用性

### 2.3 单向数据流

```
// ❌ 错误：直接修改 props
const ChildComponent = {
    props: ['count'],
    methods: {
        increment() {
            this.count++;  // 不要这样做！
        }
    }
};

// ✅ 正确方式1：用本地 data 接收
const ChildComponent = {
    props: ['initialCount'],
    data() {
        return {
            localCount: this.initialCount  // 复制到本地
        }
    },
    methods: {
        increment() {
            this.localCount++;  // 修改本地副本
        }
    }
};

// ✅ 正确方式2：通知父组件修改
const ChildComponent = {
    props: ['count'],
    emits: ['update:count'],
    methods: {
        increment() {
            this.$emit('update:count', this.count + 1);
        }
    }
};
```

> **补充说明**：
> 
> **为什么不能直接修改 props？**
> 
> Vue 强制实施单向数据流的原因：
> 
> 1. **维护数据源的一致性**：如果多个子组件都直接修改同一个 prop，父组件无法知道数据被改变了，导致数据不同步。例如：
>    ```
>    父组件 data: count = 10
>      ├── 子组件A 接收 :count="count" → 直接改为 5
>      ├── 子组件B 接收 :count="count" → 直接改为 15
>      └── 父组件还认为 count = 10  ❌ 数据混乱
>    ```
> 
> 2. **便于问题排查**：如果数据被修改了，你无法快速定位是哪个子组件改的，调试会变得非常困难。当采用统一的"子通知父，父修改"模式后，所有数据变化都通过事件，易于追踪和调试。
> 
> 3. **Props 是只读的**：Vue 在开发模式下会警告（甚至报错），在生产模式下修改 props 的结果也不确定。
> 
> 4. **响应式系统的可靠性**：如果直接修改 props，Vue 的响应式系统可能会失效，导致视图不更新。
> 
> **两种正确做法的对比**：
> 
> | 场景 | 用法 | 适用情况 |
> |------|------|--------|
> | **需要本地状态** | 方式1：data 副本 | 组件有自己的业务逻辑，只是初始化时用 props 的值 |
> | **需要同步父组件** | 方式2：emit 事件 | 组件修改时需要立即反馈给父组件，保持数据同步 |
> 
> **实际例子**：
> 
> ❌ **错误做法**（直接修改）：
> ```javascript
> // 子组件直接修改 props
> methods: {
>     handleInput(value) {
>         this.username = value;  // 错！不要这样改 props
>     }
> }
> ```
> 
> ✅ **正确做法1**（本地副本）：
> ```javascript
> // 当 prop 只是"初始值"时，复制到 data
> data() {
>     return {
>         localUsername: this.username  // 复制一份
>     }
> },
> methods: {
>     handleInput(value) {
>         this.localUsername = value;  // 修改副本，不影响 props
>     }
> }
> ```
> 
> ✅ **正确做法2**（通知父组件）：
> ```javascript
> // 当需要父组件同时更新时，发送事件
> methods: {
>     handleInput(value) {
>         this.$emit('update:username', value);  // 通知父组件
>     }
> }
> ```
> 
> **总结**：Vue 的单向数据流是为了让应用更易于理解和维护。记住这个原则：**数据从上而下流动，事件从下而上传递**。

### 2.4 Props 传递技巧

```
<!-- 传递布尔值 -->
<my-component :is-active="true" />
<my-component is-active />  <!-- 等同于 :is-active="true" -->

<!-- 传递数字 -->
<my-component :count="42" />  <!-- 数字 -->
<my-component count="42" />   <!-- 字符串 "42" -->

<!-- 传递数组 -->
<my-component :items="['a', 'b', 'c']" />

<!-- 传递对象 -->
<my-component :user="{ name: '张三', age: 25 }" />

<!-- 传递对象所有属性 -->
<user-card v-bind="user" />
<!-- 等同于 -->
<user-card :name="user.name" :age="user.age" :email="user.email" />
```

> **补充说明**：
> 
> **关键区别：冒号 `:` 的作用**
> 
> - **不带冒号**（静态属性）：`prop="value"` → 传递**字符串字面量**
> - **带冒号**（动态绑定）：`:prop="value"` → 传递 **JavaScript 表达式的值**
> 
> **常见的 Props 传递场景**：
> 
> 1. **布尔值传递**
>    ```html
>    <!-- ❌ 错误：这会传递字符串 "false"，是真值 -->
>    <my-component is-active="false" />
>    
>    <!-- ✅ 正确：才能传递布尔值 false -->
>    <my-component :is-active="false" />
>    
>    <!-- ✅ 特殊：无属性值时默认为 true -->
>    <my-component is-active />  <!-- 等价于 :is-active="true" -->
>    ```
> 
> 2. **数字传递**
>    ```html
>    <!-- ❌ 错误：传递的是字符串 "42"，不是数字 42 -->
>    <my-component count="42" />
>    
>    <!-- ✅ 正确：传递数字类型 -->
>    <my-component :count="42" />
>    ```
>    
>    如果子组件期望数字类型而你传了字符串，会导致：
>    - 数学运算出错（`"42" + 1` = `"421"` 而非 `43`）
>    - 类型验证警告（如果设置了 `props: { count: Number }`）
> 
> 3. **数组和对象传递**
>    ```javascript
>    // 子组件
>    const MyComponent = {
>        props: ['items', 'user'],
>        template: `<div>{{ items }}, {{ user.name }}</div>`
>    };
>    ```
>    ```html
>    <!-- ✅ 必须使用 : 来传递数组和对象 -->
>    <my-component :items="['apple', 'banana']" />
>    <my-component :user="{ name: '张三', age: 25 }" />
>    ```
> 
> 4. **v-bind 简写（展开对象所有属性）**
>    ```javascript
>    // 父组件 data
>    data() {
>        return {
>            user: {
>                name: '张三',
>                age: 25,
>                email: 'zhangsan@example.com'
>            }
>        }
>    }
>    ```
>    ```html
>    <!-- 方式1：逐个传递 -->
>    <user-card 
>        :name="user.name" 
>        :age="user.age" 
>        :email="user.email" 
>    />
>    
>    <!-- 方式2：v-bind 展开（等价上面，但更简洁） -->
>    <user-card v-bind="user" />
>    ```
>    
>    这在需要传递多个相同结构的对象时特别有用。
> 
> **实际开发中的常见错误**：
> 
> | 错误写法 | 问题 | 正确写法 |
> |---------|------|--------|
> | `count="10"` | 传递字符串，不是数字 | `:count="10"` |
> | `is-active="false"` | "false" 字符串是真值 | `:is-active="false"` |
> | `items="[1,2,3]"` | 传递字符串，不是数组 | `:items="[1,2,3]"` |
> | `:disabled="'disabled'"` | 冗余，字符串总是真值 | `:disabled="true"` 或 `disabled` |
> 
> **技巧总结**：
> - 👉 **记住这个原则**：如果想传递任何非字符串的值（数字、布尔、数组、对象、变量等），**必须使用冒号 `:`**
> - 👉 **静态字符串除外**：只有纯字符串可以不用冒号，如 `title="我的组件"`
> - 👉 **当不确定时**：直接用冒号更安全，`:<prop>="value"` 总是可以的

## 3. Emit 子传父

### 3.1基本用法

> **前置知识说明**：Emit 是子组件向父组件通信的机制。子组件通过 `$emit()` 方法触发自定义事件，父组件通过 `@事件名`监这些事件。

```html
<script>
//子组件：ChildButton（子按钮）
const ChildButton = {
    //组件模板：包含一个按钮
    template: `
        <button @click="handleClick">
            <!-- @click 是 v-on:click 的简写 -->
            <!-- 点击按钮时调用 handleClick 方法 -->
           点击通知父组件
        </button>
    `,
    //组件方法
    methods: {
        handleClick() {
            console.log('子组件：按钮被点击');
            
            //触发自定义事件
            // $emit(事件名, 数据1, 数据2, ...)
            this.$emit('notify');
            
            //这行代码会：
            // 1. 在当前组件实例上触发 'notify' 事件
            // 2.中监听该事件的处理函数会被调用
        }
    }
};

//父组件
createApp({
    // 注册子组件
    components: { ChildButton },
    
    // 方法
    methods: {
        // 事件处理函数：当子组件触发 notify 事件时调用
        onNotify() {
            console.log('父组件：收到子组件的通知');
            alert('收到子组件的通知！');
        }
    }
}).mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <!-- 使用子组件并监听其事件 -->
    <child-button 
        @notify="onNotify"  <!-- @notify 是 v-on:notify 的简写 -->
    />
    
    <!-- 事件监听的工作流程：
         1. 用户点击按钮
         2.子组件的 handleClick 方法执行
         3. handleClick调用 this.$emit('notify')
         4.的 onNotify 方法被调用
    -->
</div>
```

> **补充说明**：
> 
> **什么是 `$emit()` ？**
> 
> `$emit()` 是 Vue 组件中内置的一个方法，用来**触发自定义事件**。它允许子组件主动向父组件"通知"或"传递"数据。
> 
> **`$emit()` 的语法**：
> ```javascript
> this.$emit('事件名');                    // 触发事件，不传数据
> this.$emit('事件名', 数据);             // 触发事件，传递一个数据
> this.$emit('事件名', 数据1, 数据2);     // 触发事件，传递多个数据
> ```
> 
> **核心概念理解**：
> 
> 1. **自定义事件 vs 原生事件**：
>    - **原生事件**（如 `click`、`input`、`change`）是 HTML 元素本身就有的事件
>    - **自定义事件**是你自己定义的事件名，由组件开发者决定什么时候触发
> 
> 2. **事件是组件间通信的桥梁**：
>    ```
>    子组件 $emit 事件
>         ↓
>    父组件 @事件名 监听
>         ↓
>    父组件方法执行
>    ```
> 
> **`$emit()` 工作流程详解**：
> 
> 以 3.1 中的 `ChildButton` 为例：
> 
> ```javascript
> // 第1步：子组件定义方法
> methods: {
>     handleClick() {
>         console.log('按钮被点击了');
>         // 第2步：子组件触发自定义事件 
>         this.$emit('notify');
>         //     ↑       ↑
>         //   固定写法  事件名（自己定义）
>     }
> }
> ```
> 
> ```html
> <!-- 第3步：父组件在模板中监听这个事件 -->
> <child-button 
>     @notify="onNotify"
>     <!--   ↑          ↑
>           事件名    处理函数
>     -->
> />
> 
> <!-- 第4步：当 notify 事件触发时，onNotify 方法被调用 -->
> ```
> 
> **一个完整的例子对比**：
> 
> ❌ **错误理解**（子组件直接操作父组件数据）：
> ```javascript
> // 子组件不应该这样做
> methods: {
>     handleClick() {
>         // 错！子组件无法直接访问或修改父组件的数据
>         // this.parentData.count++;  // 这样不行
>     }
> }
> ```
> 
> ✅ **正确做法**（通过 $emit 通知父组件）：
> ```javascript
> // 子组件
> methods: {
>     handleClick() {
>         // 触发一个自定义事件，告诉父组件"有事情发生了"
>         this.$emit('button-clicked');
>     }
> }
> ```
> 
> ```html
> <!-- 父组件 -->
> <child-button @button-clicked="onButtonClicked" />
> 
> <!-- 父组件中的方法 -->
> methods: {
>     onButtonClicked() {
>         // 收到子组件的通知后，父组件自己决定做什么
>         this.count++;
>     }
> }
> ```
> 
> **`$emit()` 的三个要素**：
> 
> | 要素 | 含义 | 例子 |
> |------|------|------|
> | **`$emit`** | 触发事件的内置方法 | 固定写法，不能改 |
> | **事件名** | 自定义的事件标识符 | `'notify'`、`'change'`、`'update'` 等 |
> | **数据**（可选） | 传递给父组件的信息 | `this.$emit('notify', data)` 中的 `data` |
> 
> **常见场景**：
> 
> 1. **通知父组件有事件发生**（不需要传数据）
>    ```javascript
>    this.$emit('notify');  // "嘿，父组件，我这里发生了什么事"
>    ```
> 
> 2. **向父组件传递数据**（需要传数据）
>    ```javascript
>    this.$emit('change', newValue);  // "父组件，数据变成这样了"
>    ```
> 
> 3. **传递多个数据**
>    ```javascript
>    this.$emit('user-action', userId, actionType);  // 传递多个参数
>    ```
> 
> **一个生活化类比**：
> 
> 想象 `$emit()` 就像**按铃**：
> - 👦 **子组件（小孩）**：你在房间里，想要告诉父亲某件事，所以按下铃
>   ```javascript
>   this.$emit('notify');  // 按铃，发出信号
>   ```
> - 👨 **父组件（父亲）**：在听到铃声后，执行相应的动作
>   ```html
>   @notify="handleNotify"  <!-- 听到"notify"信号，执行对应方法 -->
>   ```
> - 📢 **信息传递**：如果小孩还要告诉父亲具体发生了什么，可以在按铃时说出来
>   ```javascript
>   this.$emit('notify', 'I broke a cup');  // 按铃同时说出发生了什么
>   ```
> 
> **总结**：
> - `$emit()` 是子组件与父组件通信的重要工具
> - 它遵循"子通知父"的单向通信模式
> - 通过自定义事件名来标识不同的通信类型
> - 可以携带数据让父组件知道具体发生了什么
> 
> **事件通信的流程**：
> ```
> 用户操作 →子组件方法 → $emit触发事件 →事件处理函数
> ```
> 
> **事件命名规范**：
> - 使用 kebab-case：`@my-event`
> - 事件名应该描述发生的事情
> -常用动词：`click`, `change`, `input`, `submit`, `remove`
> 
> **事件参数传递**：
> ```javascript
> //子组件
> this.$emit('change', newValue, oldValue);
> 
> //父组件
> <my-component @change="handleChange(newValue, oldValue)" />
> 注意这个地方“(newValue, oldValue)”可以省去，Vue会自动按顺序赋值的
> ```


### 3.2传递数据

> **前置知识说明**：除了触发事件，子组件还可以通过 `$emit()`向组件传递数据。这使得父组件能够获取子组件的内部状态。

```html
<script>
//子组件：Counter（计数器）
const Counter = {
    //组件模板：包含两个按钮和一个显示区域
    template: `
        <div>
            <!--减按钮 -->
            <button @click="decrement">-</button>
            
            <!--显示当前计数值 -->
            <span>{{ count }}</span>
            
            <!--按钮 -->
            <button @click="increment">+</button>
        </div>
    `,
    //组件数据：维护内部计数状态
    data() {
        return {
            count: 0  //初始值为 0
        }
    },
    //组件方法：实现计数逻辑
    methods: {
        //计数
        increment() {
            this.count++;
            console.log('子组件计数增加到：', this.count);
            
            // 传递数据给父组件
            // $emit(事件名, 参数1, 参数2, ...)
            this.$emit('change', this.count);
        },
        //减计数
        decrement() {
            this.count--;
            console.log('子组件计数减少到：', this.count);
            
            //同样传递新值给父组件
            this.$emit('change', this.count);
        }
    }
};

//父组件
createApp({
    // 注册子组件
    components: { Counter },
    
    //父组件数据：存储从子组件接收的值
    data() {
        return {
            currentValue: 0  //初始值为 0
        }
    },
    //父组件方法
    methods: {
        //处理子组件传递的数据
        // newValue 参数接收子组件传递的计数值
        handleChange(newValue) {
            // 更新父组件的数据
            this.currentValue = newValue;
            console.log('父组件收到新值：', newValue);
            
            //可以在这里执行其他逻辑
            if (newValue > 10) {
                alert('计数超过10了！');
            }
        }
    }
}).mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <!-- 使用计数器组件并监听 change 事件 -->
    <counter @change="handleChange" />
    
    <!--显示父组件接收到的值 -->
    <p>父组件收到的值：{{ currentValue }}</p>
    
    <!-- 数据流说明：
         1. 用户点击 +/-按钮
         2.子组件的 increment/decrement 方法执行
         3.方法调用 this.$emit('change', this.count)
         4.父组件的 handleChange 方法接收新值
         5. handleChange 更新父组件的 currentValue
         6.模板中的 {{ currentValue }} 自动更新
    -->
</div>
```

> **补充说明**：
> 
> **数据传递的双向性**：
>数据数据流是单向的（父→子通过 props，子→父通过 events），但通过配合使用可以实现类似双向绑定的效果。
> 
> **事件参数的灵活性**：
> ```javascript
> // 可以传递多个参数
> this.$emit('user-action', userId, actionType, timestamp);
> 
> //可以传递复杂对象
> this.$emit('form-submit', { 
>   username: this.username, 
>   email: this.email 
> });
> ```
> 
> **最佳实践**：
> - 事件名使用过去式动词（如 change, submit, remove）
> - 传递的数据应该是子组件的当前状态
> -父组件负责决定如何处理接收到的数据

### 3.3 声明 emits（推荐）

> **前置知识说明**：在前面的例子中，我们直接用 `this.$emit()` 触发事件，并没有提前"声明"会触发哪些事件。Vue 3 推荐通过 `emits` 选项显式列出组件会触发的所有自定义事件，类似于用 `props` 声明接收哪些数据一样。

```javascript
const MyComponent = {
    // 显式声明要触发的事件
    emits: ['change', 'update', 'delete'],
    
    // 带验证的声明
    emits: {
        // 无验证
        click: null,
        
        // 带验证函数
        submit(payload) {
            if (payload.email && payload.password) {
                return true;
            }
            console.warn('Invalid submit payload!');
            return false;
        }
    },
    
    methods: {
        doSubmit() {
            this.$emit('submit', {
                email: 'test@example.com',
                password: '123456'
            });
        }
    }
};
```

> **补充说明**：
> 
> **为什么要声明 emits？**
> 
> 不声明 emits 虽然也能工作，但有以下缺点：
> - 如果自定义事件名与原生 HTML 事件同名（如 `click`、`input`），Vue 会同时触发两次，产生意外行为
> - 其他开发者看不出这个组件会触发哪些事件，可读性差
> 
> **深入理解："为什么会触发两次？"**
> 
> 这是 Vue 中一个很常见的坑。让我们用一个具体例子说明：
> 
> ❌ **不声明 emits 的问题**：
> 
> ```javascript
> // 子组件：MyButton（没有声明 emits）
> const MyButton = {
>     template: `<button @click="$emit('click')">点击</button>`
>     // 注意：这里没有 emits 选项
> };
> ```
> 
> ```html
> <!-- 父组件使用 -->
> <my-button @click="handleClick" />
> 
> <!-- 当用户点击按钮时会发生什么？ -->
> ```
> 
> **两次触发的原因**：
> 
> 1. **第一次**：子组件的原生 `<button>` 元素本身触发了 `click` 事件
>    ```
>    用户点击按钮
>         ↓
>    HTML button 元素的原生 click 事件触发
>         ↓
>    父组件监听到 click 事件 → handleClick 执行
>    ```
> 
> 2. **第二次**：子组件通过 `$emit('click')` 也触发了 `click` 事件
>    ```
>    $emit('click')
>         ↓
>    自定义 click 事件触发
>         ↓
>    父组件监听到 click 事件 → handleClick 再执行一次
>    ```
> 父组件写在自定义组件上的 @click，如果没声明 emits,会直接 “粘” 在子组件最外面那个标签上！子组件最外面是 button，所以就绑在 button 上
父组件写：
><my-button @click="handleClick" />
>Vue 看到子组件没声明 emits，就翻译成：
><button @click="handleClick">  <!-- 父组件的事件绑在这里！ -->
> 点击
></button>

> 结果：**handleClick 被执行了两次！** 😱
> 
> **完整流程图**：
> ```
> 用户点击 button
>     ↓
> ┌─────────────────────────────────┐
> │ 第一次触发：HTML原生click事件    │
> │ (自动产生，不需要显式触发)       │
> └─────────────────────────────────┘
>     ↓
> 父组件 @click="handleClick"
>     ↓
> handleClick 执行 【第一次】
>     ↓
> ┌─────────────────────────────────┐
> │ 第二次触发：$emit('click')      │
> │ (子组件显式触发)                 │
> └─────────────────────────────────┘
>     ↓
> 父组件 @click="handleClick"
>     ↓
> handleClick 执行 【第二次】
> ```
> 
> **为什么会这样？**
>  如果你不在子组件里写 emits: ['click']
> Vue 会把你组件上的 @click 当成【原生 DOM 事件】直接绑在子组件最外层元素上(该案例中的最外层元素就是button)！导致
>原生一次 + $emit 一次 = 触发两次！
> - HTML 的 `<button>` 元素本身就有 `click` 事件
> - 当你在模板中写 `<button @click="...">` 时，Vue 会自动监听原生 click 事件
> - 如果子组件又通过 `this.$emit('click')` 显式触发同名事件，就会"重复"触发
> - Vue 无法区分这是真正的原生事件还是自定义事件
> 
> **声明 emits 的解决方案**：
> 
> ✅ **正确做法**（声明 emits）：
> 
> ```javascript
> // 子组件：MyButton（声明了 emits）
> const MyButton = {
>     emits: ['click'],  // 明确声明会触发 click 事件
>     template: `<button @click="$emit('click')">点击</button>`
> };
> ```
> 
> 当你声明 `emits: ['click']` 后，Vue 就知道：
> - "你这里有一个自定义的 `click` 事件"
> - "我应该把 `<button>` 的原生 click 事件和你的自定义 click 事件合并处理"
> - "只触发一次，而不是两次"
> 
> 结果：**handleClick 只执行一次** ✅
> 
> **其他容易踩坑的事件名**：
> 
> | 原生事件 | 自定义事件冲突示例 | 后果 |
> |---------|------------------|------|
> | `click` | `@click="$emit('click')"` | 触发两次 |
> | `input` | `@input="$emit('input')"` | 触发两次 |
> | `change` | `@change="$emit('change')"` | 触发两次 |
> | `focus` | `@focus="$emit('focus')"` | 触发两次 |
> | `blur` | `@blur="$emit('blur')"` | 触发两次 |
> | `submit` | `@submit="$emit('submit')"` | 触发两次 |
> 
> **实际代码对比**：
> 
> ❌ **不声明 emits - 有bug**：
> ```javascript
> const MyButton = {
>     // 没有声明 emits
>     template: `
>         <button @click="handleClick">
>             点击我
>         </button>
>     `,
>     methods: {
>         handleClick() {
>             console.log('按钮被点击');
>             this.$emit('click', '按钮数据');  // 触发自定义 click
>         }
>     }
> };
> ```
> 使用时：
> ```html
> <my-button @click="parentClick" />
> <!-- 点击一次按钮，parentClick 会执行两次！ -->
> ```
> 
> ✅ **声明 emits - 正确**：
> ```javascript
> const MyButton = {
>     emits: ['click'],  // 声明 emits
>     template: `
>         <button @click="handleClick">
>             点击我
>         </button>
>     `,
>     methods: {
>         handleClick() {
>             console.log('按钮被点击');
>             this.$emit('click', '按钮数据');  // 触发自定义 click
>         }
>     }
> };
> ```
> 使用时：
> ```html
> <my-button @click="parentClick" />
> <!-- 点击一次按钮，parentClick 只执行一次！✅ -->
> ```
> 
> **两种声明形式**：
> 
> 1. **数组形式**（简单，只列出事件名）：
> ```javascript
> emits: ['change', 'update', 'delete']
> ```
> 
> 2. **对象形式**（带验证函数，验证传递的数据是否合法）：
> ```javascript
> emits: {
>     submit(payload) {
>         // 验证通过返回 true，否则返回 false 并在控制台警告
>         return payload.email && payload.password;
>     }
> }
> ```
> 
> **声明 emits 的好处**：
> - **避免冲突**：防止自定义事件与原生事件重名导致的双重触发问题
> - **文档作用**：一眼就能看出组件对外暴露了哪些事件接口
> - **数据校验**：对象形式可以在开发时验证传出数据的合法性，提前发现 bug
> - **IDE 支持**：编辑器能更好地提供代码提示
> 
> **最佳实践建议**：
> - 👉 **总是声明 emits**，即使事件名是自定义的，不与原生事件冲突
> - 👉 **避免使用原生事件名**作为自定义事件名（`click`、`input`、`change` 等）
> - 👉 **使用有意义的事件名**，如 `'user-action'`、`'data-changed'`、`'item-selected'` 等

### 3.4 实战示例：自定义输入组件

> **前置知识说明**：`v-model` 是 Vue 内置的双向绑定语法糖，用在原生 `<input>` 上时大家都很熟悉。但如果我们想让自己封装的组件也支持 `v-model`，就需要理解它的底层原理：
> 
> `v-model="username"` 本质上等价于：
> ```html
> :modelValue="username"  @update:modelValue="username = $event"
> ```
> 也就是说，父组件向子组件传一个名为 `modelValue` 的 prop，子组件修改时通过 `$emit('update:modelValue', 新值)` 通知父组件更新。只要子组件遵守这个约定，就能使用 `v-model`。
> 
> **深入理解 v-model 的工作原理**：
> 
> 1. **v-model 是语法糖**（简写形式）：
>    ```
>    v-model="username"  →  实际上是两个东西的组合
>    ├─ 其一：:modelValue="username"     (属性绑定，父→子传数据)
>    └─ 其二：@update:modelValue="..."   (事件监听，子→父传数据)
>    ```
> 
> 2. **标准的 v-model 约定**：
>    - **Prop 名称固定**：必须是 `modelValue`
>    - **事件名称固定**：必须是 `update:modelValue`
>    - 任何组件只要遵守这个约定，就能使用 `v-model`
> 
> **具体例子：拆解 v-model 的两个步骤**
> 
> 假设你有一个自定义输入框组件，这样写：
> 
> ❌ **手动写法**（很啰嗦）：
> ```html
> <custom-input 
>     :modelValue="username"
>     @update:modelValue="username = $event"
> />
> ```
> 
> ✅ **使用 v-model 简写**（清爽多了）：
> ```html
> <custom-input v-model="username" />
> ```
> 
> 这两种写法**完全等价**！但 v-model 大大简化了代码。
> 
> **分步骤理解 v-model 的数据流向**：
> 
> **步骤1：父组件向子组件传递初始值**
> ```
> 父组件的 data:
>     username: '张三'
>         ↓
> :modelValue="username"  (属性绑定)
>         ↓
> 子组件接收 prop:
>     props: ['modelValue']
>         ↓
> 子组件能访问：
>     this.modelValue  // 值为 '张三'
> ```
> 
> **步骤2：子组件响应用户输入，通知父组件更新**
> ```
> 用户在输入框输入：'李四'
>         ↓
> @input 事件触发
>         ↓
> $emit('update:modelValue', '李四')  (事件发出)
>         ↓
> 父组件监听事件：
>     @update:modelValue="username = $event"
>         ↓
> 父组件数据更新：
>     username = '李四'
>         ↓
> 步骤1再次执行，数据同步给子组件
> ```
> 
> **为什么需要这样设计？**
> 
> 这样做的目的是实现**双向绑定**：
> - 👉 **数据从父到子**：父组件的数据变化 → 子组件立即更新显示
> - 👉 **数据从子到父**：子组件的数据变化 → 通知父组件更新自己的数据
> 
> 结果：**父子组件的数据始终保持同步**
> 
> **一个完整的生活化类比**：
> 
> 想象你和朋友共享一个便签本：
> - 你（父组件）在便签本上写下：`username: '张三'`
> - 你把便签本给朋友（传递 prop）：`:modelValue="username"`
> - 朋友（子组件）看到了，在 input 框里显示："张三"
> - 朋友改写了："李四"
> - 朋友告诉你他改的内容（触发事件）：`@update:modelValue="李四"`
> - 你听到后，把自己的便签改成了："李四"
> - 你又把最新的便签给朋友看...
> 
> 这个过程一直循环下去，两个人的便签内容始终一致。
> 
> **对比：不使用 v-model 需要手动写很多代码**：
> 
> ❌ **不使用 v-model 时**（代码冗长）：
> ```html
> <!-- 父组件需要手动绑定和监听 -->
> <custom-input 
>     :inputValue="username"
>     @change-input="handleInputChange"
> />
> 
> methods: {
>     handleInputChange(newValue) {
>         this.username = newValue;
>     }
> }
> ```
> 
> ✅ **使用 v-model 时**（代码简洁）：
> ```html
> <!-- 只需一行！ -->
> <custom-input v-model="username" />
> ```
> 
> 可以看出，v-model 大大简化了双向绑定的代码。
> 
> **v-model 的关键要点总结**：
> 
> | 概念 | 说明 | 代码 |
> |------|------|------|
> | **Prop名** | 接收父数据 | `props: ['modelValue']` |
> | **事件名** | 通知父更新 | `emits: ['update:modelValue']` |
> | **绑定值** | 显示在组件里 | `:value="modelValue"` |
> | **触发事件** | 用户输入时发出 | `@input="$emit('update:modelValue', $event.target.value)"` |
> 
> **记住这个规则**：只要子组件有 `modelValue` prop 和 `update:modelValue` 事件，父组件就可以使用 `v-model` 与之绑定，自动实现双向数据同步。

```html
<script>
// 自定义输入组件
const CustomInput = {
    props: ['modelValue'],  // 接收 v-model 的值
    emits: ['update:modelValue'],  // 声明事件
    template: `
        <input 
            :value="modelValue"
            @input="$emit('update:modelValue', $event.target.value)"
            class="custom-input"
        />
    `
};

createApp({
    components: { CustomInput },
    data() {
        return {
            username: ''
        }
    }
}).mount('#app');
</script>

<div id="app">
    <!-- 使用 v-model 绑定自定义组件 -->
    <custom-input v-model="username" />

    <!-- 这种写法等价于上面这种写法 -->
    <custom-input
    :modelValue="username"
    @update:modelValue="username = $event"
    />

    <p>输入的用户名：{{ username }}</p>
</div>
```

> **补充说明**：
> 
> **深入理解 `username = $event` 这行代码**：
> 
> 这一句出现在 v-model 的完整写法中：
> ```html
> @update:modelValue="username = $event"
> ```
> 
> 让我们拆解这句话的含义：
> 
> 1. **`@update:modelValue`** - 事件监听
>    - 这是对子组件发出的 `update:modelValue` 事件的监听
>    - 每当子组件触发这个事件时，后面的代码就会执行
> 
> 2. **`$event`** - 特殊变量
>    - `$event` 是 Vue 中的特殊关键字
>    - 它代表**事件被触发时传递过来的数据**
>    - 具体来说，就是子组件通过 `$emit()` 发送的那个值
> 
> 3. **`username = $event`** - 赋值操作
>    - 这是一个简单的赋值语句
>    - 把 `$event` 的值赋给父组件的 `username` 数据
> 
> **完整的事件数据流向**：
> 
> ```
> 用户输入："李四"
>     ↓
> input 元素的 @input 事件触发
>     ↓
> $event.target.value 获取输入框的值："李四"
>     ↓
> 子组件执行：
>     this.$emit('update:modelValue', '李四')
>                                    ↑
>                            发送这个值给父组件
>     ↓
> 父组件接收到事件：@update:modelValue="..."
>     ↓
> $event 在这里就是那个被发送的值："李四"
>     ↓
> 父组件执行：username = $event
>           即：username = '李四'
>     ↓
> 父组件的 username 数据更新成了"李四"
> ```
> 
> **一个具体的代码对比例子**：
> 
> ❌ **不使用 v-model（手动写）**：
> ```html
> <!-- 父组件模板 -->
> <custom-input 
>     :inputValue="username"
>     @change-input="handleInputChange"
> />
> 
> <!-- 父组件脚本 -->
> methods: {
>     handleInputChange(newValue) {
>         this.username = newValue;  // 手动赋值
>     }
> }
> ```
> 
> 工作流程：
> - 子组件触发事件：`this.$emit('change-input', '李四')`
> - 父组件监听事件：`@change-input="handleInputChange"`
> - 事件处理函数执行：`handleInputChange('李四')`
> - 函数内部：`this.username = newValue` （即 `this.username = '李四'`）
> 
> ✅ **使用 v-model（简写）**：
> ```html
> <!-- 父组件模板 -->
> <custom-input v-model="username" />
> 
> <!-- 自动展开为：-->
> <custom-input 
>     :modelValue="username"
>     @update:modelValue="username = $event"
> />
> ```
> 
> 工作流程完全相同，但代码更简洁。
> 
> **$event 详细讲解**：
> 
> `$event` 的具体值取决于被触发的事件类型：
> 
> | 事件类型 | `$event` 代表什么 | 例子 |
> |---------|-----------------|------|
> | 原生 DOM 事件 | 事件对象本身 | `@click="handleClick($event)"` → `$event` 是 `MouseEvent` |
> | 自定义事件 | 通过 `$emit` 发送的值 | `@update:modelValue="username = $event"` → `$event` 是发送的数据 |
> | input 事件 | 事件对象 | `@input="value = $event.target.value"` → `$event` 是 `InputEvent` |
> 
> **在 v-model 中，`$event` 特别说明**：
> 
> 当子组件这样写：
> ```javascript
> this.$emit('update:modelValue', newValue)
> //                             ^^^^^^^^
> //                          这个值就会变成 $event
> ```
> 
> 父组件这样接收：
> ```html
> @update:modelValue="username = $event"
> //                           ^^^^^^
> //                    $event 就是 newValue
> ```
> 
> **完整的三步循环**：
> 
> **第一步**：初始化
> ```javascript
> // 父组件 data
> data() {
>     return {
>         username: ''  // 初始为空
>     }
> }
> ```
> 
> **第二步**：子组件接收父数据并显示
> ```html
> <!-- 子组件通过 :modelValue="username" 接收 -->
> <input :value="username" />  <!-- 显示空值 -->
> ```
> 
> **第三步**：用户输入，数据反向传递
> ```
> 用户在输入框输入："李四"
>         ↓
> 子组件的 @input 事件触发
>         ↓
> this.$emit('update:modelValue', '李四')
>         ↓
> 父组件的 @update:modelValue="username = $event" 监听到
>         ↓
> $event = '李四'（子组件发送的值）
>         ↓
> username = '李四'（父组件数据更新）
>         ↓
> 重回第二步，子组件显示新数据
> ```
> 
> **记住这个模式**：
> ```
> 子组件：this.$emit('事件名', 发送的值)
>               ↓
> 父组件：@事件名="变量 = $event"
>                           ↑ $event 就是发送的值
> ```
> 
> 逐行解读代码**：
> ```javascript
> props: ['modelValue']           // 1. 接收父组件通过 v-model 传入的值
> emits: ['update:modelValue']    // 2. 声明要触发的事件（固定格式）
> 
> :value="modelValue"             // 3. 把接收到的值绑定到 input 的 value 属性
> @input="$emit('update:modelValue', $event.target.value)"
>                                 // 4. 用户输入时，把新值通知给父组件
> ```
> 
> **数据流向图**：
> ```
> 父组件 username ──(modelValue prop)──▶ 子组件 input 显示
> 父组件 username ◀──(update:modelValue)── 子组件 用户输入
> ```
> 
> **为什么要自定义输入组件？**
> - 统一样式：整个项目的输入框外观一致，只需修改一处
> - 内置功能：可以在组件内封装验证、格式化、字数统计等逻辑
> - 简化使用：父组件只需 `v-model` 一行，不关心内部细节
> 
> **`$event.target.value` 是什么？**
> - `$event` 是原生 DOM 事件对象
> - `$event.target` 是触发事件的元素（即 input 标签本身）
> - `$event.target.value` 就是用户当前输入框里的文字

## 4. 插槽 Slot

### 4.1默认插槽

> **前置知识说明**：插槽（Slot）是 Vue 组件中实现内容分发的机制。它允许父组件向子组件传递 HTML内容，实现组件的灵活定制。

```html
<script>
//子组件：MyCard（卡片组件）
const MyCard = {
    //组件模板：定义卡片的基本结构
    template: `
        <div class="card">
            <!--卡的装饰性样式 -->
            <div class="card-body">
                <!--插槽出口：内容占位符 -->
                <!--的内容会在这里显示 -->
                <slot>
                    <!-- 默认内容：当父组件没有提供内容时显示 -->
                    默认内容（当没有传入内容时显示）
                </slot>
            </div>
        </div>
    `
    //插槽的工作原理：
    // 1.子定义 <slot> 作为内容出口
    // 2.父在组件标签内部放置内容
    // 3. Vue将父组件的内容插入到 <slot> 的位置
};

// 创建应用并注册组件
createApp({
    components: { MyCard }
}).mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <!-- 使用1：传入自定义内容 -->
    <my-card>
        <!--这些内容会替换子组件中的 <slot> -->
        <h3>卡片标题</h3>
        <p>这是卡片内容</p>
        <button>操作按钮</button>
    </my-card>
    
    <!-- 使用2：不传入内容，显示默认内容 -->
    <my-card></my-card>
    <!--渲结果：
    <div class="card">
        <div class="card-body">
            默认内容（当没有传入内容时显示）
        </div>
    </div>
    -->
</div>
```

> **补充说明**：
> 
> **插槽的核心概念**：
> - **内容分发**：将父组件的内容分发到子组件的指定位置
> - **占位符机制**：`<slot>` 是内容的占位符
> - **作用域**：插入的内容在父组件的作用域中编译
> 
> **`<my-card>` 和 `MyCard` 是怎么关联上的？**
> 
> 1. 先在 JS 中定义组件对象：`const MyCard = { template: ... }`
> 2. 再在应用里注册：`createApp({ components: { MyCard } }).mount('#app')`
> 3. Vue 在解析模板时，会把组件名 `MyCard` 自动转换成 kebab-case 标签名 `<my-card>`
> 4. 所以，只要在 `components` 里注册了 `MyCard`，就可以在模板中写 `<my-card>...</my-card>` 来使用这个组件
> 
> 换句话说：**JS 里用 `MyCard` 这个变量名注册组件，模板里就可以用 `<my-card>` 这个自定义标签来用它**。
> 
> **“父组件的内容”指的是什么？**
> 
> 以示例中的代码为例：
> ```html
> <my-card>
>   <h3>卡片标题</h3>
>   <p>这是卡片内容</p>
>   <button>操作按钮</button>
> </my-card>
> ```
> 这些写在 `<my-card>...</my-card>` 标签内部的 `<h3>`、`<p>`、`<button>`，就是**父组件的内容**。
> 渲染时，Vue 会把这部分内容整体替换到子组件模板里的 `<slot>` 位置：
> ```html
> <!-- 子组件模板片段 -->
> <div class="card-body">
>   <slot>
>     默认内容（当没有传入内容时显示）
>   </slot>
> </div>
> ```
> 
> 情况总结：
> - 如果父组件写了：`<my-card>...自定义内容...</my-card>` → 这些内容会塞进 `<slot>` 里显示
> - 如果父组件写了：`<my-card></my-card>`（里面什么都不写） → 显示 `<slot>` 标签内的**默认内容**

#### 实战示例：父组件传入内容 vs 默认内容

以本章节开头的 `my-button` 组件为例：

```js
// 子组件定义
app.component('my-button', {
    template: `
        <button class="my-btn">
            <slot>默认按钮</slot>
        </button>
    `
});
```

**情况一**：父组件传入内容
```html
<my-button>点击我</my-button>
```
渲染结果是：
```html
<button class="my-btn">点击我</button>
```
→ **显示"点击我"**，因为父组件传入的内容会**替换**掉 `<slot>` 标签

**情况二**：父组件没有传入内容
```html
<my-button></my-button>
```
渲染结果是：
```html
<button class="my-btn">默认按钮</button>
```
→ **显示"默认按钮"**，因为没有内容传入时，显示 `<slot>` 标签内的默认值

> **核心原理**：`<slot>` 只是一个"占位符"，父组件传入的内容会**替换**这个占位符，而不是显示在它旁边。默认值只在"没有父组件内容"时才显示。

**插槽的使用场景**：
> - 卡片、面板等容器组件
> - 按钮、表单项等需要自定义内容的组件
> - 布局组件（如页面布局、模态框）

**插槽 vs Props 的区别**：
> | 特性 | Props | Slot |
> |------|-------|------|
> | 传递内容 | 数据 | HTML 结构 |
> | 编译作用域 | 子 | 父 |
> | 适用场景 | 配置数据 | 内容定制 |

### 4.2 具名插槽

```html
<script>
const PageLayout = {
    template: `
        <div class="page-layout">
            <header>
                <slot name="header">默认头部</slot>
            </header>
            
            <main>
                <slot>默认内容</slot>
            </main>
            
            <footer>
                <slot name="footer">默认底部</slot>
            </footer>
        </div>
    `
};

createApp({
    components: { PageLayout }
}).mount('#app');
</script>

<div id="app">
    <page-layout>
        <!-- 使用 v-slot 指定插槽 -->
        <template v-slot:header>
            <h1>网站标题</h1>
            <nav>导航菜单</nav>
        </template>
        
        <!-- 默认插槽内容 -->
        <p>页面主要内容</p>
        <p>更多内容...</p>
        
        <!-- 简写形式 # -->
        <template #footer>
            <p>版权信息 © 2024</p>
        </template>
    </page-layout>
</div>
```

> **前置知识说明**：具名插槽用于在一个组件中定义**多个命名插槽出口**，父组件可以根据名字把不同的内容插入到不同的位置。
>
> **示例拆解**：
> - 子组件里：`<slot name="header">默认头部</slot>` 定义了一个名为 `header` 的插槽，并提供默认内容；`<slot>默认内容</slot>` 是默认插槽
> - 父组件里：`<template v-slot:header>...</template>` 或简写 `<template #header>...</template>` 表示“这些内容塞到 header 插槽”
> - 没有写名字的插槽（`<slot>`）对应父组件中不带 `v-slot` 的那部分内容
>
> **使用步骤总结**：
> 1. 在子组件中用 `<slot name="xxx">` 定义具名插槽
> 2. 在父组件中用 `<template v-slot:xxx>` 或 `<template #xxx>` 指定要插入该插槽的 DOM 结构
> 3. Vue 渲染时，根据 `name` 把对应 `<template>` 内的内容放到子组件模板中相同名字的 `<slot>` 位置
>
> **适用场景**：
> - 页面布局：头部 / 主体 / 底部
> - 卡片组件：标题 / 内容 / 底部操作区
> - 需要在一个组件中灵活插入多块不同内容的场景

### 4.3 作用域插槽

作用域插槽让父组件可以访问子组件的数据。

```html
<script>
const UserList = {
    template: `
        <ul>
            <li v-for="user in users" :key="user.id">
                <!-- 将 user 数据传递给插槽 -->
                <slot :user="user" :index="index">
                    {{ user.name }}  <!-- 默认显示 -->
                </slot>
            </li>
        </ul>
    `,
    data() {
        return {
            users: [
                { id: 1, name: '张三', role: 'admin' },
                { id: 2, name: '李四', role: 'user' },
                { id: 3, name: '王五', role: 'editor' }
            ]
        }
    }
};

createApp({
    components: { UserList }
}).mount('#app');
</script>

<div id="app">
    <!-- 使用作用域插槽获取子组件数据 -->
    <user-list>
        <template v-slot:default="slotProps">
            <span class="user-name">{{ slotProps.user.name }}</span>
            <span class="user-role">({{ slotProps.user.role }})</span>
        </template>
    </user-list>
    
    <!-- 解构写法 -->
    <user-list>
        <template #default="{ user }">
            <strong>{{ user.name }}</strong> - {{ user.role }}
        </template>
    </user-list>
</div>
```

> **前置知识说明**：作用域插槽的特点是**数据在子组件，渲染样式由父组件决定**。子组件通过在 `<slot>` 上绑定属性，把内部数据“暴露”给父组件使用。
>
> **示例拆解**：
> - 子组件中：`<slot :user="user" :index="index">` 相当于给插槽传了一个对象 `{ user, index }`
> - 父组件中：`<template v-slot:default="slotProps">` 声明一个参数 `slotProps`，通过 `slotProps.user` 就能拿到子组件传出的 `user`
> - 解构写法：`<template #default="{ user }">` 等价于从 `slotProps` 中解构出 `user`
>
> **数据流向**：
> - 列表数据 `users` 存在子组件 `UserList` 里（父组件不需要关心获取数据的细节）
> - 子组件遍历 users 时，把当前这一项 `user` 通过插槽参数传给父组件
> - 父组件根据 `user` 自己决定这一行怎么展示（只显示名字 / 显示名字+角色 / 加图标等）
>
> **适用场景**：
> - 列表、表格等“数据来源固定，但展示样式经常变化”的场景
> - 封装通用列表组件，由业务方（父组件）通过作用域插槽来自定义每一行的样式
>
> **结合示例：一步步看 v-for 和 v-slot:default**：
> 
> 1. **子组件里的 v-for**
>    ```html
>    <li v-for="user in users" :key="user.id">
>      <slot :user="user" :index="index">
>        {{ user.name }}
>      </slot>
>    </li>
>    ```
>    - `v-for="user in users"`：从 `users` 数组中一条一条取出用户对象，当前这条就叫 `user`
>    - `:key="user.id"`：给每一条记录一个唯一 key，方便 Vue 高效更新 DOM
>    - `<slot :user="user" :index="index">`：把当前这一条 `user`（以及索引 `index`）通过插槽参数传给父组件
>
> 2. **父组件里的 v-slot:default**
>    ```html
>    <user-list>
>      <template v-slot:default="slotProps">
>        <span class="user-name">{{ slotProps.user.name }}</span>
>        <span class="user-role">({{ slotProps.user.role }})</span>
>      </template>
>    </user-list>
>    ```
>    - `v-slot:default="slotProps"`：接收子组件传来的插槽参数对象，起名为 `slotProps`
>    - `slotProps.user`：就是子组件通过 `<slot :user="user">` 传出的那条用户数据
>    - 于是父组件可以自由决定这一条 `user` 要显示哪些字段、以什么样式显示
>
> 3. **解构写法再简化一步**
>    ```html
>    <user-list>
>      <template #default="{ user }">
>        <strong>{{ user.name }}</strong> - {{ user.role }}
>      </template>
>    </user-list>
>    ```
>    - `#default="{ user }"` 等价于 `v-slot:default="slotProps"` 再从中解构 `user`
>    - 所以模板里可以直接写 `user`，不用每次写 `slotProps.user`
>
> 可以这样理解：**v-for 负责“挨个拿出数据”，v-slot:default 负责“把这条数据交给父组件决定怎么渲染”**。

### 4.4 插槽实战：可复用表格组件

```html
<script>
const DataTable = {
    props: ['data', 'columns'],
    template: `
        <table class="data-table">
            <thead>
                <tr>
                    <th v-for="col in columns" :key="col.key">
                        {{ col.title }}
                    </th>
                </tr>
            </thead>
            <tbody>
                <tr v-for="(row, index) in data" :key="index">
                    <td v-for="col in columns" :key="col.key">
                        <!-- 作用域插槽：允许自定义每列的显示 -->
                        <slot :name="col.key" :row="row" :value="row[col.key]">
                            {{ row[col.key] }}
                        </slot>
                    </td>
                </tr>
            </tbody>
        </table>
    `
};

createApp({
    components: { DataTable },
    data() {
        return {
            columns: [
                { key: 'name', title: '姓名' },
                { key: 'age', title: '年龄' },
                { key: 'status', title: '状态' },
                { key: 'action', title: '操作' }
            ],
            users: [
                { name: '张三', age: 25, status: 'active' },
                { name: '李四', age: 30, status: 'inactive' }
            ]
        }
    },
    methods: {
        editUser(user) {
            alert('编辑：' + user.name);
        }
    }
}).mount('#app');
</script>

<div id="app">
    <data-table :data="users" :columns="columns">
        <!-- 自定义状态列 -->
        <template #status="{ value }">
            <span :class="value === 'active' ? 'badge-success' : 'badge-danger'">
                {{ value === 'active' ? '激活' : '禁用' }}
            </span>
        </template>
        
        <!-- 自定义操作列 -->
        <template #action="{ row }">
            <button @click="editUser(row)">编辑</button>
        </template>
    </data-table>
</div>
```

> **补充说明**：
> 
> **DataTable 组件的核心设计**：
> 
> 这个表格组件展示了如何通过**作用域插槽**来实现一个高度可复用的数据展示组件。关键特点是：
> - 数据逻辑和行为由子组件（DataTable）负责
> - 样式和显示由父组件通过插槽来定制
> 
> **代码逐行解读**：
> 
> 1. **组件 Props 声明**
> ```javascript
> props: ['data', 'columns']
> ```
> - `data`：要显示的数据数组，每个元素代表一行
> - `columns`：列配置数组，每个对象包含 `key`（数据字段名）和 `title`（显示的列标题）
> 
> 2. **表头生成**
> ```html
> <thead>
>     <tr>
>         <th v-for="col in columns" :key="col.key">
>             {{ col.title }}
>         </th>
>     </tr>
> </thead>
> ```
> 根据 `columns` 数组动态生成表头，每列的标题来自 `col.title`
> 
> 3. **表体双层循环**
> ```html
> <tbody>
>     <tr v-for="(row, index) in data" :key="index">
>         <td v-for="col in columns" :key="col.key">
>             ...
>         </td>
>     </tr>
> </tbody>
> ```
> - 外层 `v-for`：遍历每一行数据
> - 内层 `v-for`：遍历每一列配置
> - 结果：生成 `data.length × columns.length` 个单元格
> 
> 4. **作用域插槽的魔力**
> ```html
> <slot :name="col.key" :row="row" :value="row[col.key]">
>     {{ row[col.key] }}
> </slot>
> ```
> - `:name="col.key"`：每个列都有一个对应的具名插槽（如 `name`、`age`、`status`、`action`）
> - `:row="row"` 和 `:value="row[col.key]"`：把行数据和单元格值传给父组件
> - 默认内容 `{{ row[col.key] }}`：如果父组件没有自定义该列，就显示原始值
> 
> **父组件如何使用**：
> 
> ```html
> <data-table :data="users" :columns="columns">
>     <!-- 自定义状态列 -->
>     <template #status="{ value }">
>         <span :class="value === 'active' ? 'badge-success' : 'badge-danger'">
>             {{ value === 'active' ? '激活' : '禁用' }}
>         </span>
>     </template>
>     
>     <!-- 自定义操作列 -->
>     <template #action="{ row }">
>         <button @click="editUser(row)">编辑</button>
>     </template>
> </data-table>
> ```
> 
> - `#status="{ value }"`：针对"状态"列，只使用 `value` 数据，自定义渲染为带颜色的徽章
> - `#action="{ row }"`：针对"操作"列，使用整行数据 `row`，自定义渲染为按钮，并绑定点击事件
> 
> **数据流向分析**：
> 
> ```
> 第一步：父组件传入数据
>     users: [
>         { name: '张三', age: 25, status: 'active' },
>         { name: '李四', age: 30, status: 'inactive' }
>     ]
>         ↓
> 第二步：DataTable 子组件接收
>     props: ['data']  →  this.data = users
>         ↓
> 第三步：子组件循环渲染
>     v-for="(row, index) in data"
>         ↓
>     第一行：row = { name: '张三', age: 25, status: 'active' }
>     第二行：row = { name: '李四', age: 30, status: 'inactive' }
>         ↓
> 第四步：通过作用域插槽传给父组件
>     <slot :name="'status'" :row="row" :value="'active'">
>         ↓
> 第五步：父组件接收并自定义渲染
>     <template #status="{ value }">
>         value = 'active'
>         →显示为绿色徽章"激活"
> ```
> 
> **这个设计的优势**：
> 
> | 优势 | 说明 |
> |------|------|
> | **高度复用** | 同一个 DataTable 组件可以显示任意数据结构，只需调整 `columns` 配置 |
> | **灵活定制** | 不同列可以有不同的显示方式（文本、颜色、按钮等），由父组件决定 |
> | **逻辑分离** | 子组件专注数据和结构，父组件专注样式和交互 |
> | **易于扩展** | 需要新增列时，只需在 `columns` 中新增配置和对应的插槽 |
> | **维护成本低** | 改进表格逻辑时只需改子组件，不影响使用者 |
> 
> **实际应用场景**：
> 
> 这种设计模式广泛应用于：
> - 📊 **管理后台**：用户列表、订单列表等
> - 📈 **数据展示**：报表、统计数据表格
> - 🎯 **CMS系统**：内容管理的表格视图
> - 📱 **移动应用**：任何需要展示列表数据的地方
> 
> **变种用法**：如果你想要更简洁的写法，也可以这样用
> 
> ```javascript
> // 在 columns 中直接定义 render 函数
> columns: [
>     { key: 'name', title: '姓名' },
>     { 
>         key: 'status', 
>         title: '状态',
>         // 定义如何渲染这一列
>         render: (value) => value === 'active' ? '激活' : '禁用'
>     }
> ]
> ```
> 
> 但用插槽的方式更灵活，因为它不仅能改文字，还能改 HTML 结构和样式。
> 
> **总结**：
> 
> 4.4 这个例子完美展示了 Vue 插槽的威力——通过将"显示方式"委托给父组件，让组件具备了"一次开发，到处可用"的能力。这是构建高效企业级应用的关键。

## 5. 计算属性 computed

### 5.1基本用法

> **前置知识说明**：计算属性是 Vue 中处理复杂逻辑和派生数据的重要工具。它基于响应式依赖进行缓存，只有依赖变化时才会重新计算。

```html
<script>
createApp({
    //组件数据：原始数据
    data() {
        return {
            firstName: '张',      //名
            lastName: '三',       //姓
            items: [              //商品列表
                { name: '苹果', price: 10, quantity: 2 },
                { name: '香蕉', price: 5, quantity: 3 }
            ]
        }
    },
    //计算属性：基于数据计算得出的属性
    computed: {
        //计算属性：全名
        // 当 firstName 或 lastName变化时自动重新计算
        fullName() {
            console.log('计算 fullName');  // 只有依赖变化时才执行
            return this.firstName + this.lastName;
        },
        
        //计算属性：总价
        // 计算所有商品的总价格
        totalPrice() {
            // 使用数组的 reduce 方法累加总价
            return this.items.reduce((sum, item) => {
                return sum + item.price * item.quantity;
            }, 0);
        },
        
        // 计算属性：商品数量
        // 返回商品列表的长度
        itemCount() {
            return this.items.length;
        }
    }
}).mount('#app');
</script>

<!-- HTML 模板 -->
<div id="app">
    <p>全名：{{ fullName }}</p>
    <p>再次显示：{{ fullName }}</p>  <!-- 不会重新计算，使用缓存 -->
    <p>总价：¥{{ totalPrice }}</p>
    <p>商品数：{{ itemCount }}</p>
    
    <!--计算属性的工作原理：
         1. Vue 会追踪计算属性的依赖（firstName, lastName等）
         2.只有当依赖发生变化时，计算属性才会重新执行
         3.果依赖未变化，直接返回缓存的结果
    -->
</div>
```

> **补充说明**：
>
> **为什么要用计算属性而不是在模板里直接写表达式？**
> - 模板越“干净”，越容易阅读和维护。把复杂逻辑放进 `computed`，模板只负责“展示结果”。
> - 同一段逻辑可能会在多个地方用到，只写一份计算属性即可重复使用，避免复制粘贴。
> - 模板中的复杂表达式每次渲染都会重新执行，而计算属性有缓存，性能更好。
>
> **通过上面例子理解“缓存”：**
> - 模板里有两次 `{{ fullName }}`，但当 `firstName`、`lastName` 都没变时，`fullName()` 实际只会执行一次。
> - 你可以通过 `console.log('计算 fullName')` 看到这一点：无论模板里用了几次，只要依赖没变，就不会重复打印。
> - 当你修改 `firstName` 或 `lastName` 时，下一次访问 `fullName` 才会重新计算。
>
> **计算属性的核心特性**：
> - **响应式**：依赖数据变化时自动更新
> - **缓存性**：依赖未变化时使用缓存结果，提高性能
> - **声明式**：你只需要“声明”结果和依赖的关系，而不需要在各处手动调用函数更新
>
> **常见使用场景**：
> - 对原始数据做**格式化**：价格加货币符号、时间格式化、字符串拼接等
> - 从数组中计算**合计值 / 统计值**：总价、总数量、完成任务数、未读消息数等
> - 对列表做**过滤和排序**：根据搜索条件、筛选条件、排序规则等，返回新的列表
> - 计算**状态类布尔值**：如 `isLogin`、`hasError`、`isDisabled`，方便模板里直接用

> 📌 **项目实战：Pinia Store 中 computed 的实际应用**
>
> 在 SyncHealth 项目中，计算属性主要出现在 Pinia Store 中。以 `stores/auth.ts` 为例：
>
> `const isAuthenticated = computed(() => !!accessToken.value)` 将"是否已登录"封装为一个计算属性。`!!accessToken.value` 使用双重取反将 token 字符串转换为布尔值：非空 → `true`，空字符串 → `false`。这个计算属性被多处引用——路由守卫 `router.beforeEach` 中用它判断是否允许访问需要登录的页面，侧边栏 `AppLayout.vue` 中用 `v-if="authStore.user"`（user 也是响应式 ref）控制用户信息的显示。每次访问 `isAuthenticated` 时都是从缓存读取，只有 `accessToken` 变化时（登录/退出）才重新计算。
>
> `stores/dashboard.ts` 中的 `summary`、`trends` 虽为普通 `ref` 而非 `computed`，但作为 Store state 被 `DashboardView.vue` 共享消费。页面上 `v-if="dashboardStore.summary"` 和 `v-if="dashboardStore.trends"` 分别控制指标卡片区和图表区的渲染——数据由 Store 统一管理，多个条件渲染节点消费同一份数据，不需要 Props 层层传递。

### 5.2 computed vs methods

```
createApp({
    data() {
        return {
            count: 0
        }
    },
    computed: {
        // 计算属性：有缓存
        doubleCount() {
            console.log('computed 执行');
            return this.count * 2;
        }
    },
    methods: {
        // 方法：每次调用都执行
        getDoubleCount() {
            console.log('method 执行');
            return this.count * 2;
        }
    }
});
```

```
<!-- 模板中多次使用 -->
<p>{{ doubleCount }}</p>  <!-- 只计算一次 -->
<p>{{ doubleCount }}</p>  <!-- 使用缓存 -->
<p>{{ doubleCount }}</p>  <!-- 使用缓存 -->

<p>{{ getDoubleCount() }}</p>  <!-- 执行一次 -->
<p>{{ getDoubleCount() }}</p>  <!-- 又执行一次 -->
<p>{{ getDoubleCount() }}</p>  <!-- 又执行一次 -->
```

**选择原则**：
- 需要缓存 → 用 `computed`
- 需要传参 → 用 `methods`
- 依赖响应式数据 → 用 `computed`
- 事件处理 → 用 `methods`

### 5.3 可写的计算属性

```
createApp({
    data() {
        return {
            firstName: '张',
            lastName: '三'
        }
    },
    computed: {
        fullName: {
            // getter
            get() {
                return this.firstName + this.lastName;
            },
            // setter
            set(newValue) {
                // 假设格式为 "姓名"
                this.firstName = newValue[0];
                this.lastName = newValue.slice(1);
            }
        }
    }
});
```

```
<input v-model="fullName" />
<!-- 输入 "李四" 会自动拆分为 firstName="李", lastName="四" -->
```

### 5.4 计算属性实战

```javascript
// 创建应用
createApp({
    // 原始数据：搜索词、筛选状态、待办列表
    data() {
        return {
            // 搜索关键字，用于按文本过滤
            searchQuery: '',
            // 当前筛选状态：all / active / completed
            filterStatus: 'all',
            // 待办事项列表
            todos: [
                { id: 1, text: '学习 Vue', completed: true },   // 已完成
                { id: 2, text: '写项目', completed: false },    // 未完成
                { id: 3, text: '复习笔记', completed: false }  // 未完成
            ]
        }
    },
    computed: {
        // 过滤后的待办列表
        // 根据 filterStatus 和 searchQuery 动态计算出要显示的 todos
        filteredTodos() {
            // 先从完整列表开始
            let result = this.todos;
            
            // 第一步：按状态过滤
            // this.filterStatus 可以是：
            // - 'all'：显示全部
            // - 'active'：只显示未完成的任务
            // - 'completed'：只显示已完成的任务
            if (this.filterStatus === 'active') {
                // 未完成：completed 为 false
                result = result.filter(t => !t.completed);
            } else if (this.filterStatus === 'completed') {
                // 已完成：completed 为 true
                result = result.filter(t => t.completed);
            }
            
            // 第二步：按搜索关键字过滤
            // 当 searchQuery 不为空时，再按文本内容筛一遍
            if (this.searchQuery) {
                // includes：判断文本中是否包含搜索关键字
                result = result.filter(t => 
                    t.text.includes(this.searchQuery)
                );
            }
            
            // 返回最终结果
            return result;
        },
        
        // 统计信息
        // 通过 todos 计算出：总数、已完成数、未完成数
        stats() {
            return {
                // 总任务数
                total: this.todos.length,
                // 已完成任务数
                completed: this.todos.filter(t => t.completed).length,
                // 未完成任务数
                active: this.todos.filter(t => !t.completed).length
            };
        }
    }
});
```

> **补充说明**：
>
> **这个例子想说明什么？**
> - 实际项目中，我们经常需要根据**多个条件**（状态 + 搜索词）来筛选列表。
> - 如果把这些逻辑都写在模板或者 methods 里，会又长又乱，而且很难复用。
> - 用计算属性 `filteredTodos` 和 `stats`，可以把“列表怎么显示”相关的逻辑集中起来，模板只管拿结果来用。
>
> **filteredTodos 的执行步骤**（可以对照代码看）：
> 1. 先拿到完整的 `this.todos` 列表赋值给 `result`。
> 2. 根据 `filterStatus` 先做一轮过滤：
>    - `'all'`：不动 `result`，保留全部；
>    - `'active'`：只保留 `completed === false` 的任务；
>    - `'completed'`：只保留 `completed === true` 的任务。
> 3. 如果 `searchQuery` 不为空，再做第二轮过滤，只保留 `text` 中包含关键字的任务。
> 4. 最后返回过滤后的 `result`，模板里用 `v-for="todo in filteredTodos"` 就能直接展示。
>
> **stats 计算属性的意义**：
> - `total`：总任务数，等于 `todos.length`。
> - `completed`：已完成任务数，通过 `filter(t => t.completed)` 计算出来。
> - `active`：未完成任务数，通过 `filter(t => !t.completed)` 计算出来。
> - 这样一来，模板里可以直接写：`stats.total`、`stats.completed`、`stats.active`，而不用每次在模板里写复杂表达式。
>
> **这个例子里，computed 帮你做了两件事**：
> - 把“列表筛选逻辑”封装在 `filteredTodos` 里，只要依赖（todos / filterStatus / searchQuery）不变，多次使用都不会重复计算。
> - 把“统计数字的计算”封装在 `stats` 里，模板只管拿现成结果用，既清晰又易于维护。

## 6. 侦听器 watch

### 6.1基本用法

> **前置知识说明**：侦听器用于监听响应式数据的变化，并在变化时执行相应的副作用操作。它特别适合处理异步操作和复杂的数据变化逻辑。

```javascript
createApp({
    //组件数据
    data() {
        return {
            question: '',         //用户输入的问题
            answer: '请输入问题...'  //的回答
        }
    },
    //侦听器：监听数据变化
    watch: {
        //侦听 question 的变化
        // newValue: 新值，oldValue: 旧值
        question(newValue, oldValue) {
            console.log('问题从', oldValue, '变为', newValue);
            
            //条件判断：当问题包含问号时才回答
            if (newValue.includes('?')) {
                this.getAnswer();
            }
        }
    },
    //组件方法
    methods: {
        //异步方法：获取答案
        async getAnswer() {
            // 更新状态：显示加载中
            this.answer = '思考中...';
            
            //模拟 API 调用（实际项目中这里是真实的 HTTP 请求）
            setTimeout(() => {
                //模拟异步响应
                this.answer = '这是一个好问题！';
            }, 1000);
        }
    }
});
```

> **补充说明**：
> 
> **侦听器的核心特性**：
> - **响应式监听**：数据变化时自动触发
> - **支持异步**：可以在侦听器中执行异步操作
> - **访问新旧值**：可以获取变化前后的值进行比较
> - **灵活配置**：支持深度监听、立即执行等选项
> 
> **这个示例中 watch 的监听目标和参数含义**：
> - `watch: { question(...) { ... } }` 中的 `question`，对应的是 `data()` 里同名的 `question` 字段，监听的是 `this.question` 的变化。
> - 侦听函数形参按顺序始终是「新值、旧值」，常用命名是 `newValue, oldValue`，也可以用其他名字，比如 `now, before`，只要位置不变即可。
> 
> **使用场景**：
> - API 调用（搜索、数据获取）
> -表单验证
> -变化处理
> - 复杂的状态同步
> 
> **侦听器 vs计算属性**：
> |特性 |计算属性 | 侦听器 |
> |------|----------|-------|
> | 用途 |计算派生值 |响应数据变化执行操作 |
> | 返回值 |必须有返回值 | 不需要返回值 |
> |缓存 | 有缓存 | 无缓存 |
> |异步 | 不支持异步 |支持异步操作 |
> |场 |模板中显示计算结果 | API 调用、复杂逻辑 |

> 📌 **项目实战：`AIChatView.vue` 中的 watch 侦听器应用**
>
> AI 对话页面使用了两个 `watch` 来监听消息变化，自动滚动聊天窗口到底部：
>
> 第一个 `watch(() => aiStore.messages.length, () => nextTick(scrollToBottom))` 监听消息数组长度的变化。这里只侦听 `messages.length`（数组长度）而非整个 `messages` 数组，原因是当用户发送消息时，`sendMessage` 会 push 两条新消息，长度从 N 变为 N+2，触发一次滚动即可。如果改成 `deep: true` 的深度监听，每次 WebSocket 推送 token 修改消息内容时也会触发，导致不必要的频繁 DOM 操作。
>
> 第二个 watch 专为流式输出设计：`watch(() => { const msgs = aiStore.messages; return msgs.length ? msgs[msgs.length - 1].content.length : 0 }, () => nextTick(scrollToBottom))`。它侦听的是最后一条消息的 `content.length`——当 AI 通过 WebSocket 逐步返回 token 时，消息内容的字符数持续增长，每次增长都触发滚动。这实现了"AI 打字时自动跟随"的体验。两个 watch 用 `nextTick` 确保 DOM 更新完成后再执行滚动，覆盖了"新消息到来"和"内容增长"两种场景。

### 6.2深度侦听

> **前置知识说明**：当需要监听对象或数组内部属性的变化时，需要使用深度侦听。默认情况下，侦听器只监听引用的变化。

```javascript
createApp({
    //组件数据：包含嵌套对象
    data() {
        return {
            user: {
                name: '张三',
                profile: {
                    age: 25,
                    city: '北京'
                }
            }
        }
    },
    //侦听器配置
    watch: {
        //侦听嵌套属性（默认只侦听引用变化）
        user: {
            //处理函数
            handler(newValue, oldValue) {
                console.log('user 对象引用变化了');
                console.log('新值:', newValue);
                console.log('旧值:', oldValue);
            },
            //开启深度侦听：监听对象内部所有属性的变化
            deep: true
        },
        
        //直接侦听嵌套路径（推荐方式）
        'user.profile.age'(newValue, oldValue) {
            console.log('年龄从', oldValue, '变为', newValue);
            //可以在这里执行年龄变化的特定逻辑
            if (newValue >= 18) {
                console.log('用户已成年');
            }
        },
        
        //侦听多个嵌套属性
        'user.profile': {
            handler(newProfile, oldProfile) {
                console.log('用户档案发生变化');
            },
            deep: true  //需要深度监听
        }
    }
});
```

> **补充说明**：
> 
> **deep: true 实际会做什么？**
> - 默认情况下只监听 `user` 这个引用本身是否被替换，例如整对象赋新值 `this.user = {...}` 时才会触发，内部属性变化（如 `user.profile.age++`）不会触发。
> - 加上 `deep: true` 后，Vue 会递归地跟踪 `user` 内部所有嵌套属性（包括数组元素、子对象等），只要任意一层属性发生变化，这个侦听器都会触发。
> - `deep: true` 并不是“帮你对比整个对象”，它只是保证内部属性的变更也能被监听到，真正要做什么逻辑仍然由你在 `handler` 中决定。
> 
> **多个属性一起变化时会怎样？**
> - 在一个方法里一次性修改 `user.profile.age` 和 `user.profile.city`，对于加了 `deep: true` 的 `user` 侦听器来说，表现为“本次 user 对象发生了变化”，回调通常只会在这一轮更新中触发一次，`newValue` 是修改后的完整 `user` 对象，`oldValue` 是修改前的完整快照。
> - 如果你同时还写了 `'user.profile.age'` 这种精确路径的侦听器，那么修改 age 时，既会触发深度侦听的 `user` 回调，也会触发专门监听 age 的那个回调，各自拿到各自的新旧值。
> - 实际开发中，可以利用这一点：深度侦听用来处理“整体变化”的逻辑，路径侦听用来针对某个字段做更细粒度的处理。
> 
> **深度侦听的性能考虑**：
> -深侦听会遍历对象的所有属性，性能开销较大
> - 对于大型对象，建议只侦听具体的路径
> - 可以使用 `Vue.set()` 或 `this.$set()`确保新属性是响应式的

### 6.3立即执行

> **前置知识说明**：有时希望在组件初始化时就执行一次侦听器，这时可以使用 `immediate: true` 选项。

```javascript
createApp({
    //组件数据
    data() {
        return {
            searchQuery: 'vue'  //初始搜索词
        }
    },
    //侦听器配置
    watch: {
        //配置对象形式的侦听器
        searchQuery: {
            //处理函数
            handler(newValue) {
                console.log('搜索词:', newValue);
                //执行搜索逻辑
                this.doSearch(newValue);
            },
            //立即执行：创建时立即调用一次
            immediate: true
        }
    },
    //组件方法
    methods: {
        doSearch(query) {
            console.log('执行搜索:', query);
            // 实际的搜索逻辑
        }
    }
});
```

> **使用场景**：
> -组件初始化时需要根据初始数据执行操作
> -需要立即响应默认值的变化
> -表单组件的初始验证

### 6.4 侦听器的选项

```
createApp({
    data() {
        return {
            count: 0,
            user: {
                name: '张三',
                age: 25
            }
        }
    },
    watch: {
        // 配置对象形式的侦听器
        count: {
            handler(newValue, oldValue) {
                console.log('count 变化了');
            },
            // 深度监听：监听对象内部属性的变化
            deep: true,
            // 立即执行：创建时立即调用一次
            immediate: true
        },
        // 直接侦听嵌套路径
        'user.name'(newValue, oldValue) {
            console.log('用户名变化了');
        }
    }
});
```

> **补充说明**：
> 
> **什么时候用对象写法？**
> - 当你需要同时配置 `handler`、`deep`、`immediate` 等选项时，就用对象形式来写侦听器。
> - 如果只是简单监听一个字段、也不需要深度/立即执行，直接写成 `count(newValue, oldValue) { ... }` 这种函数简写就够用了。
> 
> **6.4 示例要点回顾**：
> - `count` 的侦听使用了对象写法，所以可以同时打开 `deep` 和 `immediate`；在这个示例里 `count` 是数字，`deep: true` 实际不会带来额外效果，主要是演示语法用法。
> - `'user.name'` 这样的写法属于“路径侦听”，只在 `user.name` 改变时触发，不会因为 `user.age` 等其他属性改变而触发。
> - 实际项目中可以组合使用：对整个对象做一个通用侦听，对某些关键字段再单独写路径侦听，方便拆分不同的处理逻辑。

### 6.5 侦听器实战：防抖搜索

```javascript
createApp({
    data() {
        return {
            searchQuery: '',
            searchResults: [],
            isLoading: false
        }
    },
    watch: {
        searchQuery(newQuery) {
            //清除之前的定时器
            clearTimeout(this.debounceTimer);
            
            if (!newQuery) {
                this.searchResults = [];
                return;
            }
            
            this.isLoading = true;
            
            //：300ms后执行搜索
            this.debounceTimer = setTimeout(() => {
                this.performSearch(newQuery);
            }, 300);
        }
    },
    methods: {
        async performSearch(query) {
            try {
                // 模拟 API调用
                const response = await fetch(`/api/search?q=${query}`);
                this.searchResults = await response.json();
            } catch (error) {
                console.error('搜索失败:', error);
            } finally {
                this.isLoading = false;
            }
        }
    }
});
```

> **补充说明**：
> 
> **为什么要配合防抖使用侦听器？**
> - 直接在 `searchQuery` 每次变化时就立刻发请求，会导致用户快速输入时触发大量无用请求，增加服务器压力、也浪费浏览器资源。
> - 通过在侦听器里结合 `setTimeout` 和 `clearTimeout`，可以实现“防抖”：只有用户停止输入超过 300ms 之后才真正发起一次搜索请求。
> 
> **6.5 示例要点回顾**：
> - 每次输入触发侦听器时，先 `clearTimeout` 清掉上一次尚未执行的定时器，保证只保留最后一次输入对应的搜索任务。
> - 当输入为空字符串时，直接清空 `searchResults` 并返回，避免发出没有意义的搜索请求。
> - `isLoading` 用来标记当前是否在“搜索中”，可以用在界面上展示加载状态（例如显示一个 loading 动画）。
> - `performSearch` 中用 `try / catch / finally` 结构处理异步请求的成功、失败和结束三种状态，是在侦听器里处理异步 API 的常见写法。

### 第2阶段核心概念速查表

| 概念 | 用途 | 关键点 |
|------|------|--------|
| **组件** | 代码复用和组织 | `components` 注册，独立的作用域 |
| **Props** |子传数据 |单向数据流，可验证类型，只读性 |
| **Emit** |子→父传数据 | `$emit('事件名', 数据)`，事件驱动通信 |
| **默认插槽** | 传递内容 | `<slot>默认内容</slot>`，内容分发 |
| **具名插槽** |多个插槽 | `<slot name="xxx">`，精确内容定位 |
| **作用域插槽** |子传数据给插槽 | `<slot :data="xxx">`，数据暴露给父组件 |
| **computed** |计算派生值 | 有缓存，依赖变化才重算，声明式编程 |
| **watch** |响应数据变化 |支持异步，深度监听，副作用处理 |

###组件通信方式汇总

```
父 →子：Props（传递数据）
子 →父Emit（触发事件）
父 ↔子：v-model（Props + Emit 语法糖）
内容传递：插槽（Slot）
数据暴露：作用域插槽
```

###常问题解答

**Q: 什么时候用 computed，什么时候用 watch？**
A:需要计算派生值时用 computed，需要响应变化执行副作用时用 watch

**Q: Props 可以在子组件中修改吗？**
A: 不应该直接修改，应该通过 emit 通知父组件修改，或在 data 中创建副本

**Q:插槽和 Props 有什么区别？**
A: Props 传递数据，插槽传递 HTML 结构；Props 在子组件作用域编译，插槽在父组件作用域编译

**Q:全局组件和局部组件如何选择？**
A: 通用基础组件用全局注册，业务组件用局部注册
