# 📘 第3阶段：工程化开发详解

> 本文档详细讲解 Vue 3 的工程化开发，包括 Vite 项目创建、Vue Router 路由和 Pinia 状态管理

## 🎯 前置知识：什么是工程化开发？

### 为什么需要工程化？

在前两个阶段，我们使用 CDN 方式学习 Vue，这种方式适合学习，但在实际项目开发中有很多限制：

```
CDN 方式的局限：
┌────────────────────────────────────────────────────────┐
│  ❌ 无法使用单文件组件（.vue 文件）                      │
│  ❌ 无法使用 npm 生态的海量第三方库                      │
│  ❌ 无法使用 ES6+ 模块化语法                            │
│  ❌ 无法进行代码压缩、打包优化                           │
│  ❌ 无法使用 TypeScript                                 │
│  ❌ 无法实现热更新（修改代码自动刷新）                    │
│  ❌ 无法进行代码分割、懒加载                             │
└────────────────────────────────────────────────────────┘
```

**工程化开发**就是使用专业的开发工具和规范，让我们能够高效地开发大型项目。

### 什么是构建工具？

**构建工具**是帮助我们自动化处理代码的工具，它可以：

```
构建工具的作用：
┌─────────────────────────────────────────────────────────┐
│                      源代码                              │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐   │
│  │  .vue   │  │  .ts    │  │  .scss  │  │  .png   │   │
│  │  文件   │  │  文件   │  │  文件   │  │  图片   │   │
│  └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘   │
│       │            │            │            │         │
│       └────────────┴────────────┴────────────┘         │
│                         │                               │
│                         ▼                               │
│                  ┌─────────────┐                        │
│                  │  构建工具    │                        │
│                  │ (Vite/Webpack)│                       │
│                  └──────┬──────┘                        │
│                         │                               │
│       ┌─────────────────┼─────────────────┐            │
│       ▼                 ▼                 ▼            │
│  ┌─────────┐      ┌─────────┐      ┌─────────┐        │
│  │  .js    │      │  .css   │      │ 优化的   │        │
│  │  文件   │      │  文件   │      │  图片   │        │
│  └─────────┘      └─────────┘      └─────────┘        │
│                                                         │
│                    浏览器可直接运行                       │
└─────────────────────────────────────────────────────────┘
```

**通俗理解**：
- 源代码像是"食材"（各种格式的文件）
- 构建工具像是"厨师"
- 最终产出的是浏览器能"吃"的"菜"（标准的 HTML/CSS/JS）

### Vite vs Webpack

Vue 生态中有两个主流构建工具：

| 特性 | Vite | Webpack |
|------|------|---------|
| 启动速度 | ⚡ 极快（毫秒级） | 🐢 较慢（秒级） |
| 热更新速度 | ⚡ 极快 | 🐢 较慢 |
| 配置复杂度 | 简单 | 复杂 |
| 学习曲线 | 平缓 | 陡峭 |
| 生态成熟度 | 快速发展中 | 非常成熟 |
| Vue 官方推荐 | ✅ 推荐 | 仍支持 |

**为什么 Vite 这么快？**

```
Webpack 的工作方式（打包后启动）：
┌────────────────────────────────────────────────┐
│  启动开发服务器                                  │
│       │                                         │
│       ▼                                         │
│  扫描所有文件 ──→ 打包成 bundle ──→ 启动服务器   │
│  （可能有几千个）   （需要等待）     （终于可以访问）│
│                                                 │
│  时间：几秒到几十秒                              │
└────────────────────────────────────────────────┘

Vite 的工作方式（按需编译）：
┌────────────────────────────────────────────────┐
│  启动开发服务器                                  │
│       │                                         │
│       ▼                                         │
│  直接启动服务器 ──→ 浏览器请求哪个文件就编译哪个  │
│  （几乎瞬间）       （按需编译，超级快）          │
│                                                 │
│  时间：毫秒级                                    │
└────────────────────────────────────────────────┘
```

**本文档使用 Vite 作为构建工具**，因为它是 Vue 官方推荐的，而且学习曲线更平缓。

## 1. Vite + Vue 项目创建

### 1.1 环境准备

在创建项目之前，需要确保你的电脑已经安装了 Node.js。

#### 1.1.1 什么是 Node.js？

**Node.js** 是一个让 JavaScript 可以在浏览器之外运行的环境。

```
传统 JavaScript：
┌─────────────┐
│   浏览器    │ ← JavaScript 只能在这里运行
└─────────────┘

有了 Node.js：
┌─────────────┐     ┌─────────────┐
│   浏览器    │     │  Node.js    │ ← JavaScript 也能在这里运行
└─────────────┘     └─────────────┘
                          │
                          ▼
                    可以做更多事情：
                    - 运行开发工具
                    - 操作文件系统
                    - 搭建服务器
                    - 使用 npm 包管理器
```

**通俗理解**：Node.js 就像是给 JavaScript 配了一台"独立电脑"，让它可以脱离浏览器干活。

#### 1.1.2 什么是 npm？

**npm**（Node Package Manager）是 Node.js 的包管理器，用来：

1. **下载别人写好的代码**（称为"包"或"依赖"）
2. **管理项目的依赖版本**
3. **运行项目脚本**

```
npm 的作用示例：
┌────────────────────────────────────────────────────┐
│  你想用 Vue Router 路由功能                         │
│       │                                            │
│       ▼                                            │
│  npm install vue-router                            │
│       │                                            │
│       ▼                                            │
│  npm 自动从网上下载 vue-router 代码到你的项目       │
│       │                                            │
│       ▼                                            │
│  你就可以在项目中使用 vue-router 了                 │
└────────────────────────────────────────────────────┘
```

**通俗理解**：npm 就像是一个"代码超市"，你需要什么功能，就去"买"（下载）对应的包。

#### 1.1.3 检查 Node.js 是否已安装

打开命令行（Windows 用 PowerShell 或 CMD，Mac 用终端），输入：

```bash
# 检查 Node.js 版本
node -v

# 检查 npm 版本
npm -v
```

**正常输出示例**：
```
v18.17.0    # Node.js 版本（需要 16.0 以上）
9.6.7       # npm 版本
```

**如果提示"不是内部或外部命令"**，说明没有安装，需要去 [Node.js 官网](https://nodejs.org/) 下载安装。

#### 1.1.4 安装 Node.js（如果未安装）

1. 访问 https://nodejs.org/
2. 下载 **LTS 版本**（长期支持版，更稳定）
3. 双击安装包，一路"下一步"即可
4. 安装完成后，重新打开命令行，验证安装

```bash
# 再次检查
node -v
npm -v
```

### 1.2 创建 Vue 项目

#### 1.2.1 使用 npm create 创建项目

打开命令行，进入你想存放项目的目录，然后执行：

```bash
# 创建 Vue 项目（推荐方式）
npm create vue@latest
```

**命令解释**：
- `npm create`：npm 的创建项目命令
- `vue@latest`：使用最新版本的 Vue 项目模板

#### 1.2.2 创建过程详解

执行命令后，会出现一系列交互式问题，下面逐一解释：

```bash
# 问题1：项目名称

# 输入你的项目名称（只能用小写字母、数字、连字符）
# 这个名称会成为项目文件夹的名字

# 问题2：是否使用 TypeScript？
✔ Add TypeScript? › No / Yes

# 初学者建议选 No，熟悉后再学习 TypeScript

# 问题3：是否使用 JSX？
✔ Add JSX Support? › No / Yes
# JSX 是一种在 JavaScript 中写 HTML 的语法
# Vue 一般用模板语法，建议选 No

# 问题4：是否添加 Vue Router？
✔ Add Vue Router for Single Page Application development? › No / Yes
# Vue Router 是路由管理工具，用于页面跳转
# 建议选 Yes，我们后面会学习它

# 问题5：是否添加 Pinia？
✔ Add Pinia for state management? › No / Yes
# Pinia 是状态管理工具，用于多组件共享数据
# 建议选 Yes，我们后面会学习它

# 问题6：是否添加 Vitest？
✔ Add Vitest for Unit Testing? › No / Yes
# Vitest 是单元测试工具
# 初学者建议选 No

# 问题7：是否添加端到端测试？
✔ Add an End-to-End Testing Solution? › No
```

**初学者推荐配置**：

### 1.3 常用 npm 命令

在工程化开发中，你会频繁使用这些命令：

```bash
# 安装所有依赖（首次下载项目或 package.json 变化后执行）
npm install
# 简写：npm i

# 安装某个依赖包
npm install 包名
# 例如：npm install axios
# 简写：npm i axios

# 安装开发依赖（只在开发时需要，不会打包到最终产物）
npm install 包名 --save-dev
# 简写：npm i 包名 -D
# 例如：npm i sass -D

# 卸载依赖
npm uninstall 包名
# 例如：npm uninstall axios

# 运行脚本
npm run 脚本名
# 例如：npm run dev（启动开发服务器）
# 例如：npm run build（打包生产版本）
# 例如：npm run preview（预览打包结果）

# 查看已安装的依赖
npm list
# 只看顶层依赖：npm list --depth=0
```

**依赖 vs 开发依赖**：

```
┌─────────────────────────────────────────────────────┐
│  依赖（dependencies）                                │
│  ├── 项目运行必需的包                                │
│  ├── 会被打包到最终产物中                            │
│  └── 例如：vue、vue-router、pinia、axios            │
│                                                      │
│  开发依赖（devDependencies）                         │
│  ├── 只在开发时需要的包                              │
│  ├── 不会被打包到最终产物中                          │
│  └── 例如：vite、eslint、prettier、sass             │
└─────────────────────────────────────────────────────┘
```

### 1.4 热更新（Hot Module Replacement）

Vite 提供了强大的热更新功能，让你的开发体验极其流畅。

#### 1.4.1 什么是热更新？

**热更新**是指：修改代码后，浏览器自动更新显示，**不需要手动刷新页面**。

```
传统开发流程：
修改代码 → 保存 → 手动刷新浏览器 → 等待加载 → 查看效果
（每次修改都要重复这个过程，非常繁琐）

热更新开发流程：
修改代码 → 保存 → 浏览器自动更新显示效果
（几乎是瞬间完成，开发效率大幅提升）
```

#### 1.4.2 热更新的神奇之处

Vite 的热更新不仅快，还能**保持应用状态**：

```
场景：你正在开发一个表单页面
      用户已经填写了一些内容
      你修改了表单的样式代码

普通刷新：
页面刷新 → 用户填写的内容丢失 → 需要重新填写测试

热更新：
样式更新 → 用户填写的内容保留 → 继续测试
```

#### 1.4.3 体验热更新

1. 确保开发服务器正在运行（`npm run dev`）
2. 打开 `src/App.vue` 文件
3. 修改任意内容，例如改个标题文字
4. 保存文件（Ctrl+S）
5. 观察浏览器，内容已经自动更新了！

## 2. 项目结构详解

创建项目后，会生成以下文件和文件夹：

```
my-vue-app/
├── node_modules/          # 依赖包目录
├── public/                # 静态资源目录
│   └── favicon.ico        # 网站图标
├── src/                   # 源代码目录（最重要！）
│   ├── assets/            # 资源文件
│   │   └── logo.svg       # Logo 图片
│   ├── components/        # 组件目录
│   │   └── HelloWorld.vue # 示例组件
│   ├── router/            # 路由配置（如果选了 Vue Router）
│   │   └── index.js       # 路由配置文件
│   ├── stores/            # 状态管理（如果选了 Pinia）
│   │   └── counter.js     # 示例 store
│   ├── views/             # 页面组件
│   │   ├── HomeView.vue   # 首页
│   │   └── AboutView.vue  # 关于页
│   ├── App.vue            # 根组件
│   └── main.js            # 入口文件
├── .eslintrc.cjs          # ESLint 配置
├── .prettierrc.json       # Prettier 配置
├── index.html             # HTML 模板
├── package.json           # 项目配置文件
├── vite.config.js         # Vite 配置文件
└── README.md              # 项目说明
```

下面我们逐一详细解释每个文件和目录的作用。

### 2.1 核心文件详解

#### 2.1.1 index.html - HTML 模板

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <link rel="icon" href="/favicon.ico">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Vite App</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

**逐行解释**：

```html
<!DOCTYPE html>
<!-- 声明这是 HTML5 文档 -->

<html lang="en">
<!-- html 标签，lang="en" 表示页面语言是英文 -->
<!-- 如果你的网站是中文的，建议改成 lang="zh-CN" -->

<head>
<!-- head 标签包含页面的元信息，不直接显示在页面上 -->

    <meta charset="UTF-8">
    <!-- 设置字符编码为 UTF-8，确保中文正常显示 -->

    <link rel="icon" href="/favicon.ico">
    <!-- 设置网站图标（浏览器标签页上的小图标） -->
    <!-- href="/favicon.ico" 指向 public 目录下的 favicon.ico 文件 -->

    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <!-- 视口设置，确保在移动设备上正确显示 -->
    <!-- width=device-width：宽度等于设备宽度 -->
    <!-- initial-scale=1.0：初始缩放比例为 1 -->

    <title>Vite App</title>
    <!-- 页面标题，显示在浏览器标签页上 -->
    <!-- 你可以改成你的项目名称 -->

</head>

<body>
<!-- body 标签包含页面的可见内容 -->

    <div id="app"></div>
    <!-- 这是 Vue 应用的挂载点！！！ -->
    <!-- Vue 会把整个应用渲染到这个 div 里面 -->
    <!-- id="app" 是约定俗成的命名，和 main.js 中的 mount('#app') 对应 -->

    <script type="module" src="/src/main.js"></script>
    <!-- 引入 JavaScript 入口文件 -->
    <!-- type="module" 表示这是 ES 模块，支持 import/export 语法 -->
    <!-- src="/src/main.js" 指向源码目录下的 main.js -->

</body>
</html>
```

**工作流程图**：

```
浏览器加载流程：
┌─────────────────────────────────────────────────────┐
│  1. 浏览器请求 index.html                            │
│       │                                              │
│       ▼                                              │
│  2. 浏览器解析 HTML，看到 <script src="main.js">     │
│       │                                              │
│       ▼                                              │
│  3. 浏览器请求 main.js                               │
│       │                                              │
│       ▼                                              │
│  4. main.js 创建 Vue 应用并挂载到 #app               │
│       │                                              │
│       ▼                                              │
│  5. Vue 接管 <div id="app"></div>，渲染组件内容      │
└─────────────────────────────────────────────────────┘
```

#### 2.1.2 ES6 模块化基础（重要前置知识）

在学习 `main.js` 之前，你需要先理解 **ES6 模块化**，这是现代 JavaScript 开发的基础。

##### 什么是模块化？

**模块化**就是把代码拆分成多个文件，每个文件负责一个功能。

```
没有模块化时：
┌─────────────────────────────────┐
│  一个巨大的 JS 文件              │
│  （几千行代码混在一起）          │
│  - 难以维护                      │
│  - 容易冲突                      │
│  - 无法复用                      │
└─────────────────────────────────┘

使用模块化后：
┌──────────┐  ┌──────────┐  ┌──────────┐
│ user.js  │  │ cart.js  │  │ utils.js │
│ 用户功能  │  │ 购物车    │  │ 工具函数  │
└──────────┘  └──────────┘  └──────────┘
     │              │              │
     └──────────────┼──────────────┘
                    ▼
              ┌──────────┐
              │ main.js  │
              │ 主程序    │
              └──────────┘
```

##### import - 引入代码

**`import` = 引入别人写好的代码/功能**

```javascript
// 从 vue 这个包中，引入 createApp 函数
import { createApp } from 'vue'

// 从当前目录的 App.vue 文件中，引入默认导出的内容
import App from './App.vue'

// 从工具文件中引入多个函数
import { formatDate, formatMoney } from './utils.js'
```

**类比理解**：
- `import` 就像"借用"别人的工具
- 想用螺丝刀？从工具箱（其他文件）里拿出来用

##### export - 导出代码

**`export` = 把当前文件的代码暴露出去，让别的文件能引用**

有两种导出方式：

**1. 命名导出（Named Export）**：

```javascript
// utils.js
// 用 export 导出，可以导出多个
export function formatDate(date) {
  return date.toLocaleDateString()
}

export function formatMoney(amount) {
  return '¥' + amount.toFixed(2)
}

export const PI = 3.14159
```

```javascript
// 引入时必须用 { } 包裹，名字必须一致
import { formatDate, formatMoney, PI } from './utils.js'
```

**2. 默认导出（Default Export）**：

```javascript
// MyComponent.vue
// 每个文件只能有一个默认导出
export default {
  name: 'MyComponent',
  data() {
    return { message: 'Hello' }
  }
}
```

```javascript
// 引入时不需要 { }，可以取任意名字
import MyComponent from './MyComponent.vue'
import Abc from './MyComponent.vue'  // 也可以叫别的名字
```

##### export default 在 Vue 组件中的含义

**`export default` = 把当前这个文件，暴露成一个 Vue 组件**

```vue
<!-- MyButton.vue -->
<template>
  <button class="my-btn">{{ text }}</button>
</template>

<script>
// 这里的 export default 告诉 Vue：
// "这个文件导出的是一个 Vue 组件对象"
export default {
  name: 'MyButton',      // 组件名称
  props: ['text'],       // 接收的属性
  data() {               // 组件数据
    return { count: 0 }
  },
  methods: {             // 组件方法
    handleClick() { }
  }
}
</script>

<style>
.my-btn { color: blue; }
</style>
```

```javascript
// 在其他文件中引入这个组件
import MyButton from './MyButton.vue'

// 然后就可以使用了
// <MyButton text="点击我" />
```

##### Vue 3 的 `<script setup>` 简化写法

Vue 3 推出了 `<script setup>` 语法糖，**不需要写 export default** 了：

```vue
<!-- 传统写法 -->
<script>
export default {
  data() {
    return { count: 0 }
  },
  methods: {
    increment() {
      this.count++
    }
  }
}
</script>

<!-- script setup 简化写法（推荐） -->
<script setup>
import { ref } from 'vue'

const count = ref(0)

function increment() {
  count.value++
}
</script>
```

`<script setup>` 的好处：
- 不需要写 `export default`
- 不需要在 `methods` 里定义函数
- 不需要在 `data()` 里返回数据
- 代码更简洁！

##### 完整对照表

| 语法 | 含义 | 示例 |
|------|------|------|
| `import A from './B'` | 引入 B 文件的**默认导出** | `import App from './App.vue'` |
| `import { A } from './B'` | 引入 B 文件的**命名导出** | `import { ref } from 'vue'` |
| `import { A, B, C } from './D'` | 引入多个命名导出 | `import { ref, computed } from 'vue'` |
| `export default X` | 默认导出 X | `export default { name: 'App' }` |
| `export const X` | 命名导出 X | `export const PI = 3.14` |
| `export function X()` | 命名导出函数 X | `export function add(a, b) {}` |

> 💡 **记住这两句话**：
> - `import` = 拿来用（引入别人的代码）
> - `export` = 给别人用（暴露自己的代码）

#### 2.2.5 vite.config.js - Vite 配置文件

```javascript
import { fileURLToPath, URL } from 'node:url'

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [
    vue(),
  ],
  resolve: {
```

**逐行详细解释**：

```javascript
import { fileURLToPath, URL } from 'node:url'
// 从 Node.js 内置的 url 模块导入工具函数
// fileURLToPath：将 file:// URL 转换为文件系统路径
// URL：URL 构造函数
// node: 前缀是 Node.js 内置模块的新写法


import { defineConfig } from 'vite'
// 从 vite 导入 defineConfig 函数
// defineConfig 提供类型提示和配置验证
// 不用它也行，但用了之后编辑器会有智能提示


import vue from '@vitejs/plugin-vue'
// 导入 Vite 的 Vue 插件
// 这个插件让 Vite 能够处理 .vue 单文件组件


export default defineConfig({
  // 导出配置对象

  plugins: [
    vue(),
    // 注册 Vue 插件
    // vue() 返回一个插件对象，包含处理 .vue 文件的逻辑
    // 没有这个插件，Vite 不知道如何处理 .vue 文件
  ],
  
  resolve: {
    // 模块解析配置
    
    alias: {
      // 路径别名配置
      
      '@': fileURLToPath(new URL('./src', import.meta.url))
      // 将 @ 符号映射到 src 目录
      // 这样在代码中可以用 @/xxx 代替 ../../../src/xxx
      // 例如：import HelloWorld from '@/components/HelloWorld.vue'
      // 比写相对路径更清晰，也更方便重构
      //
      // fileURLToPath(new URL('./src', import.meta.url)) 的作用：
      // 1. import.meta.url 是当前文件的 URL
      // 2. new URL('./src', import.meta.url) 创建指向 src 目录的 URL
      // 3. fileURLToPath 将 URL 转换为操作系统识别的路径
    }
  }
})
```

```javascript
      '/api': {
        target: 'http://localhost:8080',  // 后端服务器地址
        changeOrigin: true,               // 修改请求头中的 Origin
        rewrite: (path) => path.replace(/^\/api/, '')  // 重写路径
      }
    }
  },
  
  // 构建配置
  build: {
    outDir: 'dist',           // 输出目录
    assetsDir: 'assets',      // 静态资源目录
    sourcemap: false,         // 是否生成 sourcemap
    minify: 'terser',         // 压缩方式
    chunkSizeWarningLimit: 500  // chunk 大小警告阈值（KB）
  }
})
```

> 📌 **项目实战：SyncHealth 的 `vite.config.ts` 实际配置**
>
> 项目中的 Vite 配置精简但实用：
>
> 1. **Vue 插件注册**：`plugins: [vue()]` — `@vitejs/plugin-vue` 是让 Vite 能够解析 `.vue` 文件的核心插件。没有它，Vite 无法理解 `<template>`、`<script setup>` 和 `<style scoped>` 这些 Vue 特有语法。
>
> 2. **开发服务器配置**：`port: 5173` — 固定开发端口，与文档示例一致。`proxy: { '/api': { target: 'http://127.0.0.1:8000', changeOrigin: true } }` — API 代理配置，这是解决前后端分离项目中跨域问题的关键。前端运行在 `localhost:5173`，后端 API 运行在 `127.0.0.1:8000`，浏览器的同源策略会禁止直接跨域请求。通过配置 Vite 代理，所有 `/api` 开头的请求都会被 Vite 开发服务器转发到后端，浏览器只与 Vite 服务器（同源）通信，从而绕过跨域限制。`changeOrigin: true` 会把请求头中的 Origin 改为目标地址，让后端认为请求来自同一个来源。
>
> 3. **相较于文档中的完整配置，项目配置更简洁**——只配置了实际需要的选项。这是因为 Vite 提供了合理的默认值（如构建输出目录默认就是 `dist`），不需要显式配置。工程化开发中遵循"按需配置"原则，项目复杂度增加时再逐步添加配置项。

## 3. 单文件组件 SFC

### 3.1 什么是单文件组件？

**单文件组件**（Single File Component，简称 SFC）是 Vue 特有的文件格式，使用 `.vue` 作为扩展名。

```
CDN 方式的组件定义：
┌────────────────────────────────────────┐
│  const MyComponent = {                 │
│      template: `                       │
│          <div class="box">             │ ← HTML、JS、CSS
│              {{ message }}             │   混在一起
│          </div>                        │   难以维护
│      `,                                │
│      data() { return { message: 'Hi' } }│
│  }                                     │
└────────────────────────────────────────┘

单文件组件（.vue 文件）：
┌────────────────────────────────────────┐
│  <template>                            │ ← HTML 结构
│      <div class="box">{{ message }}</div>
│  </template>                           │
│                                        │
│  <script setup>                        │ ← JavaScript 逻辑
│      const message = 'Hi'              │
│  </script>                             │
│                                        │
│  <style scoped>                        │ ← CSS 样式
│      .box { color: red; }              │
│  </style>                              │
└────────────────────────────────────────┘
```

**单文件组件的优势**：

| 特性 | 说明 |
|------|------|
| 关注点分离 | HTML、JS、CSS 分开写，结构清晰 |
| 完整的 IDE 支持 | 语法高亮、智能提示、错误检查 |
| 模块化 | 一个文件就是一个组件，方便复用 |
| scoped CSS | 样式只作用于当前组件，不会污染全局 |
| 预处理器支持 | 可以使用 Sass、Less、TypeScript 等 |

### 3.2 SFC 的三个部分

一个 `.vue` 文件由三个部分组成：

```vue
<template>
  <!-- 组件的 HTML 结构 -->
</template>

<script>
// 组件的 JavaScript 逻辑
</script>

<style>
/* 组件的 CSS 样式 */
</style>
```

#### 3.2.1 `<template>` - 模板部分

```vue
<template>
  <!-- 组件的 HTML 结构写在这里 -->
  
  <!-- 必须有一个根元素（Vue 3 已经不是必须的了，但建议有） -->
  <div class="my-component">
    <h1>{{ title }}</h1>
    <p>{{ content }}</p>
    <button @click="handleClick">点击</button>
  </div>
</template>
```

**template 的特点**：
- 里面写的就是 HTML，支持所有 HTML 标签
- 可以使用 Vue 的模板语法（插值、指令等）
- Vue 3 支持多个根元素（Vue 2 只能有一个）
- 支持使用导入的组件

**Vue 3 多根元素**：

```vue
<template>
  <!-- Vue 3 可以有多个根元素 -->
  <header>头部</header>
  <main>主体</main>
  <footer>底部</footer>
</template>
```

#### 3.2.2 `<script>` - 脚本部分

Vue 3 中有两种写法：**普通写法**和 **`<script setup>` 写法**。

**普通写法（选项式 API）**：

```vue
<script>
// 和 CDN 方式几乎一样
export default {
  // 组件名称（可选，用于调试和递归引用）
  name: 'MyComponent',
  
  // 接收的 props
  props: {
    title: String,
    count: {
      type: Number,
      default: 0
    }
  },
  
  // 组件数据
  data() {
    return {
      message: 'Hello',
      list: []
    }
  },
  
  // 计算属性
  computed: {
    doubleCount() {
      return this.count * 2
    }
  },
  
  // 方法
  methods: {
    handleClick() {
      console.log('clicked')
    }
  },
  
  // 生命周期钩子
  mounted() {
    console.log('组件已挂载')
  }
}
</script>
```

**`<script setup>` 写法（组合式 API）**：

```vue
<script setup>
// Vue 3 推荐的写法，更简洁！
import { ref, computed, onMounted } from 'vue'

// 定义 props
const props = defineProps({
  title: String,
  count: {
    type: Number,
    default: 0
  }
})

// 响应式数据（类似 data）
const message = ref('Hello')
const list = ref([])

// 计算属性
const doubleCount = computed(() => props.count * 2)

// 方法（直接定义函数就行）
function handleClick() {
  console.log('clicked')
}

// 生命周期
onMounted(() => {
  console.log('组件已挂载')
})

// 不需要 return，所有顶层变量自动暴露给模板
</script>
```

**两种写法对比**：

| 特性 | 普通写法 | `<script setup>` |
|------|----------|------------------|
| 代码量 | 较多 | 较少 |
| 学习曲线 | 平缓（类似 Vue 2） | 需要学习组合式 API |
| 变量暴露 | 需要 return | 自动暴露 |
| 组件注册 | 需要 components 选项 | 导入即可用 |
| IDE 支持 | 一般 | 更好 |
| 性能 | 一般 | 略好 |
| Vue 官方推荐 | Vue 2 风格 | Vue 3 推荐 |

**本文档后续将使用 `<script setup>` 写法**，因为这是 Vue 3 推荐的方式。

#### 3.2.3 `<style>` - 样式部分

```vue
<style>
/* 普通样式，会影响全局 */
.my-class {
  color: red;
}
</style>

<style scoped>
/* scoped 样式，只影响当前组件 */
.my-class {
  color: blue;
}
</style>

<style lang="scss" scoped>
/* 使用 SCSS 预处理器 */
.container {
  .title {
    font-size: 20px;
    
    &:hover {
      color: red;
    }
  }
}
</style>
```

**scoped 的工作原理**：

```html
<!-- 你写的代码 -->
<template>
  <div class="box">内容</div>
</template>
<style scoped>
.box { color: red; }
</style>

<!-- 编译后的结果 -->
<div class="box" data-v-7ba5bd90>内容</div>
<style>
.box[data-v-7ba5bd90] { color: red; }
</style>

<!-- 
Vue 做了什么：
1. 给组件的每个元素添加一个唯一属性 data-v-7ba5bd90
2. 给样式选择器也加上这个属性选择器
3. 这样样式就只会匹配当前组件的元素
-->
```

### 3.3 `<script setup>` 详解

`<script setup>` 是 Vue 3.2 引入的语法糖，让组合式 API 的代码更简洁。

> 📌 **项目实战：SyncHealth 中 `<script setup>` 的统一使用**
>
> SyncHealth 项目中**所有 `.vue` 文件都使用 `<script setup lang="ts">` 写法**，这是 Vue 3 工程化项目的最佳实践。以 `LoginView.vue` 为例：
>
> 1. **变量自动暴露**：`const email = ref('')`、`const loading = ref(false)` 等所有顶层变量自动对模板可用，不需要 `return` 或在 `data()` 中声明。模板中的 `v-model="email"` 和 `:disabled="loading"` 直接引用这些变量。
>
> 2. **函数即方法**：`async function handleLogin() { ... }` 直接在 `<script setup>` 顶层定义，模板中的 `@submit.prevent="handleLogin"` 直接引用。不需要像选项式 API 那样写在 `methods: { }` 中。
>
> 3. **导入即注册**：`import { useAuthStore } from '../stores/auth'` 导入的 Store 方法可以直接使用 `authStore.login(...)`，不需要在 `components` 选项中注册。路由组件也一样——在 `router/index.ts` 中通过 `component: () => import('../views/LoginView.vue')` 导入后即可使用。
>
> 4. **TypeScript 集成**：`lang="ts"` 表示在 `<script setup>` 中使用 TypeScript。项目中所有数据都有类型标注（如 `const email = ref('')` 被自动推导为 `Ref<string>`），API 调用有类型约束（如 `useAuthStore` 返回的类型包含 `login`、`logout` 等方法的完整签名），这使得 IDE 的智能提示和编译时错误检查都能正常工作。

#### 3.3.1 响应式数据：ref 和 reactive

```vue
<script setup>
import { ref, reactive } from 'vue'

// ref：用于基本类型（字符串、数字、布尔值）
const count = ref(0)
const message = ref('Hello')
const isActive = ref(true)

// 在 JS 中访问/修改 ref 的值，需要用 .value
console.log(count.value)  // 0
count.value++             // 修改值
console.log(count.value)  // 1

// 在模板中使用 ref，会自动解包，不需要 .value
// {{ count }} 而不是 {{ count.value }}


// reactive：用于对象和数组
const user = reactive({
  name: '张三',
  age: 25
})
const list = reactive([1, 2, 3])

// 在 JS 中访问/修改 reactive 的值，不需要 .value
console.log(user.name)    // '张三'
user.age = 26             // 直接修改属性
list.push(4)              // 直接操作数组
</script>

<template>
  <div>
    <!-- ref 自动解包 -->
    <p>计数：{{ count }}</p>
    <p>消息：{{ message }}</p>
    
    <!-- reactive 直接使用 -->
    <p>姓名：{{ user.name }}</p>
    <p>年龄：{{ user.age }}</p>
  </div>
</template>
```

**ref vs reactive 的选择**：

```
ref 适用于：
├── 基本类型：string、number、boolean
├── 需要整体替换的值
└── 例如：const count = ref(0)

reactive 适用于：
├── 对象和数组
├── 嵌套数据结构
└── 例如：const user = reactive({ name: '张三', age: 25 })

实际开发建议：
├── 简单数据用 ref
├── 复杂对象用 reactive
└── 如果不确定，统一用 ref 也可以
```

#### 3.3.2 计算属性：computed

```vue
<script setup>
import { ref, computed } from 'vue'

const firstName = ref('张')
const lastName = ref('三')
const todos = ref([
  { text: '学习', done: true },
  { text: '运动', done: false },
  { text: '休息', done: false }
])

// 只读的计算属性
const fullName = computed(() => {
  return firstName.value + lastName.value
})

// 可写的计算属性
const fullNameWritable = computed({
  get() {
    return firstName.value + lastName.value
  },
  set(newValue) {
    firstName.value = newValue[0]
    lastName.value = newValue.slice(1)
  }
})

// 计算属性示例：过滤未完成的待办
const unfinishedTodos = computed(() => {
  return todos.value.filter(todo => !todo.done)
})

// 计算属性示例：统计信息
const stats = computed(() => ({
  total: todos.value.length,
  done: todos.value.filter(t => t.done).length,
  undone: todos.value.filter(t => !t.done).length
}))
</script>

<template>
  <p>全名：{{ fullName }}</p>
  <p>未完成：{{ unfinishedTodos.length }} 项</p>
  <p>统计：共 {{ stats.total }} 项，已完成 {{ stats.done }} 项</p>
</template>
```

#### 3.3.3 侦听器：watch 和 watchEffect

```vue
<script setup>
import { ref, watch, watchEffect } from 'vue'

const count = ref(0)
const user = ref({ name: '张三', age: 25 })

// 侦听单个 ref
watch(count, (newValue, oldValue) => {
  console.log(`count 从 ${oldValue} 变为 ${newValue}`)
})

// 侦听多个值
watch(
  [count, () => user.value.name],  // 侦听 count 和 user.name
  ([newCount, newName], [oldCount, oldName]) => {
    console.log('count 或 name 变化了')
  }
)

// 深度侦听
watch(
  user,
  (newValue) => {
    console.log('user 变化了', newValue)
  },
  { deep: true }  // 开启深度侦听，对象内部属性变化也会触发
)

// 立即执行
watch(
  count,
  (newValue) => {
    console.log('count:', newValue)
  },
  { immediate: true }  // 创建时立即执行一次
)

// watchEffect：自动追踪依赖
// 不需要指定侦听什么，用到什么就侦听什么
watchEffect(() => {
  console.log('count 是', count.value)
  // 只要 count.value 变化，这个函数就会重新执行
})
</script>
```

**watch vs watchEffect**：

| 特性 | watch | watchEffect |
|------|-------|-------------|
 指定侦听源 | 需要明确指定 | 自动追踪 |
| 获取旧值 | 可以获取 | 不能获取 |
| 初始执行 | 默认不执行 | 立即执行 |
| 适用场景 | 需要旧值对比 | 简单的副作用 |

#### 3.3.4 生命周期钩子

```vue
<script setup>
import {
  onBeforeMount,
  onMounted,
  onBeforeUpdate,
  onUpdated,
  onBeforeUnmount,
  onUnmounted
} from 'vue'

// 组件挂载前
onBeforeMount(() => {
  console.log('即将挂载到 DOM')
})

// 组件挂载后（最常用！）
onMounted(() => {
  console.log('已挂载到 DOM')
  // 这里可以访问 DOM 元素
  // 这里可以发起网络请求
  // 这里可以初始化第三方库
})

// 组件更新前
onBeforeUpdate(() => {
  console.log('即将更新')
})

// 组件更新后
onUpdated(() => {
  console.log('已更新')
})

// 组件卸载前
onBeforeUnmount(() => {
  console.log('即将卸载')
  // 这里可以清理定时器、取消订阅等
})

// 组件卸载后
onUnmounted(() => {
  console.log('已卸载')
})
</script>
```

> 📌 **项目实战：`onMounted` 和 `onUnmounted` 在 SyncHealth 中的典型用法**
>
> **`App.vue` 中的 `onMounted`**：应用启动时检查认证状态，如果用户已登录则获取用户信息。`onMounted(async () => { if (authStore.isAuthenticated) { await authStore.fetchUser() } })`——这个逻辑放在 `onMounted` 而非 `<script setup>` 顶层，是因为 `fetchUser()` 依赖 Pinia 和 API 客户端已经初始化完毕，太早调用可能会导致依赖未就绪。
>
> **`UploadView.vue` 中的 `onMounted` + `onUnmounted` 配对**：页面挂载时调用 `loadHistory()` 获取导入历史记录；页面卸载时调用 `stopPolling()` 清除 `setInterval` 定时器。这是生命周期钩子最经典的配对模式——`onMounted` 注册副作用（定时器、事件监听、WebSocket 连接），`onUnmounted` 清理副作用，防止内存泄漏和后台继续执行。如果不清理 `setInterval`，即使用户导航到其他页面，定时器仍会在后台持续轮询，浪费网络和 CPU 资源。
>
> **`AIChatView.vue` 中的 `onMounted`**：`aiStore.fetchSessions()` 获取历史会话列表，`aiStore.fetchModels()` 获取可用模型列表——两个请求在组件挂载时并行发起（Store 内部使用 `Promise.all`），确保页面加载后用户立即看到完整数据，从用户视角是"一个瞬间"所有数据就加载好了。

#### 3.3.6 模板引用（ref）

```vue
onMounted(() => {
  // 组件挂载后才能访问 DOM
  console.log(inputRef.value)  // <input> DOM 元素
  
  // 操作 DOM
  inputRef.value.focus()       // 让输入框获得焦点
  
  // 访问子组件暴露的方法（需要子组件使用 defineExpose）
  childRef.value.someMethod()
})
</script>

<template>
  <!-- 绑定 ref 到 DOM 元素 -->
  <input ref="inputRef" type="text">
  
  <!-- 绑定 ref 到子组件 -->
  <ChildComponent ref="childRef" />
</template>
```

**子组件暴露方法**：

```vue
<!-- ChildComponent.vue -->
<script setup>
import { ref } from 'vue'

const count = ref(0)

function someMethod() {
  console.log('子组件方法被调用')
}

function reset() {
  count.value = 0
}

// 使用 defineExpose 暴露给父组件
// 默认情况下，<script setup> 中的变量不会暴露给父组件
defineExpose({
  someMethod,
  reset,
  count
})
</script>
```

## 4. Vue Router 路由

### 4.1 什么是路由？

#### 4.1.1 传统多页面 vs 单页面应用

**传统多页面应用（MPA）**：

```
用户访问不同页面：
┌─────────────────────────────────────────────────────┐
│                                                      │
│  访问首页     访问关于页     访问联系页               │
│     │            │             │                     │
│     ▼            ▼             ▼                     │
│  /index.html  /about.html  /contact.html            │
│     │            │             │                     │
│     └────────────┴─────────────┘                     │
│                  │                                   │
│                  ▼                                   │
│        每次都请求服务器                               │
│        获取完整的 HTML 页面                          │
│        页面会闪白、重新加载                          │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**单页面应用（SPA）**：

```
Vue 单页面应用：
┌─────────────────────────────────────────────────────┐
│                                                      │
│  只有一个 HTML 文件（index.html）                    │
│                                                      │
│  访问首页     访问关于页     访问联系页               │
│     │            │             │                     │
│     ▼            ▼             ▼                     │
│  /#/ 或 /     /#/about       /#/contact             │
│     │            │             │                     │
│     └────────────┴─────────────┘                     │
│                  │                                   │
│                  ▼                                   │
│        不请求服务器（只是 URL 变化）                  │
│        JavaScript 根据 URL 切换组件                  │
│        页面不刷新，体验丝滑                          │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**SPA 的优点**：
- 页面切换不刷新，体验更流畅
- 前后端分离，开发效率高
- 可以实现复杂的页面过渡动画

**SPA 的缺点**：
- 首次加载较慢（需要下载所有 JS）
- SEO 不友好（搜索引擎难以抓取）
- 需要路由管理工具

#### 4.1.2 什么是 Vue Router？

**Vue Router** 是 Vue.js 官方的路由管理器，用来：

1. **URL 和组件的映射**：定义什么 URL 显示什么组件
2. **页面导航**：在不刷新页面的情况下切换"页面"
3. **路由参数**：URL 中传递数据
4. **路由守卫**：控制页面访问权限

```
Vue Router 的工作原理：
┌─────────────────────────────────────────────────────┐
│                                                      │
│  URL 变化                                            │
│     │                                                │
│     ▼                                                │
│  Vue Router 拦截                                     │
│     │                                                │
│     ▼                                                │
│  根据路由配置找到对应的组件                          │
│     │                                                │
│     ▼                                                │
│  在 <RouterView> 中渲染该组件                        │
│                                                      │
│  ┌───────────────────────────────────────────┐      │
│  │  URL: /about                               │      │
│  │                                            │      │
│  │  路由配置：                                 │      │
│  │  { path: '/about', component: AboutView }  │      │
│  │                                            │      │
│  │  结果：显示 AboutView 组件                  │      │
│  └───────────────────────────────────────────┘      │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### 4.2 路由基础配置

#### 4.2.1 路由配置文件结构

```javascript
// src/router/index.js

import { createRouter, createWebHistory } from 'vue-router'
import HomeView from '../views/HomeView.vue'

// 定义路由规则
const routes = [
  {
    path: '/',               // URL 路径
    name: 'home',            // 路由名称（可选，用于编程式导航）
    component: HomeView      // 对应的组件
  },
  {
    path: '/about',
    name: 'about',
    // 路由懒加载：只有访问时才加载组件
    component: () => import('../views/AboutView.vue')
  }
]

// 创建路由实例
const router = createRouter({
  // 路由模式
  history: createWebHistory(import.meta.env.BASE_URL),
  // 路由规则
  routes
})

export default router
```

**逐行超详细解释**：

```javascript
import { createRouter, createWebHistory } from 'vue-router'
// 从 vue-router 导入两个函数：
// createRouter：创建路由实例
// createWebHistory：创建 HTML5 历史模式


import HomeView from '../views/HomeView.vue'
// 直接导入组件（打包时会包含在主 bundle 中）
// 适合首页等必定会访问的页面


const routes = [
  // routes 是一个数组，每个元素是一个路由规则对象
  
  {
    path: '/',
    // path：URL 路径
    // '/' 表示根路径，即 http://localhost:5173/
    
    name: 'home',
    // name：路由名称，可选但建议设置
    // 用于编程式导航：router.push({ name: 'home' })
    // 好处：即使 path 变了，代码也不用改
    
    component: HomeView
    // component：路径匹配时显示的组件
    // 这里直接使用导入的组件
  },
  
  {
    path: '/about',
    name: 'about',
    
    component: () => import('../views/AboutView.vue')
    // 路由懒加载！！！非常重要！！！
    // 使用箭头函数 + import() 语法
    // 效果：只有用户访问 /about 时，才会下载 AboutView 的代码
    // 好处：减小首次加载的文件体积，加快首屏速度
  }
]


const router = createRouter({
  // 创建路由实例
  
  history: createWebHistory(import.meta.env.BASE_URL),
  // history：路由模式
  // createWebHistory()：HTML5 History 模式
  //   URL 格式：http://example.com/about
  //   优点：URL 美观
  //   缺点：需要服务器配置支持
  //
  // 还可以用 createWebHashHistory()：Hash 模式
  //   URL 格式：http://example.com/#/about
  //   优点：不需要服务器配置
  //   缺点：URL 有 # 号，不够美观
  //
  // import.meta.env.BASE_URL：Vite 提供的基础路径
  // 默认是 '/'，可以在 vite.config.js 中配置
  
  routes
  // routes：路由规则数组
  // 这里用了 ES6 简写，等价于 routes: routes
})


export default router
// 导出路由实例，供 main.js 使用
```

> 📌 **项目实战：`router/index.ts` 中的嵌套路由 + 路由守卫完整实现**
>
> SyncHealth 的路由配置完整展示了三个核心知识点：
>
> **1. 路由懒加载**：所有路由组件都使用 `() => import('../views/xxx.vue')` 的动态导入语法。这意味着每个页面组件的代码只有在用户第一次访问时才会被下载，而不是在首次加载时全部打包。对于像 `AIChatView.vue`（包含 marked 库和 WebSocket 逻辑）这样体积较大的页面，懒加载能显著加快首屏加载速度。
>
> **2. 嵌套路由**：根路径 `/` 的 `component` 是 `AppLayout.vue`（带侧边栏的布局组件），它的 `children` 数组包含了 8 个子路由。这个设计实现了"外层布局不变、内层页面切换"——侧边栏和用户信息始终显示，右侧 `<router-view />` 中的内容随 URL 变化。子路由的 `path` 如 `'heart'` 和 `'chat'`，不以 `/` 开头，Vue Router 自动拼接父路径。
>
> **3. 路由守卫**：`beforeEach` 基于 `meta` 实现了权限控制。登录/注册页标记 `meta: { guest: true }`，其他页面标记 `meta: { requiresAuth: true }`。守卫逻辑判断：若目标路由需登录但用户未认证 → 重定向到 `/login`；若目标路由是 visitor 专属但用户已登录 → 重定向到首页。守卫中使用 `useAuthStore().isAuthenticated` 计算属性来判断登录状态——这是 Pinia 与 Router 守卫协作的典型模式。

#### 4.2.2 在 main.js 中注册路由

路由配置文件写好后，需要在入口文件 `main.js` 中**注册**给 Vue 应用，才能在整个项目中生效。

```javascript
// src/main.js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'  // 导入路由（自动找 router/index.js）

const app = createApp(App)

// app.use() 是 Vue 的插件安装方法
// 安装 router 后，整个应用的所有组件都能使用：
//   - <RouterLink> 导航链接组件
//   - <RouterView> 路由出口组件
//   - useRouter() / useRoute() 等组合式函数
app.use(router)

// 注意：app.mount('#app') 必须在所有 app.use() 之后调用
// 确保所有插件安装完毕后再开始渲染组件
app.mount('#app')
```

> 💡 **关键理解**：`app.use(router)` 相当于给整个应用"安装路由功能"。
> 不安装的话，组件里用 `<RouterLink>` 会报错，`useRouter()` 也无法使用。

**同时使用 Pinia + Router 时的顺序建议**：

```javascript
const app = createApp(App)

app.use(createPinia())  // ① 先装 Pinia
                        //   （路由守卫中可能用到 Store，要确保 Pinia 先就绪）
app.use(router)         // ② 再装 Router

app.mount('#app')       // ③ 最后挂载（必须放在最后！）
```

#### 4.2.3 在模板中使用路由

```vue
<!-- src/App.vue -->
<script setup>
import { RouterLink, RouterView } from 'vue-router'
</script>

<template>
  <div id="app">
    <!-- 导航栏 -->
    <nav>
      <!-- RouterLink：导航链接组件 -->
      <!-- to 属性指定目标路径 -->
      <!-- 渲染成 <a> 标签，但点击不会刷新页面 -->
      <RouterLink to="/">首页</RouterLink>
      <RouterLink to="/about">关于</RouterLink>
    </nav>
    
    <!-- 路由出口 -->
    <!-- 当前路由匹配的组件会渲染在这里 -->
    <RouterView />
  </div>
</template>
```

> 📌 **项目实战：`AppLayout.vue` 中的 RouterLink + 动态 class 绑定**
>
> 侧边栏导航是路由实战的绝佳范例。在 `AppLayout.vue` 中，8 个导航项通过 `v-for` 循环渲染，每个 `<router-link>` 同时使用了 `:to`（动态路径）、`:key`（唯一标识）和 `:class`（高亮判定）：
>
> ```html
> <router-link
>   v-for="item in navItems"
>   :key="item.path"
>   :to="item.path"
>   :class="{ active: route.path === item.path }"
> >
> ```
>
> 当用户点击导航项时，`router-link` 不刷新页面地切换到目标路径，`route.path` 自动更新，Vue 重新计算每个链接的 `:class` 绑定条件——当前页面对应的链接获得 `active` 类名并显示品牌色背景。同时，`<router-view />` 在右侧主内容区渲染匹配的路由组件。
>
> 这种"左侧固定导航 + 右侧动态路由内容"的布局模式是后台管理系统的标准架构。路由配置中嵌套路由（`children`）使得 `AppLayout.vue` 作为父布局组件始终显示，而子路由组件（如 `DashboardView`、`AIChatView`）在它的 `<router-view />` 中动态切换。

**RouterLink vs 普通 a 标签**：

```html
<!-- 普通 a 标签 -->
<a href="/about">关于</a>
<!-- 点击会刷新整个页面，重新加载所有资源 -->

<!-- RouterLink -->
<RouterLink to="/about">关于</RouterLink>
<!-- 点击只会更新 URL 和 RouterView 中的内容 -->
<!-- 页面不刷新，体验更流畅 -->
```

**RouterLink 自动激活 class**：

RouterLink 渲染成 `<a>` 标签后，当链接地址与当前 URL 匹配时，会自动添加 CSS 类，让你可以给当前页面的导航链接设置高亮样式：

```
当前 URL：/about

<RouterLink to="/">首页</RouterLink>
→ <a href="/">首页</a>                              ← 不匹配，无特殊 class

<RouterLink to="/about">关于</RouterLink>
→ <a href="/about" class="router-link-active router-link-exact-active">关于</a>
                                                     ↑ 自动加上这两个 class
```

| 自动添加的 CSS 类 | 触发条件 | 场景举例 |
|-----------------|---------|---------|
| `router-link-active` | URL **包含**该路径（前缀匹配） | 访问 `/about/team` 时，`/about` 的链接也会激活 |
| `router-link-exact-active` | URL **完全等于**该路径 | 只有访问 `/about` 时才激活 |

> ⚠️ **首页 `/` 的特殊性**：由于所有路径都以 `/` 开头，首页链接会一直匹配 `router-link-active`。
> 通常给首页链接加 `exact` 属性解决：`<RouterLink to="/" exact>首页</RouterLink>`

```css
/* 在 CSS 中直接用这两个类名来设置高亮样式 */
.router-link-active {
  color: #e74c3c;               /* 当前路由高亮颜色 */
}
.router-link-exact-active {
  font-weight: bold;            /* 精确匹配时加粗 */
  border-bottom: 2px solid #e74c3c;
}
```

### 4.3 路由导航方式

#### 4.3.1 声明式导航（RouterLink）

**声明式导航**是指在模板中直接用 `<RouterLink>` 组件来写跳转链接，不需要在 JavaScript 中写任何导航逻辑，适合写在导航栏、面包屑、按钮等固定跳转的地方。

**`to` 属性的两种写法对比**：

| 写法 | 示例 | 优缺点 |
|------|------|--------|
| 字符串路径 | `to="/about"` | 简单，但路径改变时需要全局查找替换 |
| 对象形式（推荐） | `:to="{ name: 'about' }"` | 用路由名称导航，路径改变时只需改路由配置 |

```vue
<template>
  <!-- 基础用法 -->
  <RouterLink to="/">首页</RouterLink>
  <RouterLink to="/about">关于</RouterLink>
  
  <!-- 使用路由名称（推荐） -->
  <RouterLink :to="{ name: 'home' }">首页</RouterLink>
  <RouterLink :to="{ name: 'about' }">关于</RouterLink>
  
  <!-- 带参数 -->
  <RouterLink :to="{ name: 'user', params: { id: 123 } }">用户详情</RouterLink>
  <!-- 生成: /user/123 -->
  
  <!-- 带查询参数 -->
  <RouterLink :to="{ path: '/search', query: { keyword: 'vue' } }">
    搜索
  </RouterLink>
  <!-- 生成: /search?keyword=vue -->
  
  <!-- 激活状态样式 -->
  <!-- 当前路由匹配时，RouterLink 会自动添加以下 class： -->
  <!-- router-link-active：路径包含匹配 -->
  <!-- router-link-exact-active：路径精确匹配 -->
  <RouterLink to="/about" active-class="active">关于</RouterLink>
</template>

<style>
/* 激活状态样式 */
.router-link-active {
  color: blue;
}
.router-link-exact-active {
  font-weight: bold;
}
/* 或者自定义 class */
.active {
  color: red;
}
</style>
```

#### 4.3.2 编程式导航（router.push）

```vue
<script setup>
import { useRouter, useRoute } from 'vue-router'

// useRouter：获取路由实例，用于导航
const router = useRouter()

// useRoute：获取当前路由信息
const route = useRoute()

// 导航方法
function goHome() {
  // 字符串路径
  router.push('/')
}

function goAbout() {
  // 对象形式
  router.push({ path: '/about' })
}

function goUser(userId) {
  // 带路由参数
  router.push({ name: 'user', params: { id: userId } })
  // 或
  router.push(`/user/${userId}`)
}

function goSearch(keyword) {
  // 带查询参数
  router.push({ path: '/search', query: { keyword } })
  // 生成: /search?keyword=xxx
}

function goBack() {
  // 后退一步
  router.back()
  // 等价于 router.go(-1)
}

function goForward() {
  // 前进一步
  router.forward()
  // 等价于 router.go(1)
}

function replaceToLogin() {
  // replace：替换当前历史记录（不能后退）
  // 适合登录跳转等场景
  router.replace('/login')
}
</script>

<template>
  <button @click="goHome">返回首页</button>
  <button @click="goAbout">去关于页</button>
  <button @click="goUser(123)">查看用户 123</button>
  <button @click="goSearch('vue')">搜索 Vue</button>
  <button @click="goBack">后退</button>
</template>
```

**push vs replace 的区别**：

```
router.push('/about')：
历史记录：[ /home ] → [ /home, /about ]
可以点击浏览器后退按钮回到 /home

router.replace('/about')：
历史记录：[ /home ] → [ /about ]
/home 被替换了，不能后退

使用场景：
- push：普通页面跳转
- replace：登录后跳转、404 页面跳转、重定向等不需要后退的场景
```

### 4.4 动态路由

**动态路由**解决的问题：当页面内容由 URL 中的参数决定时，你不可能为每条数据单独写一条路由规则。

```
// ❌ 不可能这样写（用户有成千上万个，写不完）
{ path: '/user/1', component: UserView }
{ path: '/user/2', component: UserView }
{ path: '/user/3', component: UserView }
...

// ✅ 使用动态路由（一条规则匹配所有用户）
{ path: '/user/:id', component: UserView }
// /user/1、/user/42、/user/9999 都能匹配！
// 冒号后面的 id 叫做"动态参数"，URL 中对应位置的值会被提取出来
```

**常见使用场景**：
- 用户主页：`/user/:id`
- 文章详情：`/article/:id`
- 商品详情：`/product/:id`
- 分类页：`/category/:type`

#### 4.4.1 路由参数（params）
这段路由配置本身不会自动展示对应用户 / 帖子页面，它只是定义了动态路由规则，真正展示对应数据需要你在组件里获取路由参数并请求 / 渲染数据。

它只是定义了路由匹配规则：
/user/123 → 匹配到 UserView.vue
/user/456 → 也匹配到同一个 UserView.vue
/post/vue/100 → 匹配到 PostView.vue
所有相同前缀的动态路由，都渲染同一个组件，路由本身不会区分用户 ID、分类 ID。
```javascript
// src/router/index.js
const routes = [
  {
    // :id 是动态参数，可以匹配任意值
    path: '/user/:id',
    name: 'user',
    component: () => import('../views/UserView.vue')
  },
  {
    // 多个参数
    path: '/post/:category/:id',
    name: 'post',
    component: () => import('../views/PostView.vue')
  },
  {
    // 可选参数（参数后加 ?）
    path: '/search/:keyword?',
    name: 'search',
    component: () => import('../views/SearchView.vue')
  }
]
```

**在组件中获取参数**：

```vue
<!-- src/views/UserView.vue -->
<script setup>
import { useRoute, onBeforeRouteUpdate } from 'vue-router'
import { ref, watch } from 'vue'

const route = useRoute()

// 获取路由参数
const userId = ref(route.params.id)

// ① ref(route.params.id) 为什么能获取到 id？
// 因为：
// route 是当前路由对象
// route.params 是路由里所有动态参数的集合
// 你路由写的是 /user/:id → 所以参数名就叫 id
// 访问 /user/123 → route.params.id 就等于 "123"
// ref(xxx) 只是把这个值变成响应式变量，方便模板和监听使用。



// 注意：如果从 /user/1 切换到 /user/2
// 组件不会重新创建，所以需要监听参数变化
watch(
  () => route.params.id,
  (newId) => {
    userId.value = newId
    // 重新加载数据
    loadUserData(newId)
  }
)

// 或者使用路由守卫
onBeforeRouteUpdate((to, from) => {
  userId.value = to.params.id
})
</script>

<template>
  <div>
    <h1>用户详情</h1>
    <p>用户 ID: {{ userId }}</p>
    <p>也可以直接用: {{ $route.params.id }}</p>
    <!-- 加以 $ 开头的变量 = Vue 内置的全局对象 / 方法比如：$route、$router、$store -->
  </div>
</template>
```

#### 4.4.2 查询参数（query）

```vue
<script setup>
```

**params vs query 的区别**：

| 特性 | params | query |
|------|--------|-------|
| URL 格式 | /user/123 | /search?id=123 |
| 路由配置 | 需要在 path 中定义 | 不需要配置 |
| 必填性 | 通常必填（除非加 ?） | 可选 |
| 刷新页面 | 需要路由配置支持 | 不会丢失 |
| 适用场景 | 资源标识（用户ID、文章ID） | 筛选条件（关键词、页码） |

### 4.5 嵌套路由

**嵌套路由**解决的问题：页面中有一部分内容固定不变（如用户信息头部、侧边栏），另一部分内容随子路由切换。

```
实际场景：用户中心页面
┌──────────────────────────────────────────┐
│  👤 用户：张三  [个人资料] [我的文章] [设置] │  ← 父路由 UserLayout（始终显示）
├──────────────────────────────────────────┤
│                                          │
│  /user/1          → 显示个人资料          │  ← 子路由出口（随 URL 切换）
│  /user/1/posts    → 显示文章列表          │
│  /user/1/settings → 显示设置页面          │
│                                          │
└──────────────────────────────────────────┘
```

**核心原理**：
1. 在路由配置中，用 `children` 数组定义子路由
2. 在父组件（UserLayout）内再放一个 `<RouterView />`，作为子路由的渲染位置
3. 访问子路由时，父组件和子组件同时显示

当页面有多层嵌套结构时，使用嵌套路由。

#### 4.5.1 路由配置

```javascript
// src/router/index.js
const routes = [
  {
    path: '/user/:id',
    name: 'user',
    component: () => import('../views/UserLayout.vue'),
    // 子路由
    children: [
      {
        // 空路径，匹配 /user/:id
        path: '',
        name: 'user-profile',
        component: () => import('../views/user/Profile.vue')
      },
      {
        // 匹配 /user/:id/posts
        path: 'posts',
        name: 'user-posts',
        component: () => import('../views/user/Posts.vue')
      },
      {
        // 匹配 /user/:id/settings
        path: 'settings',
        name: 'user-settings',
        component: () => import('../views/user/Settings.vue')
      }
    ]
  }
]
```

**嵌套路由图解**：

> 💡 **子路由 `path` 的写法规则**：
> - 子路由的 `path` **不要**以 `/` 开头 → 它是相对于父路由的路径，会自动拼接
> - `path: 'posts'` → 完整 URL 是 `/user/:id/posts`
> - `path: ''` → 完整 URL 就是 `/user/:id`（作为父路由的默认子页面）
> - ❌ `path: '/posts'` → 完整 URL 变成 `/posts`，脱离父路由了（通常不是你想要的）

**嵌套路由图解**：

```
URL: /user/123/posts

┌─────────────────────────────────────────────────────┐
│  App.vue                                             │
│  ┌───────────────────────────────────────────────┐  │
│  │  <RouterView>  ← 一级路由出口                  │  │
│  │                                                │  │
│  │  ┌─────────────────────────────────────────┐  │  │
│  │  │  UserLayout.vue                          │  │  │
│  │  │  ┌─────────────────────────────────────┐ │  │  │
│  │  │  │  用户信息头部                        │ │  │  │
│  │  │  │  用户名: 张三                        │ │  │  │
│  │  │  ├─────────────────────────────────────┤ │  │  │
│  │  │  │  <RouterView>  ← 二级路由出口        │ │  │  │
│  │  │  │  ┌───────────────────────────────┐  │ │  │  │
│  │  │  │  │  Posts.vue                     │  │ │  │  │
│  │  │  │  │  用户的文章列表                 │  │ │  │  │
│  │  │  │  └───────────────────────────────┘  │ │  │  │
│  │  │  └─────────────────────────────────────┘ │  │  │
│  │  └─────────────────────────────────────────┘  │  │
│  │                                                │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### 4.6 路由守卫

路由守卫用于在导航过程中进行拦截和控制。

#### 4.6.1 全局守卫

```javascript
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),
  routes: [...]
})

// 全局前置守卫
// 每次导航前都会执行
router.beforeEach((to, from, next) => {
  // to: 即将进入的目标路由
  // from: 当前导航正要离开的路由
  // next: 放行函数
  
  console.log('从', from.path, '到', to.path)
  
  // 检查是否需要登录
  if (to.meta.requiresAuth) {
    // 检查用户是否已登录
    const isLoggedIn = localStorage.getItem('token')
    
    if (!isLoggedIn) {
      // 未登录，跳转到登录页
      next({ path: '/login', query: { redirect: to.fullPath } })
      return
    }
  }
  
  // 放行
  next()
})

// 也可以用返回值代替 next()
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return { path: '/login' }  // 返回路由对象表示重定向
  }
  // 返回 true 或不返回，表示放行
  // 返回 false 表示取消导航
})


// 全局后置守卫
// 导航完成后执行，没有 next 参数
router.afterEach((to, from) => {
  // 可以用于：修改页面标题、发送统计等
  document.title = to.meta.title || '默认标题'
})


export default router
```

#### 4.6.2 路由元信息（meta）

**路由元信息**是附加在每条路由配置上的**自定义数据**，可以存放任何你想要的信息，然后在路由守卫或组件中读取和使用。

**为什么需要 meta？**

路由对象本身（`path`、`name`、`component`）只能描述“显示哪个组件”，却无法表达“这个页面需要登录吗？”“这个页面叫什么名字？”等附加信息。`meta` 就是专门存放这类**路由附加描述**的地方，相当于给每条路由贴上自定义的“标签”。

**在路由守卫中如何读取 meta**：

访问目标路由的 meta，直接用 `to.meta.字段名` 即可（通常在 `beforeEach` 守卫中使用）：

```javascript
router.beforeEach((to, from) => {
  // to.meta 就是目标路由的 meta 对象
  // 读取 meta.title 并设置到浏览器标签页标题
  document.title = to.meta.title || '默认标题'

  if (to.meta.requiresAuth) {
    // 这条路由需要登录才能访问，进行权限验证
    const token = localStorage.getItem('token')
    if (!token) return { path: '/login' }  // 未登录则跳转登录页
  }
})
```
Vue Router 内部不会主动读取 meta 里任何字段，包括 requiresAuth、title 等都不是内置的。
**meta 的常见用途**：

| meta 字段 | 典型用途 |
|-----------|----------|
| `title` | 设置浏览器标签页的标题 |
| `requiresAuth` | 标记是否需要登录才能访问 |
| `requiresAdmin` | 标记是否需要管理员权限 |
| `keepAlive` | 标记是否缓存该页面（配合 `<KeepAlive>` 使用） |
| `breadcrumb` | 存放面包屑导航的路径数据 |

```javascript
// src/router/index.js
const routes = [
  {
    path: '/',
    name: 'home',
    component: HomeView,
    meta: {
      title: '首页',          // 页面标题
      requiresAuth: false     // 是否需要登录
    }
  },
  {
    path: '/dashboard',
    name: 'dashboard',
    component: DashboardView,
    meta: {
      title: '控制台',
      requiresAuth: true      // 需要登录才能访问
    }
  },
  {
    path: '/admin',
    name: 'admin',
    component: AdminView,
    meta: {
      title: '管理后台',
      requiresAuth: true,
      requiresAdmin: true     // 需要管理员权限
    }
  }
]
```

**完整的权限控制示例**：

```javascript
// src/router/index.js
router.beforeEach((to, from) => {
  // 设置页面标题
  document.title = to.meta.title || 'Vue App'
  
  // 检查登录状态
  const token = localStorage.getItem('token')
  const user = JSON.parse(localStorage.getItem('user') || '{}')
  
  // 需要登录但未登录
  if (to.meta.requiresAuth && !token) {
    return {
      path: '/login',
      query: { redirect: to.fullPath }  // 保存目标路径，登录后跳回
    }
  }
  
  // 需要管理员权限但不是管理员
  if (to.meta.requiresAdmin && user.role !== 'admin') {
    return { path: '/403' }  // 跳转到无权限页面
  }
  
  // 已登录用户访问登录页，跳转到首页
  if (to.path === '/login' && token) {
    return { path: '/' }
  }
})
```

### 4.7 路由过渡动画

**路由过渡动画**让页面切换时有动态效果（淡入淡出、滑动等），而不是生硬的瞬间替换。

**核心思路**：用 Vue 内置的 `<Transition>` 组件包裹 `<RouterView>`，路由切换时自动应用 CSS 动画。

**关键概念说明**：

| 写法 | 作用 |
|------|------|
| `<RouterView v-slot="{ Component }">` | 用插槽方式获取当前路由对应的组件对象 |
| `<component :is="Component" />` | 动态渲染该组件（替代直接写 `<RouterView />`） |
| `mode="out-in"` | 先播放**离开**动画，再播放**进入**动画（避免两个页面同时显示重叠） |
| `name="fade"` | 动画名称前缀，CSS 类名会自动加上这个前缀 |

**CSS 过渡类名的命名规则**（以 `name="fade"` 为例）：

```
fade-enter-from    ← 进入前的初始状态（如：透明度 0）
fade-enter-active  ← 进入过渡过程（在这里定义动画时长和曲线）
fade-enter-to      ← 进入后的最终状态（通常不写，默认正常显示）

fade-leave-from    ← 离开前的初始状态（通常不写，默认正常显示）
fade-leave-active  ← 离开过渡过程（在这里定义动画时长和曲线）
fade-leave-to      ← 离开后的最终状态（如：透明度 0）
```

```vue
<!-- src/App.vue -->
<template>
  <RouterView v-slot="{ Component }">
    <Transition name="fade" mode="out-in">
      <component :is="Component" />
    </Transition>
  </RouterView>
</template>

<style>
/* 进入和离开的过渡效果 */
.fade-enter-active,
.fade-leave-active {
  transition: opacity 0.3s ease;
}

.fade-enter-from,
.fade-leave-to {
  opacity: 0;
}

/* 或者滑动效果 */
.slide-enter-active,
.slide-leave-active {
  transition: all 0.3s ease;
}

.slide-enter-from {
  transform: translateX(20px);
  opacity: 0;
}

.slide-leave-to {
  transform: translateX(-20px);
  opacity: 0;
}
</style>
```

### 4.8 滚动行为

**问题**：默认情况下，Vue Router 切换路由时不处理滚动位置——你可能发现从一个很长的页面跳转到新页面后，滚动条停留在原来的位置，而不是回到顶部。

`scrollBehavior` 选项让你完全自定义每次路由切换后的滚动位置。

**函数的三个参数**：

| 参数 | 说明 | 常见用途 |
|------|------|---------|
| `to` | 即将进入的目标路由对象 | `to.hash` 获取锚点（如 `#section1`） |
| `from` | 正在离开的路由对象 | 根据来源做不同处理 |
| `savedPosition` | 浏览器后退/前进时浏览器保存的滚动坐标 | `{ left: 0, top: 500 }`，只有点击浏览器前进/后退时才有值 |

**函数返回值决定最终滚动到哪里**：

```
返回 { top: 0 }                   → 滚动到页面顶部（最常用）
返回 { top: 0, behavior: 'smooth' } → 平滑滚动到顶部
返回 { el: '#section1' }          → 滚动到页面中 id="section1" 的元素
返回 savedPosition                → 恢复到用户后退前的滚动位置
返回 false 或不返回               → 不处理滚动，保持原位
```

```javascript
// src/router/index.js
const router = createRouter({
  history: createWebHistory(),
  routes,
  
  // 自定义滚动行为
  scrollBehavior(to, from, savedPosition) {
    // savedPosition 只有在浏览器后退/前进时才有值
    if (savedPosition) {
      // 后退时恢复到之前的滚动位置
      return savedPosition
    }
    
    // 如果有 hash（锚点），滚动到锚点位置
    if (to.hash) {
      return {
        el: to.hash,           // 滚动到指定元素
        behavior: 'smooth'     // 平滑滚动
      }
    }
    
    // 默认滚动到顶部
    return { top: 0, behavior: 'smooth' }
  }
})
```

## 5. Pinia 状态管理

### 5.1 什么是状态管理？

#### 5.1.1 为什么需要状态管理？

在 Vue 应用中，组件之间需要共享数据时，我们学过 Props 和 Emit：

```
简单场景（Props + Emit 可以处理）：
┌───────────┐
│   Parent   │
│  (数据源)  │
└────┬──────┘
     │ props 传递
     ▼
┌───────────┐
│   Child    │
└───────────┘
```

但是当应用变大时，问题就出现了：

```
复杂场景（Props 传递地狱）：
                      App
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       Header       Sidebar       Main
          │            │            │
          ▼            ▼            ▼
       UserInfo    NavMenu      Content
          │            │            │
          ▼            ▼            ▼
       Avatar      MenuItem   ProductList
                                   │
                                   ▼
                              ProductCard
                                   │
                                   ▼
                              AddToCart  ← 需要用户信息！

  问题：AddToCart 需要用户信息，但用户信息在 Header 里
        如果用 Props 传递，需要经过很多层组件！
```

**状态管理**就是把共享的数据抽出来，放在一个"全局仓库"里：

```
使用状态管理（Pinia Store）：

  ┌─────────────────────────────────────────────┐
  │           Pinia Store（全局仓库）              │
  │                                              │
  │   user: { name: '张三', role: 'admin' }      │
  │   cart: [{ id: 1, name: '商品' }]            │
  │                                              │
  └──────────────┬───────────────┬───────────────┘
                 │               │
                 ▼               ▼
             UserInfo        AddToCart
          （直接读取）       （直接读取）

  任何组件都可以直接访问 Store，不需要层层传递！
```

#### 5.1.2 什么是 Pinia？

**Pinia** 是 Vue 官方推荐的状态管理库，替代了 Vuex。

**Pinia 的核心概念**：

```
┌─────────────────────────────────────────────────────┐
│                      Store                           │
│                                                      │
│  ┌───────────────┐                                   │
│  │     State      │  ← 数据（类似于组件的 data）        │
│  │  count: 0      │                                   │
│  │  name: '张三'  │                                   │
│  └───────────────┘                                   │
│                                                      │
│  ┌───────────────┐                                   │
│  │    Getters     │  ← 计算属性（类似于 computed）       │
│  │  doubleCount   │                                   │
│  └───────────────┘                                   │
│                                                      │
│  ┌───────────────┐                                   │
│  │    Actions     │  ← 方法（类似于 methods）           │
│  │  increment()   │                                   │
│  │  fetchUser()   │  可以是异步的！                     │
│  └───────────────┘                                   │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### 5.2 创建和使用 Store

#### 5.2.1 安装和配置

如果创建项目时没有选择 Pinia，可以手动安装：

```bash
npm install pinia
```

在 main.js 中配置：

```javascript
// src/main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
const pinia = createPinia()
app.use(pinia)
app.mount('#app')
```

#### 5.2.2 创建 Store（选项式 API）

**选项式写法**的结构与 Vue 2 的组件选项非常类似，分为固定的 `state`、`getters`、`actions` 三个选项块。如果你熟悉 Vue 2 / Vuex，这种写法会很自然。

**三个选项块的对应关系**：

| Pinia 选项 | 作用 | 对应 Vue 组件中的 |
|-----------|------|-----------------|
| `state` | 存储数据（必须是函数，返回对象） | `data()` |
| `getters` | 基于 state 计算的派生数据 | `computed` |
| `actions` | 修改 state 的方法，支持异步 | `methods` |

```javascript
// src/stores/counter.js
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  // state：存储数据
  state: () => ({
    count: 0,
    name: '计数器'
  }),
  
  // getters：计算属性
  getters: {
    doubleCount: (state) => state.count * 2
  },
  
  // actions：方法
  actions: {
    increment() {
      this.count++
    },
    async fetchData() {
      // 支持异步
      const response = await fetch('/api/data')
      this.items = await response.json()
    }
  }
})
```

#### 5.2.3 创建 Store（组合式 API）

**组合式写法**与 `<script setup>` 风格完全一致：`ref` 做 state、`computed` 做 getters、普通函数做 actions，最后 `return` 暴露出去。Vue 3 官方更推荐这种写法。

```javascript
// src/stores/counter.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  // state：使用 ref
  const count = ref(0)
  const name = ref('计数器')
  
  // getters：使用 computed
  const doubleCount = computed(() => count.value * 2)
  
  // actions：普通函数
  function increment() {
    count.value++
  }
  
  // 返回所有需要暴露的内容
  return { count, name, doubleCount, increment }
})
```

> 💡 **选项式 vs 组合式的选择建议**：
> - **选项式**：结构固定、更易上手，适合熟悉 Vue 2 / Vuex 的开发者
> - **组合式（推荐）**：与 `<script setup>` 风格统一，更灵活，是 Vue 3 官方推荐方向
> - 两种写法**功能完全等价**，同一个项目中可以混用，根据个人习惯选择

#### 5.2.4 在组件中使用 Store

在组件中使用 Store 时，有一个关键细节需要注意：**直接解构 Store 会丢失响应式**，必须用 `storeToRefs` 包裹。

**为什么直接解构会失去响应式？**

```javascript
const counterStore = useCounterStore()

// ❌ 直接解构：count 变成了普通数字，不再是响应式的
// 即使 Store 中的 count 变化，模板也不会更新！
const { count } = counterStore

// ✅ 用 storeToRefs 解构：count 是 ref，保持响应式
const { count } = storeToRefs(counterStore)
```

`storeToRefs` 的作用：把 Store 中的 state 和 getters 转换成 **ref 引用**，解构后依然与 Store 保持同步。

**actions（方法）不需要 storeToRefs**：

```javascript
// actions 是普通函数，可以直接解构，不涉及响应式问题
const { increment } = counterStore  // ✅ 直接解构方法没问题
```

```vue
<script setup>
import { useCounterStore } from '@/stores/counter'
import { storeToRefs } from 'pinia'

const counterStore = useCounterStore()

// 使用 storeToRefs 解构 state 和 getters（保持响应式）
const { count, doubleCount } = storeToRefs(counterStore)

// actions 可以直接解构
const { increment } = counterStore
</script>

<template>
  <div>
    <p>计数: {{ count }}</p>
    <p>双倍: {{ doubleCount }}</p>
    <button @click="increment">+1</button>
  </div>
</template>
```

### 5.3 实战示例：用户认证 Store

用户认证（登录/登出）是几乎每个应用都需要的功能，非常适合用 Pinia 管理，因为：
- 用户信息需要在**所有页面**中访问（导航栏显示用户名、路由守卫检查权限等）
- 登录状态需要**持久化**（刷新页面后仍然保持登录）

**该 Store 管理的数据和功能**：

```
useAuthStore
├── State
│   ├── user         → 当前登录的用户对象（null 表示未登录）
│   ├── token        → 登录凭证（从 localStorage 恢复，实现持久化）
│   └── loading      → 登录请求加载状态（用于禁用按钮防止重复提交）
├── Getters
│   ├── isLoggedIn   → 是否已登录（true/false）
│   └── username     → 当前用户名（未登录时显示"游客"）
└── Actions
    ├── login()      → 发送登录请求，成功后保存 token 和用户信息
    └── logout()     → 清除 token 和用户信息，退出登录
```

```javascript
// src/stores/auth.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useAuthStore = defineStore('auth', () => {
  const user = ref(null)
  const token = ref(localStorage.getItem('token') || '')
  const loading = ref(false)
  
  const isLoggedIn = computed(() => !!token.value)
  const username = computed(() => user.value?.name || '游客')
  
  async function login(credentials) {
    loading.value = true
    try {
      const response = await fetch('/api/login', {
        method: 'POST',
        body: JSON.stringify(credentials)
      })
      const data = await response.json()
      token.value = data.token
      user.value = data.user
      localStorage.setItem('token', data.token)
      return true
    } catch (error) {
      return false
    } finally {
      loading.value = false
    }
  }
  
  function logout() {
    token.value = ''
    user.value = null
    localStorage.removeItem('token')
  }
  
  return { user, token, loading, isLoggedIn, username, login, logout }
})
```

> 📌 **项目实战：SyncHealth 的 Pinia Store 完整剖析**
>
> **`stores/auth.ts` — 认证状态管理的真实实现：**
>
> 项目中的认证 Store 使用了组合式 API 写法（`defineStore('auth', () => { ... })`），与文档示例高度相似但有一些实际项目特有的细节：
>
> 1. **Token 持久化**：`const accessToken = ref(localStorage.getItem('access_token') || '')` 在 Store 初始化时就从 localStorage 读取已有的 token。这意味着用户刷新页面后无需重新登录——Store 实例化时恢复 token，`isAuthenticated` 计算属性自动变为 `true`，路由守卫允许访问受保护页面。这是单页面应用中"刷新不丢登录"的标准实现方式。
> 2. **双 Token 机制**：`login()` 和 `register()` 方法中同时存储了 `access_token` 和 `refresh_token`。短期的 access_token 用于 API 鉴权，长期的 refresh_token 用于在 access_token 过期后自动续期（具体逻辑在 `api/client.ts` 的响应拦截器中实现）。这种设计平衡了安全性和用户体验——即使 access_token 泄露，攻击者的窗口期也只有 15 分钟左右。
> 3. **Store 的跨组件使用**：`authStore.user` 在 `AppLayout.vue` 的侧边栏底部显示用户昵称和邮箱；`authStore.isAuthenticated` 在路由守卫中控制页面访问权限；`authStore.logout()` 由退出按钮的 `@click` 调用。同一个 Store 实例被三个完全不同的场景消费，这正是 Pinia 替代 Props 层层传递的核心价值。

> **`stores/ai.ts` — 复杂状态管理的范例：**
>
> AI Store 管理了会话列表、消息历史、模型选择、WebSocket 连接等复杂状态，展示了 Pinia 在复杂业务场景下的能力：
>
> 1. **多状态协同**：`currentSessionId`（当前会话 ID）、`messages`（消息数组）、`loading`（加载状态）、`currentModel`（选择的模型）等多个 `ref` 变量协同工作。当用户发送消息时，`sendMessage` 方法同时操作多个状态——push 用户消息和 AI 占位消息到 `messages`、创建 WebSocket 连接、在 `onmessage` 中更新流式内容。所有状态的修改都是响应式的，组件模板自动同步。
> 2. **局部变量管理**：`let ws: WebSocket | null = null` 是一个模块级变量而非 `ref`，因为 WebSocket 实例不需要触发模板更新。这是 Pinia 的一个重要特点——你可以在 Store 中混合使用响应式状态（`ref`/`reactive`）和普通变量，只有需要驱动 UI 更新的数据才需要是响应式的。
> 3. **异步操作的完整模式**：`fetchModels()` 使用 `Promise.all` 并发请求模型列表和服务健康状态——减少请求等待时间。`sendMessage()` 中使用 WebSocket 而非 HTTP，展示了 Pinia actions 支持任何异步模式，不限于 axios/fetch。

### 5.4 实战示例：购物车 Store

购物车数据是跨页面共享的典型场景：用户在**商品列表页**添加商品，在**购物车页**查看，在**导航栏**显示数量徽标——这三处需要同一份数据，放在 Pinia 中最合适。

**该 Store 管理的数据和功能**：

```
useCartStore
├── State
│   └── items        → 购物车商品数组（每项包含 id、name、price、quantity）
├── Getters
│   ├── itemCount    → 购物车总商品数量（用于导航栏的数字徽标）
│   └── totalPrice   → 购物车总金额（实时计算）
└── Actions
    ├── addItem()    → 添加商品（已存在则增加数量，否则新增一项）
    ├── removeItem() → 移除指定商品
    └── clearCart()  → 清空购物车
```

```javascript
// src/stores/cart.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useCartStore = defineStore('cart', () => {
  const items = ref([])
  
  const itemCount = computed(() => 
    items.value.reduce((total, item) => total + item.quantity, 0)
  )
  
  const totalPrice = computed(() =>
    items.value.reduce((total, item) => total + item.price * item.quantity, 0)
  )
  
  function addItem(product) {
    const existing = items.value.find(item => item.id === product.id)
    if (existing) {
      existing.quantity++
    } else {
      items.value.push({ ...product, quantity: 1 })
    }
  }
  
  function removeItem(productId) {
    const index = items.value.findIndex(item => item.id === productId)
    if (index > -1) items.value.splice(index, 1)
  }
  
  function clearCart() {
    items.value = []
  }
  
  return { items, itemCount, totalPrice, addItem, removeItem, clearCart }
})
```

### 5.5 何时使用 Pinia

```
使用 Pinia 的场景：
✓ 多个组件需要共享的数据（用户信息、购物车、主题设置）
✓ 需要跨页面保持的数据
✓ 复杂的业务逻辑（登录、购物流程）
✓ 需要缓存的数据（避免重复请求）

不需要 Pinia 的场景：
✗ 只在一个组件内使用的数据
✗ 父子组件间简单的数据传递
✗ 临时的 UI 状态（弹窗开关、表单输入）
```
